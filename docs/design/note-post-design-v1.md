## §1 責務と境界

Threads 版 §1 とほぼ同じだが、2点が違う。

1. **記事（1500〜2000字目安）を作る。** 短文ではない
2. **タイトルと本文を別々に扱う。** note のエディタが別枠だからである

引き受けないことは Threads 版と同じ。加えて、**note への投稿も公開も行わない。**
このアプリの出力は「note の作成画面に貼り付ける材料」までである。

## §2 モジュール構成

Threads 版 §2 と同じ6ファイル・同じ依存の向き。
DOM の id 接頭辞は `np-`。`app.js` に**「本文をコピー」ボタン**（`np-copy-body`）が増えている。

## §3 状態とデータ構造

保存の形が Threads 版と少し違う。**`title` を持つ。**

```json
{
  "drafts":  [{ "id": "…", "title": "…", "text": "…", "createdAt": 1755500000000 }],
  "history": [{ "id": "…", "at": 1755500000000, "kind": "作成画面を開いた", "title": "…", "text": "…" }],
  "stylePrompt": "…"
}
```

| 項目 | 値 |
| --- | --- |
| `localStorage` キー | `tsam-note-post-v1` |
| 履歴の上限 | 100 件 |
| 本文の上限 | `TEXT_LIMIT` = 30000 文字 |

`title` は**空でも保存できる。** note 側も無題を許すためである。
一覧では、タイトルがあれば日時の後ろに並べて表示する。

その他（壊れたデータの読み捨て、`localStorage` 不可時の扱い、キーをメモリに残さない方針）は
Threads 版 §3 と同じ。

## §4 主要フロー

### 4-1. 起動

Threads 版 §4-1 と同じ。

### 4-2. 生成

Threads 版 §4-2 と同じ流れだが、**応答が JSON である**（§5-1）。
`{ "title": …, "body": … }` を受け取り、タイトル欄と本文欄へ別々に流し込む。

### 4-3. 作成画面を開く（このアプリ固有・2段階コピー）

**note には本文プリフィルの URL が存在しない**（2026-08-12 実機確認）。
そのため「コピーして貼り付ける」方式を採る。

クリップボードは一度に1つしか持てず、note のエディタは最初のカーソルが
タイトル欄にある。そこで**2段階**にしている。

```
handlePost()（「note で作成」ボタン）
  1. validatePostText() で本文を検証
  2. navigator.clipboard.writeText(タイトル)     ← タイトルが空なら本文をコピー
       失敗しても中止しない（許可が無い環境では諦めて先へ進む）
  3. window.open(NOTE_NEW_URL, '_blank', 'noopener,noreferrer')
       ※ クリックと同じイベント内。開けなければ案内して終了（履歴に残さない）
  4. 履歴へ記録（kind = '作成画面を開いた'）
  5. 案内を出す:
       コピー成功・タイトルあり → 「貼り付けたら、このタブに戻って『本文をコピー』を押してください」
       コピー成功・タイトル空   → 「本文をコピーして開きました」
       コピー失敗               → 「手動でコピーしてください」

handleCopyBody()（「本文をコピー」ボタン。2段階目）
  1. validatePostText()
  2. navigator.clipboard.writeText(本文)
  3. 成否を案内する
```

**`window.open` を `await` の後に置いている**点に注意。`navigator.clipboard.writeText()`
は非同期だが、クリックのユーザー操作コンテキストは同じタスク内で維持されるため
実機では阻止されない。**この順序を入れ替えると、コピー前に画面が開いて手順が崩れる。**

### 4-4. キー設定の反映

Threads 版 §4-4 と同じ。

## §5 外部インターフェース

### 5-1. Gemini（記事生成・JSON 応答）

送信先・認証・モデル・フォールバックは Threads 版 §5-1 と同じ。違いは3点。

| 項目 | 値 | 理由 |
| --- | --- | --- |
| `MAX_OUTPUT_TOKENS` | 4096 | 記事は 1500〜2000 字。1024 では途中で切れる |
| `responseMimeType` | `application/json` | コードブロックが付きにくくなる |
| 出力形式の指示 | `{ "title": …, "body": … }` | note がタイトルと本文を別枠で持つため |

プロンプトの方針には、Threads 版の「創作の禁止」に加えて次が入る。

- 見出し（`## 見出し`）を適度に入れる
- タイトルは内容を正確に表し、誇張しない
- **未確認の情報を断定しない。一般論は「一般的には」と明示する**

### 5-2. note

| 項目 | 値 |
| --- | --- |
| URL | `https://note.com/notes/new`（`config.js` の `NOTE_NEW_URL`。クエリなし） |
| 未ログイン時 | note が `/login?redirectPath=/notes/new` へ誘導し、ログイン後にエディタが開く（2026-08-12 実機確認） |

### 5-3. クリップボード

`navigator.clipboard.writeText()`。**セキュアコンテキストと利用者操作が要る。**
拒否された場合は例外を握りつぶし、手動コピーを案内して先へ進む。

## §6 エラー設計

Threads 版 §6 と同じ分類。加えて、クリップボードの失敗は**エラーとして扱わない**
（作成画面は開けているため、案内文だけを変える）。

---

## §7 移植（他プロダクトへの組み込み）

### 7-1. 移植単位

Threads 版 §7-1 の表に加えて次の2つ。

| 単位 | ファイル | 依存 | 単独で持ち出せるか |
| --- | --- | --- | --- |
| JSON 応答の生成（`title`＋`body`） | `gemini.js` の `buildPostRequest()` と取り出し部 | なし | **可**。構造化出力が要る場面の雛形になる |
| 2段階コピー導線 | `app.js` の `handlePost()` / `handleCopyBody()` | `navigator.clipboard` | 可（プリフィル不可の外部サービス全般に使える） |

### 7-2. 置換点

Threads 版 §7-2 の6点に加えて、

| 置換点 | このアプリの値 |
| --- | --- |
| `STORAGE_KEY` | `tsam-note-post-v1`（**移植先で必ず変える**） |
| `NOTE_NEW_URL` | 作成画面の URL |
| `TEXT_LIMIT` | 30000（note 側の公開仕様ではなく、貼り付け事故を防ぐための頭打ち） |
| `BODY_TARGET_MIN` / `BODY_TARGET_MAX` | 生成の目安字数（1500／2000） |
| `MAX_OUTPUT_TOKENS` | 4096 |
| DOM id 接頭辞 | `np-` |

### 7-3. 前提

Threads 版 §7-3 に加えて、**クリップボード API が使えること**（セキュアコンテキスト）。
使えない環境でも壊れないが、手順が手動になる。

### 7-4. 持ち出してはいけないもの

Threads 版 §7-4 と同じ。

## §10 既知の制約・未解決

1. **公開されたかどうかを観測できない**（Threads 版 §10-1 と同じ理由）
2. **`TEXT_LIMIT` は note の公開仕様ではない。** note 側の上限は公開されておらず、
   記事として現実的な範囲で頭打ちにしている
3. **2段階コピーは利用者の手順に依存する。** タイトルを貼り付けたあと、
   このタブへ戻って「本文をコピー」を押してもらう必要がある。
   案内文が唯一の担保であり、押し忘れは検知できない
4. Threads 版 §10 の 2（`AbortSignal` 未使用）・4（下書きの件数上限なし）も同じ

## §11 設計判断の記録

| 判断 | 採らなかった案 | 理由 |
| --- | --- | --- |
| コピー＋作成画面を開く方式 | プリフィル URL を探す／自動入力する | note にプリフィル URL が無いことを実機で確認済み。DOM 操作による自動入力は他社サイトの構造に依存し、壊れる |
| 最初にコピーするのは**タイトル** | 本文を先にコピーする | エディタの初期カーソルがタイトル欄。本文を先に入れると貼り直しになる |
| タイトル空を許す | タイトル必須にする | note 側が無題を許す。生成前に下書きだけ保存したい場合もある |
| JSON で受け取る | 本文の1行目をタイトルとみなす | 見出し記法と混同する。`responseMimeType` を使えば分離が確実 |
| クリップボード失敗で中止しない | 失敗したら開かない | 作成画面へ行けること自体に価値がある。手動コピーの案内で回復できる |
