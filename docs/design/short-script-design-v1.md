**このアプリだけ、利用者のPC上で動くローカルサービスと通信する。**
音声（VOICEVOX）と動画（FFmpeg）は `127.0.0.1` の補助サービス（ai-video-app）が担う。
ブラウザ内で完結する他のアプリとは、外部との関わり方が根本的に違う。

---

## §1 責務と境界

### 1-1. 引き受けること

- テーマと尺（30秒／60秒）から、Gemini で**構造化された台本**を作る
- 既存の台本を貼り付けて同じ形へ直す（Gemini を介さない経路）
- ローカル補助サービスへ台本を渡し、音声・動画の生成を依頼して進捗を表示する
- 音声エンジンの状態を見て、必要なら画面から起動する

### 1-2. 引き受けないこと

- **音声合成・動画生成そのもの。** ローカル補助サービスの担当
- 補助サービスの配布・インストール
- 当社サーバーでの処理

### 1-3. 隣との関係

| 相手 | 関係 |
| --- | --- |
| ai-video-app（ローカル） | **このリポジトリの外**。`http://127.0.0.1:3000` の REST ＋ NDJSON |
| `threads-post` など投稿系 | `gemini.js` の複製元。エラー分類の系譜はここから伸びている |
| `card-ocr` | `prompt.js` の書き方（指示・スキーマ・組み立てを1本に閉じる）の手本 |
| KeyStore | Gemini キーの取得元 |

## §3 状態とデータ構造

### 3-1. 台本の形（このアプリの中心データ）

```json
{ "title": "…", "scenes": [{ "seconds": 8, "text": "…" }] }
```

**AI 生成と貼り付けの両方がこの形へ収束する。** 後段（音声・字幕・動画）が
そのまま食える JSON にすることが、`prompt.js` の構造化スキーマの目的である。

制約は `prompt.js` の定数で持つ。

| 定数 | 値 | 意味 |
| --- | --- | --- |
| `SCENE_SECONDS_MIN` / `MAX` | 2 / 20 | **モデルの返り値をここへ丸める**（プロンプトだけに頼らない） |
| `SCENE_TEXT_MAX_LENGTH` | 60 | 1シーンの文字数 |
| `PROMPT_VERSION` | `short-script-1` | 変えたら `APP_VERSION` も上げる |

### 3-2. 永続化するもの

**無い。** `localStorage` を使っていない（投稿系アプリのような下書き保存を持たない）。

### 3-3. メモリだけに置くもの

Gemini APIキー（都度取得）、作成中の台本、生成した動画の参照。

## §4 主要フロー

### 4-1. AI 生成

`buildScriptRequest(theme, durationSec)` → Gemini → 構造化応答 → 丸め。

**台本は「分類」ではなく「創作」なので、名刺OCR と違い `temperature` を上げる。**
ただし出力の**形**は構造化スキーマ（`SCRIPT_SCHEMA`）で固定する。

尺は `DURATIONS`（30 / 60）の2択。
**ここを増やすなら `prompt.js` のシーン数の指示も見直す**
（尺だけ増やしてシーン数の指針が無いと、モデルの裁量で間延びする）。

### 4-2. 貼り付け（`paste.js`）

Gemini を介さず、`{ title, scenes }` へ直す。

- 区切りは利用者の選択により「区切らない＝全文を1シーン」もある
- 尺の目安は `estimateSeconds()`：日本語のナレーションはおよそ 6〜7 文字/秒なので、
  **空白を除いた文字数 × 0.15**、下限2秒。**目安であり、最終尺は後段で実音声に同期する**
- タイトル未入力なら `DEFAULT_PASTED_TITLE`

### 4-3. 音声エンジンの起動（`companion.js`）

```
fetchEngineStatus()      … 3状態（起動中／未起動／補助サービス自体が不在）を返す
startEngine()            … 画面から起動を依頼
waitForEngineOnline()    … 2秒間隔・最大30秒でポーリング
```

**実測7.9秒で起動するが、低速機・コールドスタートに備えて約4倍のマージン**を取っている。

疎通確認と話者取得は短いタイムアウトを持つ。**起動していなければ待たずに失敗させる。**

### 4-4. 動画生成（`renderVideo()`）

`POST {COMPANION_BASE_URL}/api/generate` に台本と音声パラメータ
（`speakerId` / `speedScale` / `volumeScale` / `pitchScale` / `backgrounds`）を送り、
**NDJSON のストリームを1行ずつ解釈して進捗を返す。**

```
reader.read() → デコード → buffer へ足す → '\n' で分割
  行の途中で切れることがあるのでバッファする（最後の断片は次回へ持ち越す）
```

- `credentials: 'omit'` … ローカルへ資格情報を送らない
- 接続失敗は例外にせず、**「ai-video-app を起動しているかご確認ください」という
  案内へ変換する。** 補助サービスが無いのは異常ではなく通常の状態でありうる

## §5 外部インターフェース

### 5-1. Gemini

他アプリと同じ（`x-goog-api-key` ヘッダー、`DEFAULT_MODEL` → 404 で `FALLBACK_MODEL`）。
`MAX_OUTPUT_TOKENS` は 1024。

### 5-2. ローカル補助サービス

| 項目 | 値 |
| --- | --- |
| ベース | `http://127.0.0.1:3000`（`COMPANION_BASE_URL`。**秘密情報ではない**） |
| 生成 | `POST /api/generate` → NDJSON ストリーム |
| 状態・起動・話者 | `fetchEngineStatus()` / `startEngine()` / `fetchSpeakers()` |
| 動画の取得 | `videoUrl(videoId)` |

**CSP に `http://127.0.0.1:3000` と `http://localhost:3000` を許可している**
（`index.html`）。ローカルの原点へ通信する唯一のアプリである。

---

## §6 エラー設計

Gemini 側は投稿系アプリと同じ体系（`GeminiErrorCode` ＋ `describeGeminiError`。
`short-script` が複製元）。

補助サービス側は**エラーコードを持たず、案内文へ直接変換する。**
利用者が取るべき行動が「ai-video-app を起動する」の1つに収束するためである。

## §7 移植（他プロダクトへの組み込み）

### 7-1. 移植単位

| 単位 | ファイル | 依存 | 単独で持ち出せるか |
| --- | --- | --- | --- |
| **NDJSON ストリームの受信** | `companion.js` の `renderVideo()` の読み取り部 | なし | **可。行の途中で切れる前提のバッファ処理は、進捗を返す長時間 API 全般に効く** |
| ローカルサービスの状態管理 | `companion.js`（状態3値・起動・ポーリング） | `config.js` の3定数 | 可 |
| 構造化台本の生成 | `prompt.js` ＋ `gemini.js` | `config.js` | 可（スキーマを差し替える） |
| 尺の見積もり | `paste.js` | なし | 可（**日本語の話速前提**） |

### 7-2. 置換点

1. `COMPANION_BASE_URL`（ポート／ホスト）と CSP の対応する許可
2. `SCRIPT_SCHEMA` ＋ `buildSystemInstruction()`（作りたいものが変われば両方）
3. `DURATIONS` / `SCENE_SECONDS_MIN` / `MAX` / `SCENE_TEXT_MAX_LENGTH`
   （**尺を増やすならシーン数の指示も**。§4-1）
4. `estimateSeconds()` の係数 0.15（言語が変われば変わる）
5. `ENGINE_START_TIMEOUT_MS`（30秒。起動時間の実測に基づく）
6. `PROMPT_VERSION` / `APP_VERSION`
7. `public/auth/` への依存

### 7-3. 前提

- **利用者のPCで補助サービスが動いていること。** 動いていなくても
  台本作成までは使える（機能が段階的に落ちる設計）
- ブラウザから `http://127.0.0.1` への通信が許されること
  （**混在コンテンツの扱いはブラウザによる**）
- 利用者が Gemini APIキーを持っていること

### 7-4. 持ち出してはいけないもの

- **`credentials: 'omit'` を外した版**（ローカルサービスへ資格情報が飛ぶ）
- モデルの返り値を丸めずに使う版（§3-1）
- 補助サービスの不在を例外として扱う版（§4-4）

## §8 テスト設計

スイート: `tests/unit/short-script-companion.mjs`。

**実サービスへ通信しない。** ai-video-app はテスト環境に存在しないため、
`fetch` はすべてスタブし、`companion.js` の判定（ヘッダの正規化・
ステータスの伝搬・ポーリング）だけを検証する。

`app.js` / `index.html` は DOM 前提のため import せず、
**ソースの静的検証**で「3状態の分岐・起動ボタン・文言」が存在することを確かめている。
（DOM を持つ画面に対する、このリポジトリで唯一の検証方法である。）

## §10 既知の制約・未解決

1. **補助サービスが無いと動画までは作れない。** 台本作成までで止まる
2. **`renderVideo()` の `duration` が 30 固定で送られている。**
   画面で 60 を選んでも、補助サービスへ渡る値は 30 のままである。
   台本の中身（シーン数と秒数）は 60 秒ぶんで作られるため、
   **補助サービス側がこの値をどう使うかによって挙動が変わる**
   （[findings-2026-08.md](./findings-2026-08.md) #4）
3. **`localStorage` を持たないため、作った台本は再読み込みで消える**
4. **尺の見積もりは日本語前提**（6〜7 文字/秒）

## §11 設計判断の記録

| 判断 | 採らなかった案 | 理由 |
| --- | --- | --- |
| 音声・動画をローカルへ委ねる | ブラウザ内で FFmpeg を動かす／サーバーで処理する | VOICEVOX と FFmpeg はブラウザに載せられない。サーバーは持たない方針 |
| 台本を構造化スキーマで固定 | 自由記述の台本 | 後段がそのまま食える形にする |
| モデルの返り値を丸める | プロンプトだけで制約する | 指示は守られないことがある |
| 貼り付け経路を Gemini なしにする | 貼り付けも整形させる | キーが無くても使える経路を残す |
| エンジン起動待ちを4倍マージン | 実測値どおり8秒 | 低速機・コールドスタートで失敗する |
| 補助サービス不在を案内に変換 | エラーとして表示 | 不在は通常ありうる状態であり、行動は1つに決まる |
| 画面をソース静的検証で確かめる | 実ブラウザテストを足す | 検証したいのが分岐の存在であり、実行までは要らない |
