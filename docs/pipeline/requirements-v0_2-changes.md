### 7.7（下書き・投稿・予約）— **FR-063 を読み替え**

| v0.1 | v0.2 |
| --- | --- |
| FR-063「予約日時を指定し、**バックグラウンドワーカーが投稿処理を実行する**」 | **予約リマインダー方式**。指定時刻に Web Push で通知し、利用者のワンタップで投稿する。サーバーは代理実行しない |

サーバーは期限を知らない。

### 10章（データ要件）— **全面的に読み替え**

| v0.1 のエンティティ | v0.2 での扱い |
| --- | --- |
| User | サーバーに持たない。既存の本番認証系（`tsam-auth-session`）の利用者IDを参照するのみ |
| SocialAccount（`token_ref`） | **廃止。** トークンは利用者ブラウザ内のみ。`token_ref` を中心にした設計は成立しない |
| ContentProject / ContentVersion | **利用者ブラウザの IndexedDB へ移す。** スキーマ自体は流用する |

| PublishJob | 利用者ローカルのキューへ。サーバーに持たない |
| PublishedPost | 利用者ローカルへ。サーバーは結果コードの計数のみ |

**新規に必要なもの**: **Threads の利用量カウンタ**（利用者ID・月・回数）、上限設定、許可リスト。
**これだけがサーバー側に存在する**（guide §2-1・§3-3）。**v0.6 で LLM・X のカウンタは不要になった**（BYOキーのため）。

| v0.1 | v0.2 |
| --- | --- |

### 14章（非機能要件）— **2項目を読み替え**

| v0.1 | v0.2 |
| --- | --- |

#### AC-09 新設の経緯と、AC-06 復活時の注意

AC-06 は「台本を生成し**、かつ**シーン分割された動画をレンダリングできる」という
**複合条件**だった。MVP から動画化を外した結果、次の状態になった。

```
AC-06 の内訳            MVP での扱い
─────────────────────  ──────────────────────────────
① note→台本 の生成      AC-01 が既にカバー（重複していた）
② シーン分割            ★ カバーが無くなる → AC-09 を新設
③ 動画レンダリング       拡張フェーズ（AC-06 として凍結）
```

**拡張フェーズで AC-06 を復活させるときは、①と②を差し引いて③だけにする。**
そのまま戻すと AC-01・AC-09 と三重に重なる。

### 4-2. 第1段では使わないもの（**第2段で復活する**）

- データ非保持アーキテクチャ（v0.4 の核）— **保持先が発注者自身の Sheets になったため、
  そもそも「他人のデータを預からない」という論点が第1段では生じない**
- `tsam-auth-session` 連携（v0.4.1 で案A に確定していた）
- IndexedDB（Phase 1 設計の中核だった）
- 利用者BYOキー方式（v0.6）— **Flows の組み込み Gemini は APIキー不要**
- 利用量カウンタ・上限・許可リスト（利用者が1名のため。**第2段で復活**）
- Meta App Review（開発モードのまま自分のアカウントへ投稿する想定）
- 法務文書（個別規約・プライバシー補遺）— 第三者へ提供しないため。**起案は archive/legal/ にある**
