## A. スプレッドシートの用意

### A-1. 一想スプレッドシートを作る

1. Google ドライブで**新しいスプレッドシート**を作る
2. 名前を付ける（例: `一想 ISSO`）

**シートの中身は作らなくて構いません。** 見出し行を含め、
**B-4 の初期化がすべて作ります**（手で作ると見出しの表記ゆれで読めなくなります）。

作られるのは次の6シートです。

| シート | 中身 |
| --- | --- |
| `themes` | テーマ（着想） |
| `versions` | 段階ごとの案。採用の印もここ |
| `scenes` | 台本のシーン（ナレーション・映像指示） |
| `generation_queue` | 生成の依頼と結果。**Flow が読み書きする唯一のシート** |
| `posts` | 投稿の記録。**X の月次上限はここを数えて判定します** |
| `settings` | 目安の字数・口調・**X の月次上限** |

> **列は手で足さないでください。** 一想は**見出しの名前で列を探す**ので、
> 列を移動・挿入しても壊れませんが、**見出しの文字を変えると読めなくなります。**

### A-2. シートIDを控える

URL のこの部分です。**【秘密】ではありませんが、公開しないでください。**

```
https://docs.google.com/spreadsheets/d/【ここがシートID】/edit
```

B-3 で使います。

## B. GAS プロジェクト

### B-1. スタンドアロンで新規作成する

1. <https://script.google.com/> を開く
2. **「新しいプロジェクト」**
3. 名前を付ける（例: `一想 ISSO`）

> **Note Draft Helper とは別のプロジェクトにしてください。**
> 同居させると、一想の不具合が Helper の note 投稿を止めます
> （[implementation-guide-v1_0-personal.md](./implementation-guide-v1_0-personal.md) §3 の決定）。
> **Helper には一切手を入れません。**

> **A-1 のスプレッドシートに紐づけない**（「拡張機能 → Apps Script」から作らない）。
> スタンドアロンにしておくと、スプレッドシートを作り直しても
> プロジェクトが道連れになりません。

### B-2. `gas-isso/` のファイルを貼る

**方法A: 手で貼る（初回はこちらが確実）**

`gas-isso/` の各ファイルを、同じ名前でエディタに作って貼ります。

| エディタ上の名前 | 元ファイル |
| --- | --- |
| `Config`（スクリプト） | `Config.gs` |
| `Sheets` | `Sheets.gs` |
| `Prompts` | `Prompts.gs` |
| `Themes` | `Themes.gs` |
| `Versions` | `Versions.gs` |
| `Scenes` | `Scenes.gs` |
| `Generation` | `Generation.gs` |
| `Settings` | `Settings.gs` |
| `Http` | `Http.gs` |
| `Oauth1` | `Oauth1.gs` |
| `Posts` | `Posts.gs` |
| `Threads` | `Threads.gs` |
| `X` | `X.gs` |
| `Api` | `Api.gs` |
| `Main` | `Main.gs` |
| `Index`（HTML） | `Index.html` |
| `Style`（HTML） | `Style.html` |
| `Script`（HTML） | `Script.html` |

さらに、**マニフェストを合わせます。**

1. 「プロジェクトの設定」→ **「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオン**
2. エディタに出てきた `appsscript.json` を、`gas-isso/appsscript.json` の内容で置き換える

> **`appsscript.json` を合わせないと B-5 のデプロイ設定が既定に戻ります。**
> ここに「実行=自分／アクセス=自分のみ」が書いてあります。

**方法B: clasp（2回目以降が楽）**

```powershell
npm install -g @google/clasp     # 初回のみ
clasp login
cd gas-isso
clasp clone 【スクリプトID】     # 初回。既存プロジェクトに接続する
clasp push
```

> **`clasp push` は上書きです。** エディタで直接直した内容は消えます。
> **直すのは常にリポジトリ側**にしてください（そうしないとテストが実物と合わなくなります）。

### B-3. Script Properties を設定する

「プロジェクトの設定」→ **「スクリプト プロパティ」** で追加します。

**この時点で必要なのは1つだけです。**

| プロパティ名 | 値 | 要る時期 |
| --- | --- | --- |
| `ISSO_SPREADSHEET_ID` | A-2 で控えたID | **いま** |
| `HELPER_SPREADSHEET_ID` | Helper の記事キューのシートID | F で |
| `HELPER_SHEET_NAME` | そのシート名（タブ名） | F で |
| `THREADS_USER_ID` 他 | §D の表 | D で |
| `X_API_KEY` 他 | §E の表 | E で |

> **無い値は「使う時点で」名前付きのエラーになります。**
> Threads を設定していなくても、生成と note の導線は動きます
> （起動時に全部そろっている必要はありません）。

> **貼り付けのとき、前後に空白や改行を入れないよう気をつけてください。**
> 一想側で BOM と前後空白は落としていますが、**途中に混ざったものは落とせません。**

### B-4. 初期化して権限を承認する

1. エディタ上部の関数選択で **`issoSetup`** を選ぶ
2. **「実行」**
3. 権限の承認を求められるので、承認する
   - 「このアプリは確認されていません」と出たら
     **「詳細」→「（プロジェクト名）に移動」** で進む
     （**自分が書いた自分用のスクリプトなので、この警告は想定どおりです**）
4. 実行ログに `作成したシート: themes, versions, ...` と出れば成功

承認する権限は3つです。

| 権限 | 何に使うか |
| --- | --- |
| スプレッドシートの閲覧・編集 | 一想のデータ、および F の Helper への1行追加 |
| 外部サービスへの接続 | D・E の投稿 |
| （ウェブアプリとしての実行） | B-5 の画面 |

> **`issoSetup` は何度実行しても既存を壊しません。** 足りないシートだけ作ります。

### B-5. ウェブアプリとしてデプロイする

1. 右上 **「デプロイ」→「新しいデプロイ」**
2. 歯車 → **「ウェブアプリ」**
3. 設定を確認する

| 項目 | **値** |
| --- | --- |
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **自分のみ** |

4. 「デプロイ」→ **ウェブアプリのURLを控える**

> ### 「アクセスできるユーザー」を「全員」にしないでください
>
> 画面ごと GAS の上に置いているため、**「全員」にすると URL を知っている人が
> 誰でもあなたのテーマ・下書き・投稿操作にアクセスできます。**
> 一想には一想自身のログイン機能がありません（**要らないのは「自分のみ」だからです**）。

> ### 2回目以降は「デプロイを管理」から更新する
>
> **「新しいデプロイ」を作るとURLが変わります。** ホーム画面のショートカットが
> 古いコードを指したままになります。
> **コードを直したら「デプロイを管理」→ 既存のデプロイ → 鉛筆 → バージョン「新バージョン」→ デプロイ。**
> （`gas-auth` と同じ落とし穴です。あちらは URL が変わると `public/auth/config.js` と
> Stripe の設定を直すことになります。）

> **エディタで保存しただけでは、公開中の画面は変わりません。**

### B-6. スマホのホーム画面に追加する

1. スマホのブラウザで B-5 のURLを開く
   - **Google アカウントでログインしている必要があります**（「自分のみ」のため）
2. **iOS (Safari)**: 共有 → 「ホーム画面に追加」
   **Android (Chrome)**: メニュー → 「ホーム画面に追加」

**【記録】** ここまでで、スマホから着想を入力できます。
**320px 幅で崩れていないか**を見てください（実装は 320 / 375px を基準にしています）。

## C. Workspace Studio Flow

> **飛ばして構いません。** C が無くても、画面の「結果を手で貼る」欄から
> 通しで使えます。**先に G の通し確認をして、必要を感じてから戻ってきてください。**

### C の役割は1つだけです

一想は**プロンプトを組み立てて `generation_queue` に1行書く**ところまでを行います。
Flow の仕事は次の3つだけです。

```
1. generation_queue の「状態」が「待機」の行を拾う
2. その行の「prompt」列（H列）を Gemini へ渡す
3. 返答を「result」列（I列）へ、「状態」を「完了」へ書き戻す
```

> **段階ごとに Flow を作る必要はありません。** プロンプトは一想が
> 段階に応じて組み立てて H 列に入れてあります。**Flow は中身を見ません。**
> したがって**作る Flow は1つです。**

### C-1〜C-3. Flow を作る

1. Workspace Studio で新しい Flow を作る
2. **入力**: Google Sheets コネクタ。A-1 のスプレッドシート、`generation_queue` シート
   - 条件: `status` 列が `待機`
3. **処理**: Gemini ステップ。プロンプトに **`prompt` 列の値をそのまま**渡す
4. **出力**: 同じ行へ書き戻す
   - `result` 列 ← Gemini の返答
   - `status` 列 ← `完了`

**列の位置**（`generation_queue`）

| 列 | 見出し | Flow から見た役割 |
| --- | --- | --- |
| A | `request_id` | 行の特定に使う |
| B | `theme_id` | — |
| C | `stage` | — |
| D | **`status`** | **読む（`待機`）・書く（`完了`）** |
| E | `requested_at` | — |
| F | `completed_at` | 書ければ書く（任意） |
| G | `error` | — |
| H | **`prompt`** | **読む** |
| I | **`result`** | **書く** |

> **状態の語は日本語です**（`待機` / `処理中` / `完了` / `取込済` / `失敗`）。
> **画面・GAS・Flow がこの語を共有しています。** 英語に変えないでください。

> **`取込済` を Flow が書くことはありません。** これは一想が
> 「versions へ取り込んだ」ことを記録する語です。**`完了` のまま止めてください。**
> （分けていないと、画面で更新を2回押したときに版が二重に作られます。）

### C-4. 手動実行で1件通す

1. 一想の画面でテーマを作り、「Threads を生成する」を押す
2. `generation_queue` に「待機」の行ができることを確認
3. Flow を手動実行
4. その行が「完了」になり、I列に返答が入ることを確認
5. 一想の画面で **「更新」** を押す → 3案が出れば成立

**【記録】** 確認事項②の回答になります。

| # | 記録すること |
| --- | --- |
| 1 | **Sheets コネクタで、条件に合う行を読めたか** |
| 2 | **同じ行へ書き戻せたか**（別行への追記しかできない場合は、その旨） |
| 3 | Gemini ステップに**APIキーが要ったか**（要らない想定です） |
| 4 | 1件あたりの所要時間 |

> **書き戻しができない場合でも、シートの形は変えません。**
> 「手で貼る」運用に落とします（画面に常時その欄があります）。

### 代替: Flow を使わない運用

1. 画面で「生成する」を押す → **プロンプトが画面に出ます**
2. それを Gemini（Studio のチャットでも可）へ貼る
3. 返答をコピーし、画面の **「結果を手で貼る」** 欄へ貼る
4. **「貼った結果を取り込む」**

> `docs/pipeline/flow-text/*.txt` は**段階別プロンプトの本文**です。
> Flow 側にプロンプトを持たせたい場合のみ使います。
> **手で貼る運用では要りません**（画面がプロンプトを出すため）。
> **これらは生成物です。直すときは `lib/pipeline/prompts/definitions.mjs` を直し、
> `node lib/pipeline/prompts/build.mjs` で作り直します。**

### D-3. 認証情報を Script Properties へ

**【秘密】**

| プロパティ名 | 値 | 出どころ |
| --- | --- | --- |
| `THREADS_USER_ID` | Threads のユーザーID | 先行確認 手順5（`GET /v1.0/me` の `id`） |
| `THREADS_ACCESS_TOKEN` | **長期トークン**（下記） | 先行確認 手順4 → 長期化 |
| `THREADS_APP_ID` | アプリID | アプリ管理画面 |
| `THREADS_APP_SECRET` | アプリシークレット | アプリ管理画面 |

#### 短期トークンのままにしないでください

先行確認の手順4で取れるトークンは**短期（約1時間）**です。
これを登録すると、**翌日には投稿が失敗します。**

**長期トークン（約60日）に交換します。**

```
GET https://graph.threads.net/access_token
  ?grant_type=th_exchange_token
  &client_secret=【アプリシークレット】
  &access_token=【短期トークン】
```

返ってきた `access_token` を `THREADS_ACCESS_TOKEN` に入れます。

> **長期トークンも60日で切れます。** 期限内に1回でも更新すれば延長されます。
> **`THREADS_APP_ID` / `THREADS_APP_SECRET` を登録しておくのは、
> 一想が自動で更新できるようにするためです**（実装順序7）。
> **60日以上使わなかった場合は、手でこの交換をやり直します。**

**【記録】** トークンを取得した日付を控えてください（切れたときの判断材料になります）。

## E. X

> **ここだけ「お金がかかる」節です。** 先に **E-0** を読んでください。

### E-0. 【重要】無料で投稿できるかを、まず実測する

**X の料金体系は変わり続けています。** 2026年時点では
**Free プランは廃止され従量課金へ移行した**という情報があります。
一方で、少量の投稿に無料枠が残っている可能性も否定できません。

> **本書は「無料枠がある／ない」のどちらも前提にしません。**
> **コンソールで実際に見た値が正です。** 下の【記録】を先に行ってください。

| | |
| --- | --- |
| 一想の投稿頻度 | 1テーマにつき X へ1投稿。**週に数本** |
| 一想側の月次上限（E-4） | **60件/月**（1日2件ペース。初期値） |

**手順**

1. E-1 の Developer アカウント登録まで進む（**ここまでは課金されません**）
2. Developer Portal の**プラン一覧**を開く
3. **無料で投稿できるプランがあるか**を見る

| 見た結果 | 進み方 |
| --- | --- |
| **無料で投稿できるプランがある** | それで始める。**E-4 は飛ばす。** 上限に当たってから E-4 へ戻る |
| **無料では投稿できない**（従量課金のみ） | **E-4 へ進み、支出上限を設定してから** E-2・E-3 を行う |

**【記録】** 見た結果を教えてください。[learnings.md](./learnings.md) §4-2 に記録し、本書を直します。

| # | 記録すること |
| --- | --- |
| 1 | **無料で投稿できるプランがあったか**（あれば、その月間投稿上限） |
| 2 | 従量課金の**単価と課金単位**（投稿1件あたりか、リクエスト1件あたりか） |
| 3 | **支出上限の設定欄があるか**（E-4） |
| 4 | **最低利用料・基本料があるか**（使わなかった月にも発生するか） |

> **無料で投稿できる場合は、課金を有効にしないでください。**
> 有効化は後からできますが、**基本料が発生する形態だと、使わなかった月の分は戻りません。**
> 逆に、無料では投稿できないと分かったら、**E-4 を先に済ませてください**——
> 上限を設定しないまま自動投稿を動かさないためです。

### E-1. X Developer アカウントを作る

1. <https://developer.x.com/> を開き、**投稿したい X アカウントでログイン**
2. Developer Portal へのサインアップ（開発者規約への同意、利用目的の記入）
   - 利用目的は**正直に書いてください**（例:「自分のアカウントへ、自作の下書き支援ツールから投稿するため」）
3. **プランの選択は E-0 の結果に従う**
   - 無料で投稿できるプランがあれば、それで始める
   - 無い場合は、**E-4（支出上限）を先に済ませてから**従量課金を有効にする

> **投稿先のアカウントでログインしてください。** 別アカウントで作ると、
> E-3 のトークンが別アカウントのものになります。

> **【前提の確認】** ご指示のとおり、Threads / X の自動投稿基盤は既存にありません。
> **既存の自動化は note（Note Draft Helper）のみ**です。
> したがって本節は**新規取得**として書いています。

### E-2. アプリを作り、権限を「読み書き」にする

1. Developer Portal → **Projects & Apps** → プロジェクトとアプリを作る

3. 次を設定する

| --- | --- | --- |
| **App permissions** | **Read and write** | **既定は Read only です。投稿できません** |
| Type of App | Web App / Automated App or Bot | — |
| Callback URI | **【TODO】** 必須なら `https://localhost/` を入れる | 一想は使いません（下記） |
| Website URL | `https://tsam-ai.com/` | — |

> ### 権限を変えたら、トークンを取り直します
>
> **App permissions を「Read and write」に変えるより**前**に発行したトークンは、
> 読み取り専用のままです。** 変更後に E-3 を行ってください。
> これは「設定は直したのに 403 が出続ける」という分かりにくい詰まり方をします。

### E-3. 認証情報を取得して Script Properties へ

**【秘密】**

アプリの **「Keys and tokens」** で発行します。

| プロパティ名 | コンソール上の名称 | 備考 |
| --- | --- | --- |
| `X_API_KEY` | **API Key**（Consumer Key） | |
| `X_API_SECRET` | **API Key Secret**（Consumer Secret） | |
| `X_ACCESS_TOKEN` | **Access Token** | **自分のアカウントのもの**を生成する |
| `X_ACCESS_TOKEN_SECRET` | **Access Token Secret** | |

> **「Access Token and Secret」は、ログインしているアカウント自身のものを
> その場で発行できます。** OAuth の画面遷移は要りません。
> **一想が OAuth 1.0a を使うのはこのためです**——認可のリダイレクトを受ける
> ウェブページが要らず、**トークンに期限もありません**（Threads と違い、
> 60日ごとの更新が不要）。

> **表示は1度きりのことがあります。** その場で Script Properties に入れてください。
> 控え損ねたら「Regenerate」で作り直せます（**古い値は無効になります**）。

### E-4. 従量課金と、月次の支出上限

> **課金は投稿ごとにあなたに発生します。** 上限を設定しないまま自動化しないでください。

1. Developer Portal の **プラン／課金**（Subscriptions / Billing）を開く
2. **先に支出上限を設定する**（monthly spend limit / budget cap）

| 項目 | **初期値** |
| --- | --- |
| 月次の支出上限 | **10 USD** |

   - **【TODO】** 設定欄の実際の名称と、設定できる最小額を記録してください
   - **10 USD は「事故で青天井にしない」ための値**です。実際にいくらかかるかは
     E-0 の【記録】2（単価）が分かってから見直します
3. 従量課金を有効にする
4. **請求の通知先メールアドレスを確認する**（届かないと気づけません）

> **2 を 3 より先に書いてあるのは意図的です。** 有効化してから上限を設定するまでの間に
> 投稿が走ると、上限の無い状態で課金されます。**順序を入れ替えないでください。**

**【記録】** 支出上限の欄が**無い**場合は、その旨を教えてください。

#### 一想側にも上限を持ちます（X 側の設定と二重に）

**X 側に上限があっても、一想側でも止めます。**

一想は投稿を `posts` シートに記録しているので、
**「今月すでに N 件投稿していたら、それ以上投稿しない」**という制限を持てます。

| 設定値 | **初期値** | |
| --- | --- | --- |
| `x.monthlyPostLimit` | **60** | 件/月（**1日2件ペース**） |

設定は一想の画面（**設定**）から変えられます。**0 にすると X への投稿を止められます。**

> **X 側の上限設定の有無にかかわらず入れます。**
> **外部サービスの課金を、外部サービスの設定だけに頼らない**——
> 止められる場所が自分の手元にもあるほうが安全です。
> また、X 側の上限は**課金額**で止まりますが、こちらは**件数**で止まるので、
> **単価が変わっても件数の見込みは変わりません。**

> **60件/月・10 USD はどちらも仮の初期値です。** E-0 の単価が分かったら、
> 「60件 × 単価」が 10 USD に収まるかを確かめて、両方を見直してください。

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| 画面が真っ白 | B-2 で `Index` / `Style` / `Script` の**3つとも HTML ファイルとして**作ったか |
| 「Script Properties に … が設定されていません」 | B-3。**名前が正確か**（前後の空白に注意） |
| コードを直したのに画面が変わらない | B-5 の「デプロイを管理」→ **新バージョン**。保存だけでは反映されません |
| 「シートが見つかりません」 | B-4 の `issoSetup` を実行したか。`ISSO_SPREADSHEET_ID` が正しいか |
| 「この段階はすでに依頼中です」 | `generation_queue` に `待機`/`処理中`/`完了` の行が残っています。**その行の `status` を `失敗` にする**と再依頼できます |
| 「更新」を押しても取り込まれない | その行が `完了` になっているか。`取込済` なら**すでに取り込み済み**です（版が増えているはず） |
| 前の段階のタブが押せない | **前段を採用していません。** 生成しただけでは進めません |
| Threads が突然失敗する | **長期トークンの60日**（D-3）。取り直してください |
| X が 403 | E-2 の **App permissions を Read and write にした後**でトークンを取り直したか |
| 「今月の X への投稿が上限に達しています」 | 一想側の上限（E-4・既定60件/月）です。**画面の設定 `x.monthlyPostLimit` で変えられます** |

> **エラーは画面にそのまま出ます**（言い換えていません）。**文面をそのまま教えてください。**
> ただし**トークン・キーが含まれていないか確認してから**にしてください。
