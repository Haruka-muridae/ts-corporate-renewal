# D-4 先行確認：Threads へ開発モードのまま投稿できるか

**作成日**: 2026年8月8日
**所要**: 30〜60分（Meta 側の反映待ちを含む）
**実施**: 発注者

---

## なぜこれを先にやるのか

**第1段の成立条件**だからです。

一想の第1段は「Meta App Review を通さず、**開発モードのまま発注者自身のアカウントへ
投稿する**」という想定に立っています（[roadmap.md](./roadmap.md) §2）。
**この想定が崩れると、Threads 連携そのものが第1段から外れます。**

実装（GAS・Sheets・画面）はこの結果に依存しないので、**並行して確認**できます。
手順書 `setup-v1_0-personal.md` の完成を待つ必要はありません。

> **確認するのは1点だけです。**
> 「審査を通していないアプリから、自分の Threads アカウントへ投稿できるか」

---

## 事前に用意するもの

| | |
| --- | --- |
| Meta アカウント | 開発者登録が済んでいるもの（未登録なら手順1で行う） |
| **Threads アカウント** | **投稿先。テスト投稿が公開されます**（後で消せます） |
| ブラウザ | Graph API Explorer を使うため、PC を推奨 |

> **テスト投稿は実際に公開されます。** 差し支えない文面にしてください
> （例:「テスト投稿です。まもなく削除します。」）。確認後に消せます。

## 手順

### 1. Meta for Developers でアプリを作る

1. <https://developers.facebook.com/> を開き、Meta アカウントでログイン
2. 開発者登録が未了なら、案内に従って登録する
3. **「マイアプリ」→「アプリを作成」**
4. ユースケースの選択で **「Threads API へのアクセス」**（表記は変わることがあります。
   Threads に関するものを選ぶ）
5. アプリ名を入力（例: `一想` / `ISSO`）。**表示名は後から変えられます**
6. 作成する

> **アプリは開発モードで作られます。そのままにしてください。**
> ライブモードへ切り替えると App Review が必要になり、この確認の意味がなくなります。

### 2. 自分の Threads アカウントに**アプリのロールを付与**する

**ここがこの確認の中心です。** 開発モードのアプリは、**ロールを持つ人のアカウント
にしか投稿できません。** 逆に言えば、ロールさえあれば審査なしで投稿できます。

1. アプリの管理画面で **「アプリの役割」→「役割」**（App Roles → Roles）を開く
2. 自分が **管理者（Administrator）** として入っていることを確認
3. **Threads のテスターとして自分を追加**する項目があれば追加する
   （「Threads テスター」「テストユーザー」など、Threads 用の役割欄）
4. 追加した場合、**招待の承認が要ることがあります。**
   <https://www.threads.net/settings/account> または Threads アプリの
   「設定 → アカウント → ウェブサイトのアクセス許可」あたりに承認待ちが出ます

> **【記録してください】** ここで**どの役割欄に何を追加したか**をメモしてください。
> 手順書（setup-v1_0-personal.md §D）に反映します。**画面構成は変わるため、
> 実際に見た名称が正です。**

### 3. Threads の設定を確認する

アプリ管理画面の **「Threads API」→「設定」** で、次を確認・設定します。

| 項目 | 値 |
| --- | --- |
| **リダイレクトURI** | この確認では使いませんが、後で要ります。**空のままで構いません** |
| **必要な権限（スコープ）** | `threads_basic` と `threads_content_publish` |

### 4. アクセストークンを取る

**この確認の目的はトークンの取得方法の確立ではなく、投稿できるかの確認**です。
最短の方法を採ります。

**方法A: Graph API Explorer（推奨）**

1. <https://developers.facebook.com/tools/explorer/> を開く
2. 右上の「Meta App」で**手順1で作ったアプリ**を選ぶ
3. 「User or Page」で **Threads のユーザートークン**を選ぶ（選択肢に
   Threads が出ない場合は方法Bへ）
4. 権限に `threads_basic` と `threads_content_publish` を追加
5. **「Generate Access Token」** を押し、承認する
6. 表示されたトークンを控える

**方法B: 認可URLを自分で開く**

Explorer に Threads が出ない場合、次のURLをブラウザで開きます
（`YOUR_APP_ID` と `YOUR_REDIRECT_URI` は手順1・3の値に置き換え）。

```
https://threads.net/oauth/authorize
  ?client_id=YOUR_APP_ID
  &redirect_uri=YOUR_REDIRECT_URI
  &scope=threads_basic,threads_content_publish
  &response_type=code
```

承認後、リダイレクト先URLの `code=` の値を使って、アプリのシークレットと
引き換えにトークンを取得します（Meta のドキュメントの手順に従ってください）。

> **方法Bが必要になった場合、リダイレクトURIの設定が要ります。**
> ローカルで受けるなら `https://localhost/` を手順3で登録しておいてください。

> ### 【重要】トークンの扱い
> - **トークンは認証情報です。** チャット・課題管理ツール・スクリーンショットへ
>   貼らないでください（`gas-auth` と同じ扱いです）
> - この確認で使ったトークンは、**確認後に失効させて構いません**
> - **私（Claude Code）へ値を送る必要はありません。** 必要なのは「取れたかどうか」だけです

### 5. 自分のユーザーIDを調べる

投稿には Threads のユーザーIDが要ります。

```
GET https://graph.threads.net/v1.0/me?fields=id,username
```

Graph API Explorer なら、上のパスを入れて実行するだけです。
返ってきた `id` を控えます。

### 6. **投稿してみる**（本題）

Threads の投稿は**2段階**です。コンテナを作ってから公開します。

**6-1. コンテナを作る**

```
POST https://graph.threads.net/v1.0/{ユーザーID}/threads

  media_type = TEXT
  text       = テスト投稿です。まもなく削除します。
```

返ってきた `id`（コンテナID）を控えます。

**6-2. 公開する**

```
POST https://graph.threads.net/v1.0/{ユーザーID}/threads_publish

  creation_id = {コンテナID}
```

**6-3. Threads で確認する**

自分の Threads アカウントに投稿が出ていれば **成立**です。

### 7. 後片付け

- テスト投稿を削除する
- 使ったアクセストークンを失効させる（アプリ管理画面から）

## 結果ごとの扱い

| 結果 | 第1段への影響 |
| --- | --- |
| **投稿できた** | **想定どおり。** 第1段の Threads 連携をそのまま実装します |
| **ロール付与だけで足りた** | 手順書 §D が短くなります |
| **追加の申請・審査が要った** | 要る作業を手順書 §D に足します。**第1段の範囲は変わりません**（自分のアカウントへの投稿なので） |
| **開発モードでは投稿できない** | **第1段から Threads を外し、X と note の2媒体で始めます。** Threads は第2段（App Review 通過後）へ。**申請文面は [archive/phase0/review-submissions.md](./archive/phase0/review-submissions.md) §2 に完成済み**なので、進める判断は後からでもできます |

> **最後の場合でも第1段は成立します。** note は Helper 経由、X は BYOキー方式で
> 独立しているため、Threads が外れても着想→X→note→台本のパイプラインは動きます。
> **その判断ができるように、この確認を先にお願いしています。**

## 補足：この確認が第2段で意味を持つこと

第2段（会員向け）では **App Review が必須**です。この確認で分かるのは
「**発注者自身のアカウントには審査なしで投稿できるか**」であって、
**会員が使えるかではありません。**

したがって、この確認が成功しても **[archive/phase0/review-submissions.md](./archive/phase0/review-submissions.md)
の申請文面は捨てません**（[roadmap.md](./roadmap.md) §2）。
