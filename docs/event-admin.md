# 交流会 管理画面

実装仕様書9章の管理画面。URL は `/event/admin/`。

| 画面 | URL |
| --- | --- |
| ログイン | `/event/admin/login/` |
| 申込者一覧 | `/event/admin/` |
| 申込者詳細 | `/event/admin/<申込ID>/` |
| 申込者CSV（全件） | `/event/admin/csv/applications/` |
| 名札印刷用CSV（支払済みのみ） | `/event/admin/csv/nametags/` |

未ログインでページを開くとログイン画面へ送られ、CSV は 401 で拒否される（受入条件10）。

## 1. 管理者ユーザーの作成

管理者は Supabase Auth に登録する。**このプロジェクトの Supabase に登録された
利用者＝管理者**という設計にしてある。一般の申込者は認証を一切通らない
（申込はサーバー側が service role キーで書き込む）。

そのため、**管理者以外を登録してはいけない**。あわせて新規登録も止めておく。

### 1-1. 新規登録を無効にする（最初に1回だけ）

<https://supabase.com/dashboard/project/ixxxlmfhrtommsfiumlz/auth/providers>

* **Email** を開き、**Allow new users to sign up** を **オフ**にする

これを切らないと、誰でも自分でアカウントを作って管理画面に入れてしまう。

### 1-2. 管理者を追加する

<https://supabase.com/dashboard/project/ixxxlmfhrtommsfiumlz/auth/users>

1. 右上の **Add user** → **Create new user**
2. **Email** に管理者のメールアドレスを入れる
3. **Password** を設定する（自動生成でもよい）
4. **Auto Confirm User** を**オン**にする
   （オフだと確認メールを踏むまでログインできない）
5. **Create user**

この手順を管理者2名分（齋藤貴之・齋藤悠貴）行う。パスワードは本人へ直接渡し、
最初のログイン後に各自で変更してもらうこと。

### 1-3. パスワードを変える・忘れたとき

同じ画面で対象の利用者の行の「…」から **Reset password** を選ぶと、
パスワード再設定のメールが送られる。または **Update user** から直接設定する。

### 1-4. 管理者を外すとき

同じ画面から **Delete user** で削除する。削除すると、その利用者が持っていた
セッションでは次のページ表示から入れなくなる。管理画面はページを開くたびに
Supabase へ利用者の有効性を問い合わせているため、期限切れを待つ必要はない。

## 2. できること

### 申込者一覧

受付番号 / 氏名 / メール / 会社名 / 業界 / 職種 / 立場 / 年齢区分 / 出禁申告 /
割引内訳 / 支払金額 / ステータス / 申込日時 / 決済日時 を表示する。
上部に全件数・支払済み件数・支払済みの合計金額を出す。

### 申込者詳細

全入力情報、割引計算の内訳、Stripe の ID 類、譲渡履歴、管理者メモを表示する。

割引の内訳は `payments` に保存した**申込時点のスナップショット**を正とする。
参考として現在の割引ルールで計算し直した金額も併記し、食い違う場合は
その旨を示す（ルール変更の前後で申し込まれた記録を見分けるため）。

### 申込者情報の編集（譲渡対応）

氏名・フリガナ・メール・電話・会社名・部署名・役職名・管理者メモを書き換えられる。

「譲渡として記録する」にチェックすると、譲渡元の氏名とメール、譲渡日時を
履歴に残す。2回目以降の書き換えでは譲渡元を上書きしない（最初の申込者が
分からなくなるため）。

**受付番号と支払金額は変わらない**（仕様書7.2）。譲渡先の属性が違っても
差額の徴収・返金はしない。

### 参加確定メールの再送

現在登録されているメールアドレス宛に送り直す。譲渡で宛先を変えたあとに使う。
受付番号が未発行（＝支払済みでない）の場合は送れない。

### CSV出力

* **申込者CSV**：一覧と同じ項目を全件
* **名札印刷用CSV**：**支払済みのみ**、氏名・会社名・業界・職種・立場の5項目だけ。
  **年齢は含めない**（仕様書7.3。当日の名札に年齢を記載しないため）

どちらも Excel で開けるよう BOM 付き・CRLF で出力する。氏名や会社名が
`=` などで始まる場合に Excel が数式として実行しないよう無害化している。

### 返金

管理画面からは行わない。Stripeダッシュボードから手動で返金すると、
Webhook を通じてステータスが「返金済み（例外対応）」になる（仕様書7.1）。

## 3. まだ実装していないもの

* **受付状態の切替**（受付中 / 満席 / 受付終了）
  仕様書9章では管理画面から変更できるようにするとしているが、
  交流会の詳細ページ（`/event/`）は静的HTMLのままにする方針のため、
  管理画面から切り替えても表示は変わらない。現時点では
  `public/event/index.html` の `data-event-status` を書き換えて運用する。
  詳細ページをNextのページへ移す判断をした時点で、管理画面へ移す。
* ダッシュボード / イベント編集画面 / 割引ルール管理 / 返金機能（フェーズ2）

## 4. 設計上の要点

### セッション

アクセストークンは httpOnly の Cookie に置く（ブラウザのJavaScriptからは読めない）。
Cookie のパスは `/event/admin` に限定し、公開画面へは送らない。

ページを開くたびに Supabase へ問い合わせて有効性を確かめる。期限の見た目だけで
通すと、管理者を削除した直後にも入れてしまうため。期限が近い場合は
リフレッシュトークンで取り直す。

### ログインの失敗メッセージ

「メールアドレスが存在しない」と「パスワードが違う」を区別せず、
同じ文言を返す。区別すると、登録済みのアドレスを探る手掛かりになる。
