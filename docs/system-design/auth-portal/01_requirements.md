# 本番認証系（TSAM AI ログイン・Portal・決済連携）— 要件定義書

対象アプリID: `auth-portal`

読者は「このリポジトリを知らないが、このアプリを自分のプロダクトへ移植したい開発者」を想定する。
本書は既存仕様書（[docs/specs/login-page-detailed-spec-v3.md](../../specs/login-page-detailed-spec-v3.md) ほか）を置き換えない。詳細は §番号で既存仕様書へ参照を張る。

---

## 1. 目的・背景

TSAM AI が提供する複数の本番アプリ（ブラウザ録音、領収書スキャナ等）に対し、共通の認証・利用者管理・決済（サブスクリプション課金）を提供する。

このアプリの担う責務は次の3つに整理できる。

1. **本人確認**（ログイン・セッション維持・ログアウト）
2. **アプリ入口の提供**（Portal からログイン後のアプリ一覧へ遷移する）
3. **課金の開始と継続**（プラン選択・法的な事前同意・Stripe Checkout・Webhook による契約状態の反映）

配信は静的ホスティング（HTML/JS）＋ Google Apps Script（以下 GAS）という、サーバーレスかつ低コストな構成を意図的に選んでいる。利用者規模が数百人規模になるまでは、この構成で十分という判断（[AUTH_SETUP.md](../../../AUTH_SETUP.md)「将来の移行について」）。

## 2. 用語定義

| 用語 | 意味 |
| --- | --- |
| セッショントークン | ログイン成功時にサーバーが発行する、推測困難なランダム文字列。ブラウザは `localStorage` に保存し、認可判断の材料にはしない |
| アカウント状態（`account_status`） | 利用者アカウント自体の状態（`pending` / `active` / `suspended` / `disabled` / `locked`）。当社側の運用値 |
| 契約状態（`subscription_status`） | Stripe のサブスクリプション状態（`active` / `trialing` / `past_due` / `canceled` 等）。Stripe 由来の値 |
| `payment_exempt` | 決済確認を省略するフラグ（管理者・招待枠向け） |
| 同意（consent） | 申込み直前に利用規約・自動更新・API利用料・解約条件へ同意する行為。特定商取引法対応の一部 |
| guardPage | 保護対象ページの入口関数。サーバーへセッションを確認し、有効と答えるまで内容を描画しない |
| KeyStore | 利用者が自分で発行した外部AIサービス（Gemini）のAPIキーを、端末内にのみ保管する仕組み。当社サーバーへは送らない |

## 3. スコープ

### 対象

- `/login/`（ログイン）
- `/portal/`（ログイン後のアプリ入口、アカウント情報、APIキー設定）
- `/pricing/`（プラン選択と申込み前の同意）
- `/password/setup/` `/password/reset/`（パスワード初期設定・再設定）
- `/payment/success/` `/payment/cancel/`（Stripe Checkout からの戻り先）
- `/logout/`
- `public/auth/`（上記画面が共有する通信層・UI部品・セッション管理・KeyStore）
- `gas-auth/`（GAS 認証バックエンド。ログイン判定・セッション・パスワード・Stripe連携・Webhook・同意設定の配信）

## 4. 利用者とロール

| ロール | 判定方法 | できること |
| --- | --- | --- |
| 未認証の訪問者 | セッショントークン無し、または verifySession が無効と返す | `/login/` `/pricing/` `/password/*` の閲覧・操作。保護対象アプリへは入れない |
| 一般利用者（`role: member`） | ログイン成功後、`isAdmin: false` | Portal からアプリを開く。自分のアカウント情報の閲覧、パスワード変更、APIキーの管理 |
| 管理者（`role: admin`） | `role` 列が `admin`。**メールアドレスでは判定しない**（[portal-spec-v1.md](../../specs/portal-spec-v1.md) §3-2） | 一般利用者と同じ画面操作に加え、Portal 上に管理者バッジが表示される。管理操作自体（利用者停止等）はスプレッドシート直接編集で、画面上の管理機能は無い（§9 未確定/未実装参照） |
| 決済免除利用者（`payment_exempt = TRUE`） | ロールとは独立した列 | 契約状態を問わず利用可（管理者・招待枠向け） |

権限そのものはサーバー（`users` シートの `role` 列・`payment_exempt` 列）が持つ。画面側の表示制御（管理者バッジ等）は権限の実体ではない。

## 6. 非機能要件

| # | 要件 |

| NFR-01 | パスワードは PBKDF2-HMAC-SHA256（既定反復回数10,000）＋利用者ごとソルト＋アプリ全体で共有する pepper（Script Properties）でハッシュ化して保存する。平文は保存・ログ出力・メール記載しない |

## 7. 制約条件

- **GAS の `doGet`/`doPost` は HTTPリクエストヘッダーを受け取れない。** User-Agent はリクエスト本文で送る（詐称可能な参考値と割り切る）。Stripe 署名ヘッダーも直接は受け取れないため、Stripe API への再照会で真正性を担保する（NFR-03）。
- **GAS は単一エンドポイント（`/exec`）しか持てない。** REST パス形式は採らず、`action` パラメータで分岐するホワイトリスト方式とする。
- **プリフライト（OPTIONS）に GAS が応答できない。** POST は `Content-Type: text/plain;charset=utf-8` で送り、単純リクエストに収める。
- **GAS には `crypto.getRandomValues` も PBKDF2 の実装も無い。** `Utilities.getUuid()` の合成とSHA-256圧縮で乱数を、HMAC-SHA256の反復でPBKDF2を自前実装する。
- **静的ホスティングはリクエストを止める仕組みを持たない。** HTML/JSファイルそのものの取得は防げず、保護できるのはサーバー側のデータと操作のみ。
- **KeyStore が扱う利用者の外部APIキーは、当社サーバーへ送らない設計を維持する。** これは技術的制約ではなく意図的な設計方針（keystore-spec-v1.md §2）。

## 9. 前提条件・未確定事項

### 前提

- 利用者規模は数百人未満を想定する（スプレッドシートの全件走査が成立する範囲）。
- Apps Script の実行速度制約（PBKDF2 反復回数を大きくできない）を、pepper の併用で補うという方針を継続する前提。
