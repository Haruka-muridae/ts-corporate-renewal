# ショート動画 台本メーカー（short-script）要件定義書

作成: 2026年8月18日

> 本書は `docs/system-design/_authoring-guide.md` の規約に従う。実装と
> [docs/specs/short-script-spec-v1.md](../../specs/short-script-spec-v1.md)（以下「仕様書」）が正であり、
> 本書は移植を検討する読者向けに要点を整理したものである。詳細は仕様書の該当 §番号を参照する。

## 1. 目的・背景

「ショートAIスタジオ」（テーマから台本→音声→字幕→縦型動画を自動生成する構想）を、TSAM AI Portal の本番アプリとして段階的に実装したものである（仕様書 §1）。

- **第1段階**: テーマから Gemini で台本（タイトル＋シーンごとのナレーション）を生成する。VOICEVOX にブラウザ版が存在せずローカルエンジン必須という制約と無関係にブラウザ完結できるため、先行して単体提供した。
- **第2段階**: 台本を利用者のPCで動くローカル補助サービス（別プロダクト `ai-video-app`。本リポジトリには同梱されない）へ渡し、ナレーション音声（VOICEVOX）付きの縦型動画（FFmpeg）を生成する（仕様書 §13）。

いずれも「利用者の資格情報（Gemini APIキー）も生成物も当社サーバーへ送信しない」という BYOK（Bring Your Own Key）原則を貫く（仕様書 §0.1）。当社が提供するのは静的アプリという「道具」のみで、サーバーコードを持たない。

## 2. 用語定義

| 用語 | 意味 |
| --- | --- |
| BYOK | Bring Your Own Key。利用者本人が発行した API キーを利用者自身が使う方式。当社は預からない。 |
| KeyStore | `public/auth/keystore.js`。Gemini API キーをブラウザの localStorage（キー名 `tsam-api-keys`）へ保存する共通モジュール。 |
| guardPage | `public/auth/session.js` が提供する、保護対象ページの入口関数。サーバー検証が済むまで画面内容を描画させない。 |
| Companion / ai-video-app | 利用者のPC上で動くローカル補助サービス。VOICEVOX（音声合成）と FFmpeg（動画合成）を実行する別プロダクト。short-script 自体には同梱されない。 |
| NDJSON | Newline Delimited JSON。Companion の `/api/generate` が進捗を1行1JSONで返すストリーミング形式。 |
| Ken Burns | 静止画をゆっくりズーム／パンさせる映像効果。背景画像に自動適用される（Companion 側の処理）。 |
| セグメント編集 | Gemini を介さず、〔ナレーション文＋背景画像〕の組を利用者が手動で並べて台本を組み立てる入力方式。 |
| 3状態 | Companion の接続状態を表す `offline` / `engine-offline` / `online` の区分（仕様書 §13.3）。 |

## 3. スコープ

### 3.1 対象

- 入力方式3種（AIで作る／台本を貼り付け／セグメント編集）による台本の作成（仕様書 §3.1, §7）。
- 生成・取り込み結果の画面表示、プレーンテキストのコピー、JSON での保存（仕様書 §8）。
- ローカル補助サービス（ai-video-app）と連携した、ナレーション音声付き縦型動画の生成（仕様書 §13）。
- ログイン必須（`guardPage`）と Gemini APIキー必須（AI モードのみ）の2つのガード（仕様書 §4）。
- ヘルプ画面（`help/`）。

### 3.2 対象外

- 音声・動画のブラウザ内完結生成（VOICEVOX はローカルエンジン必須のため原理的に不可。仕様書 §1, §3.2）。
- 台本の保存・履歴・アカウントへの紐付け（その場でコピー／ダウンロードするのみ。仕様書 §3.2）。
- BGM、SNS投稿、Companion の URL を画面から変更する機能（将来拡張。仕様書 §13.4）。
- Companion（ai-video-app）自体の実装。short-script はそのクライアントであり、Companion 側のソースはこのリポジトリの対象外。

## 4. 利用者とロール

| 利用者 | 前提 | 制約 |
| --- | --- | --- |
| ログイン済みの一般利用者 | `guardPage()` によるサーバー検証済みセッション（`tsam-auth-session`） | 未ログインはログイン画面へ強制遷移。中身（`#ss-content`）は描画されない。 |
| AI モード利用者 | 上記に加え、KeyStore に自分の Gemini APIキーを保存済み（`KeyStore.has('gemini')`） | 未設定時は案内パネルを表示し生成ボタンを無効化。設定導線は Portal「API設定」。 |
| 貼り付け／セグメント編集利用者 | ログインのみ | Gemini キー不要。§4 のキーガードはこの2方式にはかからない。 |
| 動画生成を行う利用者 | 上記に加え、自分のPCで ai-video-app を起動していること | ロールという意味での区別ではなく、ローカル環境の準備状況によって機能可否が変わる（3状態。§13.3）。 |

ロールによる権限分岐（管理者／一般利用者の区別など）はこのアプリには存在しない。

## 5. 機能要件

| ID | 要件 | 補足 |
| --- | --- | --- |
| FR-01 | 入力方式（AIで作る／台本を貼り付け／セグメント編集）をラジオボタンで切り替えられる | 切り替えると前の結果・メッセージを引き継がない（仕様書 §7.7、app.js `applyMode`）。 |
| FR-02 | テーマ（最大100文字）と尺（30秒／60秒）から Gemini で台本を生成する | シーン数の目安・秒数合計・話し言葉・フック/まとめ構成を指示（仕様書 §7.2）。 |
| FR-03 | 既存の台本本文を Gemini を介さず全文1シーンとして取り込む | Gemini キー不要。60文字への切り詰めは行わない（仕様書 §7.6）。 |
| FR-04 | セグメントごとに〔ナレーション文＋任意の背景画像〕を指定し、上から順に並べて台本を組み立てる | 最大20セグメント。空文字セグメントは取り込み時に除外（仕様書 §7.7）。 |
| FR-05 | Gemini の応答を必ず既定の形へ正規化する | title 空／scenes 非配列／全シーン除外はエラー扱い。秒数は2〜20へ丸め、文は60文字に切り詰め（仕様書 §7.5）。 |
| FR-06 | 生成・取り込み結果（タイトル・メタ情報・シーン一覧）を画面表示する | メタ情報は由来（AI／貼り付け／セグメント）で内容を変える（仕様書 §8.1）。 |
| FR-07 | 台本をプレーンテキストとしてクリップボードへコピーする | `navigator.clipboard` 不可時は失敗を通知（仕様書 §8.2）。 |
| FR-08 | 台本を後段（音声・字幕・動画）が読める JSON として保存する | 由来ごとに付随情報を変える。ファイル名はタイトルから禁止文字を除去（仕様書 §8.3）。 |
| FR-09 | 生成エラーをコード＋原因要約（detail）付きで表示する | KEY-001/002, AI-001〜005, SYS-999 の体系（仕様書 §9）。 |
| FR-10 | ローカル補助サービス（ai-video-app）の疎通状態を3状態（offline/engine-offline/online）で判定し、状態に応じた案内を出す | `X-Engine-Status` ヘッダを正とする。ヘッダ欠落は後方互換で online 扱い（仕様書 §13.1, §13.3）。 |
| FR-11 | 「エンジンを起動」操作で VOICEVOX の起動を依頼し、online になるまでポーリングする | 2秒間隔・最大30秒。409（未インストール）は即時案内、404（旧版）は手動起動を案内、到達失敗2回連続で打ち切り（仕様書 §13.3）。 |
| FR-12 | 台本と声設定（話者・話速）、任意の背景画像から、ナレーション音声付き縦型動画を生成する | 進捗は NDJSON で逐次表示。背景画像はシーン数と同数なら1対1対応、それ以外はローテーション（仕様書 §13.1）。 |
| FR-13 | 生成済み動画を画面内で再生し、MP4としてダウンロードできる | Range 対応（`GET /api/video/:id`。仕様書 §13.1）。 |
| FR-14 | ヘルプ画面でデータの扱い・APIキー・商用利用上の注意を提示する | ログインガードのみ（Gemini キー無関係。仕様書 §4, help/index.html）。 |
| FR-15 | ログイン未検証時／Gemini キー未設定時に、それぞれ適切な案内へ誘導する | 画面再表示（`visibilitychange`/`focus`）時にキー状態を読み直す（仕様書 §4）。 |

## 6. 非機能要件

### セキュリティ

- NFR-01: Gemini APIキーは KeyStore の外で localStorage を直接扱わない。値を読むのは生成の瞬間のみで、モジュールに保持しない・console やログ・URL に出さない（仕様書 §0.2, §10.1）。
- NFR-02: CSP はページごとに `<meta>` で宣言する（`next.config.ts` の変更は本体サイトを巻き込むため採らない）。`script-src` は `'self'` のみでインライン・eval なし（仕様書 §10.2, index.html）。
- NFR-03: DOM 組み立ては `createElement`/`textContent` のみで行い、`innerHTML` を使わない（リポジトリ共通方針。app.js 全体で徹底）。
- NFR-04: ローカル補助サービスとの通信では、許可オリジンを `https://tsam-ai.com` と `localhost`/`127.0.0.1` に絞った CORS＋Private Network Access ヘッダを Companion 側が返す前提とする（`*` を使わない。仕様書 §13.2）。

### 性能

- NFR-05: Companion への疎通確認・話者取得は4秒でタイムアウトする（`PING_TIMEOUT_MS`。companion.js）。
- NFR-06: エンジン起動のポーリングは2秒間隔・最大30秒（実測7.9秒の約4倍のマージン。仕様書 §13.3、config.js）。

### 可用性

- NFR-07: ローカル補助サービスが未起動／VOICEVOX 停止でも、台本生成（第1段階の機能）は独立して利用できる（仕様書 §1 の設計方針）。
- NFR-08: Companion への到達失敗が2回連続した場合のみ「アプリ自体が落ちた」と判断し、1回の瞬断では状態を維持する（仕様書 §13.3）。

### 運用

- NFR-09: プロンプトの指示を変更したら `PROMPT_VERSION`（prompt.js）を、それに伴い `APP_VERSION`（config.js）も上げる（仕様書 §7.2）。
- NFR-10: 本番アプリ間で共通層を作らない方針（[repository-structure.md](../../repository-structure.md) §4-1）に従い、`gemini.js` のエラー分類等は他アプリ（card-ocr）からの複製であり import しない。

### アクセシビリティ

- NFR-11: 320/375/768/1024/1440px のレスポンシブ確認、操作要素44px以上（仕様書 §11、AGENTS.md）。
- NFR-12: ラベルと入力の対応、`role="status"`/`aria-live` による進捗・エラーの読み上げ、結果見出しへのフォーカス移動（`tabindex="-1"`）、`prefers-reduced-motion` への配慮（仕様書 §11）。
- NFR-13: 尺セレクタの選択ハイライトは `:has()` を用いる。非対応ブラウザではハイライトのみ出ないがラジオ自体は機能する（仕様書 §11）。

## 7. 制約条件

- サーバーコードを持たない静的アプリであること（BYOK原則の帰結。仕様書 §0.1）。
- Portal と同一オリジンに配置すること（KeyStore 参照の必須条件。仕様書 §0.1）。
- 外部ライブラリを追加しないこと。素の ES モジュールと `fetch` のみを使う（仕様書 §6）。
- `public/production-app/` 配下でアプリ間の共通層（`shared/`/`common/`/`lib/`）を作らないこと。同じロジックが要る場合は複製し、複製元パスと複製日を冒頭コメントに書く（[repository-structure.md](../../repository-structure.md) §4-1）。
- テスト環境 `public/apps/` のコードを import しないこと（複製する。仕様書 §2）。
- `APP_REGISTRY`（`public/portal/app-registry.js`）の `id` は配置データが指す先であり、あとから変更しないこと。
- `href` は相対パスとし、先頭 `/` を付けず `apps/` を含めないこと（[repository-structure.md](../../repository-structure.md) 全体像の表、`app-registry.js` のコメント）。

## 8. 外部依存

| 依存先 | 用途 | 認証・鍵の扱い |
| --- | --- | --- |
| Gemini API（`generativelanguage.googleapis.com`） | AI モードの台本生成（`generateContent`） | 利用者本人の APIキーを `x-goog-api-key` ヘッダーで送信（BYOK）。当社は預からない。 |
| Apps Script（`script.google.com` / `script.googleusercontent.com`） | `guardPage()` のセッション検証・ログアウト（`public/auth/api.js` 経由） | 当社の認証基盤。エンドポイントURLは秘密情報ではないが、本書には値を書かない。 |
| ai-video-app（ローカル補助サービス。既定 `http://127.0.0.1:3000`） | 話者取得・エンジン状態確認／起動・動画生成・完成動画配信 | 利用者PC上で稼働。OAuth 等の認証は行わない（同一利用者のローカル通信）。 |
| Portal アプリ一覧スプレッドシート | Portal 上でのカード掲載（アプリID／名称／URL／アイコン） | シートIDは仕様書・本書ともに非掲載。実値は `public/portal/app-source.js`。 |

このアプリは Google OAuth（GIS）を使わない（仕様書 §10.2）。

## 9. 前提条件・未確定事項

仕様書 §0.3 に明記されている未確定事項をそのまま引き継ぐ。

- 実 Gemini API が `responseSchema`（§7.3 相当）を受理し期待どおりの JSON を返すことは、同型実装（card-ocr）で確認済みだが、本アプリでの実 API 疎通は本書作成時点で未検証。
- ログイン後の実UI（フォーム→生成→表示）の目視確認は、要ログイン環境またはプレビュー配信で行う必要があり、ローカル（別オリジン）では確認できない。

加えて、本書作成にあたり実装（テストスイート構成）から確認できた事実として次を記す（詳細は [03_detailed-design.md](./03_detailed-design.md) §8）。

- `gemini.js`・`prompt.js`・`paste.js` の単体挙動を検証する自動テストは、本リポジトリの `tests/run.mjs` SUITES に存在しない（存在するのは `short-script-companion` の1件のみで、対象は `companion.js`・`config.js`・静的ソース検証）。この事実は「未確定」ではなく確認済みの事実として記載する。
