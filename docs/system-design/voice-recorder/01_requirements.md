# ブラウザ録音アプリ（voice-recorder）要件定義書

## 1. 目的・背景

TSAM AIポータルにログインした利用者が、ブラウザだけで最長90分の音声を録音し、MP3として**利用者自身のGoogle Drive**（マイドライブ ＞ TSAM AI ＞ Voice Recorder）へ保存できるようにする。録音・MP3変換・一時保存はすべて端末内で完結し、当社のサーバーを音声が経由しない。

もとの要件定義書 v1.1 は、録音を一時形式（WebM/Opus）のままバックエンドAPIへ送り、サーバー側でFFmpegによりMP3変換・Drive保存する構成を前提にしていた。実装着手前の調査で、当時のホスティング（Vercel）の関数では90分・約86MBの受信とFFmpeg実行が成立しないことが判明し、v1.2でバックエンドを全廃してブラウザ完結の構成へ改めた。詳細な経緯と根拠は正式な要件定義書の §14（変更履歴）を参照。

**実装済みの詳細は既存要件定義書 [docs/requirements/mvp-requirements.md](../../requirements/mvp-requirements.md)（以下「既存要件書」）を正とする。** 本書は既存要件書を要件定義〜詳細設計の章立てへ再構成し、実装の実態と突き合わせたものであり、内容を置き換えない。歴史的経緯は [docs/requirements/mvp-requirements-v1.1-original.md](../../requirements/mvp-requirements-v1.1-original.md) に保存されている。

## 2. 用語定義

| 用語 | 意味 |
| --- | --- |
| TSAM AIポータル（Portal） | TSAM AIのアプリ一覧画面（`public/portal/`）。本アプリはここから起動する |
| guardPage | `public/auth/session.js` が提供する、TSAM AIログインセッションをサーバー（Apps Script）で検証してから画面を描画する共通の入口関数 |
| drive.file | 「そのクライアントIDのアプリが作成した、または利用者が明示的に開いたファイルだけ」に見える範囲を絞ったGoogle Driveの権限スコープ |
| GIS（Google Identity Services） | Googleが提供するOAuth 2.0のトークンモデル実装。`accounts.google.com/gsi/client` から読み込む |
| トークンモデル（暗黙フロー） | リフレッシュトークンを発行せず、短命のアクセストークンだけで動くOAuthの形。client secretを必要とせず、静的サイトに向く |
| OPFS（Origin Private File System） | ブラウザが提供する端末内の非公開ストレージ領域。本アプリは録音中の一時保存先として使う |
| SyncAccessHandle | OPFS上のファイルへ同期的に読み書きするAPI。専用Worker内でのみ利用できる |
| AudioWorklet | Web Audio APIのうち、オーディオスレッド上で低遅延の音声処理を行う仕組み |
| PCM | Pulse Code Modulation。圧縮前の生の音声サンプル列 |
| resumable upload | Google Drive APIが提供する分割アップロード方式。セッションを開始し、チャンク単位で送信できる |
| バックプレッシャ | 録音（PCM送出）の速度にMP3エンコードが追いつかず、未処理分が溜まっている状態 |
| セッショントークン | TSAM AI認証系が発行する、ポータルへのログイン状態を示すランダム文字列 |

## 3. スコープ

### 3.1 含む（Must）

既存要件書 §2.1 のとおり。要約すると次の10項目。

1. TSAM AIポータル経由のアクセス制御（画面描画前のセッション検証）
2. Google OAuth 2.0によるアカウント連携（`drive.file` スコープのみ、トークンはメモリ上のみ）
3. ブラウザ上での録音開始・停止、経過時間表示（上限90分）
4. 録音後のプレビュー再生と破棄（再録音）
5. ブラウザ内でのMP3逐次変換（モノラル・128kbps）
6. ファイル名の自動生成と編集、同名時の連番付与
7. 保存先フォルダ（名前から解決し、無ければ作成）へのアップロード
8. アップロード進捗表示・保存完了表示（ファイル名・Driveリンク）
9. 保存完了後の端末内一時データ削除、異常終了時の次回起動時クリーンアップ
10. 主要エラーの表示と、認証期限切れ時の再認証導線

### 3.2 含まない（対象外）

既存要件書 §2.2 のとおり。

| 対象外 | 補足 |
| --- | --- |
| 文字起こし・要約・AI分析 | 別アプリ（音声文字起こしアプリ）の領域。保存先フォルダ名だけを共有する |
| 音声編集・複数マイク・バックグラウンド録音・録音予約 | MVPの検証範囲外 |
| 録音一覧・履歴管理・自動分類 | データベースを持たない構成のため |
| 共有設定変更・既存ファイルの削除／移動 | `drive.js` に `permissions.create` を呼ぶ関数を意図的に置いていない |
| 利用者によるフォルダ選択UI | 保存先は固定（名前解決） |
| **異常終了した録音の復旧** | flush前のMP3が確実に再生できる保証がなく、「復旧可能」と表示すると過度な期待を与えるため、意図的に持たない |
| スマートフォン対応 | 動作すれば可だが保証しない |
| Chrome以外のブラウザの動作保証 | Edge/Safariは後続で検証（未着手） |
| 通信切断時の自動リトライ | 手動再試行のみ。ただし録音データ自体はOPFSに残るため再試行は可能 |
| Google Driveカスタムプロパティ等の追加メタデータ | 設定しない |

## 4. 利用者とロール

- TSAM AIポータルにログインでき、Googleアカウントを持つ関係者（少人数の限定ユーザー）。ロールによる機能差はない。
- 対象アカウントは組織アカウントに限定する方針（既存要件書 §10-3。OAuth同意画面を内部限定に設定）。この設定はGoogle Cloud Console側で行うものであり、コードからは検証できない（§9「未確定事項」参照）。
- 対応環境はPC版Google Chrome最新版のみ動作保証。マイク接続済み・インターネット接続ありを前提とする。

## 5. 機能要件

既存要件書 §5（FR-01〜FR-08）の番号をそのまま踏襲する。

| ID | 要件 | 補足（実装参照） |
| --- | --- | --- |
| FR-01 | ポータル経由アクセス制御 | `guardPage()`（`public/auth/session.js`）が画面描画前にセッショントークンをサーバーで検証する。未認証はログイン画面へ誘導。**静的配信のためHTML/JSファイル自体の取得は防げず、これは「画面に入れない」制御であって機密の保護ではない**（実質的な保護はFR-02のOAuthが担う）。同一オリジン配信のためCORS設定は行わない |
| FR-02 | Google連携 | GISのトークンモデルで認証。スコープは `drive.file` のみに限定し増やさない。アクセストークンは `oauth.js` のクロージャ変数にのみ保持し、外部へ参照を返さない。リフレッシュトークン・client secretは扱わない。アプリを開いただけでは認可を要求せず、「連携する」または保存操作から要求する |
| FR-03 | 保存先の解決 | 「マイドライブ ＞ TSAM AI ＞ Voice Recorder」をフォルダIDで固定登録せず、毎回「名前と親の関係」から解決し、無ければ作成する（`drive.js` の `resolveTargetFolder`）。`drive.file` スコープではアプリが作成していないフォルダへ書き込めないための制約。フォルダ名は音声文字起こしアプリ（`public/apps/drive-folders.js`）とも共有しており、片方だけの変更は禁止 |
| FR-04 | 録音 | マイク許可取得後、「録音開始」で開始し経過時間（hh:mm:ss）を表示。上限90分で自動停止、残り5分で予告。対応サンプルレートは44,100Hz/48,000Hzのみ（規格外はリサンプリングせず開始しない）。開始前に空き容量250MB以上を要求し、録音中も安全下限100MBを監視して自動停止する |
| FR-05 | プレビューと破棄 | 停止後にブラウザ上で再生できる（`blob:` URL）。「破棄」でOPFS上の一時ファイルを含めて削除し、再録音できる |
| FR-06 | MP3変換（ブラウザ内・逐次） | AudioWorkletでPCMを取得し、Worker内のlamejsでモノラル・128kbps・`audio/mpeg` へ録音と同時に逐次変換する。変換は録音と同時に進むため、変換失敗は録音失敗として扱い、部分ファイルからの復旧は行わない |
| FR-07 | ファイル名 | 初期値 `YYYYMMDD_HHmmss_録音.mp3`（録音開始時刻・ブラウザのローカル日時基準）。保存前に編集可能、拡張子の自動付与、保存先の同名ファイルには保存直前にDriveへ問い合わせて `_2`, `_3`… の連番を付与する |
| FR-08 | 保存 | 「Google Driveに保存」で resumable upload（8MBチャンク）を開始する。手動保存のみ（自動保存なし）。「準備中／フォルダ確認中／アップロード中／確定中」の4段階の進捗表示。失敗時は再試行導線を出し、録音データは端末内に保持したまま破棄しない。保存完了後に一時データを削除し、異常終了で残った一時ファイルは次回起動時に無条件で自動削除する（24時間待たない） |

上記に加え、既存要件書 §7（画面要件）は、録音データ未保存の状態でページを閉じようとした場合の離脱警告（`beforeunload`）を定めている。これはFR番号を持たない画面要件として実装済み（`app.js` の `handleBeforeUnload`）。

## 6. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | セキュリティ | 通信はHTTPSのみ。ポータルガード（FR-01）は機密の保護ではなく、実質的なアクセス制御はGoogle OAuthが担う。OAuthクライアントIDは公開値であり秘密ではない。実質的な防御はGoogle Cloud側の「承認済みのJavaScript生成元」に本番・開発オリジンのみを登録することで行う |
| NFR-02 | セキュリティ | Google認証トークンはブラウザのメモリ上でのみ保持し、localStorage／sessionStorage／Cookie／URL／ログ／外部送信のいずれにも残さない。ページ再読み込みで消え、再認可が必要になる（意図した挙動） |
| NFR-03 | セキュリティ | 保存先以外のGoogle Driveデータを読み取らない（`drive.file` スコープで担保）。共有設定を変更する関数（`permissions.create` 等）は実装しない |
| NFR-04 | 性能・安定性 | 録音開始操作から2秒以内に録音状態へ移行する。90分録音（MP3約86MB）を安定して録音・変換・保存できる |
| NFR-05 | 性能・安定性 | 録音データ全体を単一のメモリバッファに保持しない。PCMは約0.2秒ぶん、MP3は生成直後にOPFSへ書いて破棄し、メモリ使用量は録音時間に依存せず一定とする。Workerが追いつかない場合は未処理秒数を監視し、5秒で警告・10秒で安全停止する |
| NFR-06 | 可用性・運用 | 保存操作以外はネットワーク接続がなくても録音・変換・プレビューが継続できる（Google通信が必要なのは連携時と保存時のみ）。端末内の一時音声ファイルは保存完了後に削除し、削除失敗に備え次回起動時にクリーンアップを行う |
| NFR-07 | 運用 | バックエンドを持たないため、サーバー側の運用（プロセス監視・定期クリーンアップ・スケーリング）が発生しない。デプロイは静的アセットの配信のみで完結する |
| NFR-08 | アクセシビリティ | 録音状態を色だけで示さず、「録音中」「待機中」等の文言を必ず併記する。点滅アニメーションは `prefers-reduced-motion` に対応する。進捗・状態・エラーには `role="status"` / `role="alert"` / `role="progressbar"` を付与する |

## 7. 制約条件

- **バックエンドAPIを持たない。** 録音・変換・一時保存はすべてブラウザ内で完結する。既存要件書 §14 はこの判断の根拠を当時のホスティング（Vercel）の関数制限に基づいて説明している。本書執筆時点でのホスティングはCloudflare Workers（OpenNext）へ移行済み（`CLAUDE.md` §配信構成）だが、**Cloudflare Workers前提でのバックエンド可否の再評価は行われていない**（§9「未確定事項」）。
- **本番アプリ間で共通層を作らない。** `public/production-app/` 配下に `shared/`・`common/`・`lib/` の類を置かず、アプリ間でimportし合わない（[docs/repository-structure.md](../../repository-structure.md) §4-1）。本アプリの録音ロジックは `public/apps/voice-recorder/`（長時間録音モード）から、OAuth処理は `public/production-app/receipt-ocr/oauth.js` から、それぞれ複製して作られている。複製元を直しても本アプリには反映されない。
- **本番アプリからテスト環境（`public/apps/`）をimportしない。** 流用は複製で行う（[docs/repository-structure.md](../../repository-structure.md) §1）。
- **OAuthクライアントIDは領収書スキャナ（`receipt-ocr`）と意図的に共用する。** `drive.file` はクライアントIDごとに見える範囲が分かれるため厳密にはアプリ間の独立性は保たれないが、共用自体は許容された設計判断である。
- **対応ブラウザはPC版Google Chrome最新版のみ。** リサンプリング機能を持たないため、44.1kHz/48kHz以外のサンプルレートでは録音を開始しない。
- **CSP（Content Security Policy）で通信先を厳格に絞る。** `script-src`/`connect-src` は自身と `accounts.google.com`・`www.googleapis.com`・`script.google.com`・`script.googleusercontent.com` に限定し、第三者CDNを読み込まない。過去にカレンダー通知ゲート（`notifier-gate`）向けの許可を持っていたが、通知機能をテスト環境へ移設した際（2026-08-11）に「使わない許可は置かない」方針で除去済み。
- **同梱ライブラリ lamejs（LGPL-3.0）のライセンス表示を維持する。** 画面フッターからNOTICE・LICENSE全文へのリンクを外さないこと。

## 8. 外部依存

| 依存先 | 用途 | 認証・スコープ |
| --- | --- | --- |
| Google Identity Services（GIS） | OAuth 2.0 トークンモデルでの認可 | 公式配信URL（`accounts.google.com/gsi/client`）のみを承認済みの読み込み先とする |
| Google Drive API v3 | 保存先フォルダの解決・作成、同名ファイルの検索、resumable uploadによるMP3保存 | `drive.file` スコープのみ |

## 9. 前提条件・未確定事項

### 前提条件

1. 利用者がTSAM AIポータルにログイン済みで、Googleアカウントを保有していること。
2. マイクが接続済みで、Chrome（PC版・最新版）で利用すること。
3. Google Cloud Console側で、OAuthクライアントの「承認済みのJavaScript生成元」に本番・開発オリジンが登録済みであること（コードからは検証できない）。
4. 保存先フォルダ名「マイドライブ ＞ TSAM AI ＞ Voice Recorder」は、音声文字起こしアプリ側の定義（`public/apps/drive-folders.js`）と一致していること。

### 未確定事項（本書執筆時点でコード・既存要件書から読み取れないもの）

- 対象アカウントを組織アカウントに限定する設定（既存要件書 §10-3）が、Google Cloud Console側のOAuth同意画面で実際に「内部」設定になっているか、審査は不要な状態か。コードからは確認できない。
- Cloudflare Workers（OpenNext）への移行後も「ブラウザ完結が必須」という既存要件書 §14 の結論が妥当か、再評価が行われたかどうか。移行はホスティングの制約緩和を意味しうるが、本書の調査範囲では再評価の記録が見つからなかった。
- カレンダー通知機能（`public/apps/voice-recorder/` へ2026-08-11に移設済み）を本番へ復帰させるかどうか、および時期。`docs/notifier-v2-resume.md` に手順は残されているが、判断自体は保留中と明記されている。
- `drive.file` スコープの制約により、利用者が手動で作成した同名ファイルとの重複が避けられない（`drive.js` のコメントに明記）。この重複を運用上どこまで許容するかは明文化されていない。
- Edge/Safari対応・スマートフォン対応の着手時期。
