# ブラウザ録音アプリ｜Googleカレンダー通知のセットアップ

作成: 2026年8月9日 ／ **改訂: 2026年8月10日（V2）**

予定が始まる少し前に、パソコンへ「そろそろ始まります。録音しますか？」という
通知を出すための設定手順です。**5分ほど**で終わります。

> **V2 で手順が短くなりました。**
> Apps Script のエディタを開く作業・コードを貼り付ける作業・
> 接続コードを手で貼る作業は、**すべて無くなりました**。

> **通知から録音が自動で始まることはありません。**
> 通知はお知らせだけで、録音は今までどおり「録音開始」ボタンを押したときにだけ始まります。

---

## 0. はじめに

### この仕組みについて

**予定の中身（予定名・参加者・説明）は、あなたのGoogleアカウントの中から出ません。**

- 予定の読み取りも、通知の送信も、あなたのアカウント内のプログラムが行います
- 設定・通知の記録は、あなたのGoogleドライブにあるスプレッドシートに入ります
- カレンダーへの書き込み権限は要求しません（読み取りのみ）

当社のサーバーが受け取るのは、**通知するかどうかを決めるために必要な最小限**だけです。

| 当社が受け取るもの | 当社が受け取らないもの |
| --- | --- |
| 予定の開始時刻 | **予定名** |
| あなたの出欠（参加／辞退など） | **説明・場所・添付** |
| 終日かどうか・削除されたか | **参加者・メールアドレス** |
| 予定を見分けるための符号（※） | **カレンダーの ID・予定の ID そのもの** |

※ 予定の ID を、あなたのシートの中だけにある鍵で変換した値です。
**当社側では元の予定に戻せません。** 同じ会議に出ている別の方の値とも一致しません。

> 「送らないように気をつける」ではなく、**当社のサーバーが上の表以外の項目を
> 含む要求を受け取らずに拒否する**作りにしています。

### 動作する環境

| | |
| --- | --- |
| 対応ブラウザ | パソコンの Google Chrome / Microsoft Edge / Mozilla Firefox（いずれも最新版） |
| 対象外 | iPhone / iPad / Safari（現時点では通知の仕組みが異なるため未対応） |
| 必要なもの | Googleアカウント（会社のものでも個人のものでも構いません） |

### 準備するもの

- 録音アプリの画面（`https://tsam-ai.com/production-app/voice-recorder/`）
- TSAM AI のログイン（**ご契約が有効なアカウント**）

> **ご契約が確認できないと通知は出ません。** 設定そのものは進められますので、
> あとからご契約いただければ、やり直しなしで通知が始まります。

## 1. 通知用シートをコピーする

1. 録音アプリを開き、TSAM AI にログインします。
2. 下のほうにある **「Googleカレンダー連携（通知）」** を開きます。
3. **［通知をセットアップ］** を押します。新しいタブでコピー画面が開きます。

   <!-- 撮影指示: 録音アプリの「Googleカレンダー連携（通知）」パネル全体。
        ［通知をセットアップ］ボタンが見えること。 -->
   > **［スクリーンショット①］** 録音アプリの「Googleカレンダー連携（通知）」パネル

4. **「コピーを作成」** を押します。あなたのドライブにシートができます。

> このボタンを押した時点で、あなた専用のライセンスが用意されます。
> **控える必要はありません。** 最後の手順で自動的に引き渡されます。

## 2. 承認する

コピーしたシートを開くと、上部に **「録音通知」** というメニューが増えています。

1. **「録音通知」→「セットアップを開く」** を押します。
   右側にセットアップの画面（サイドバー）が開きます。
2. サイドバーの **［セットアップを実行］** を押します。
3. Googleの承認画面が出ます。アカウントを選んで進みます。

### 「このアプリは Google で確認されていません」と出たとき

**これは正常です。** あなたがコピーしたスクリプトを、あなた自身が承認する操作だからです。
一般に公開されているアプリではないため、Googleの審査を受けていません。

<!-- 撮影指示: 「このアプリはGoogleで確認されていません」の警告画面。
     「詳細」を展開して、「（プロジェクト名）に移動」のリンクが見える状態で撮る。 -->
> **［スクリーンショット②］** 「このアプリは Google で確認されていません」の画面

1. 左下の **「詳細」** を押します
2. 下に出る **「（プロジェクト名）に移動（安全ではないページ）」** を押します
3. 求められる権限を確認して **「許可」** を押します

求められる権限は次の7つだけです。これ以外は要求しません。

| 権限 | 何のためか |
| --- | --- |
| カレンダーの予定を**読み取る** | 通知する予定を調べるため（**書き込みはできません**） |
| 外部サービスへの接続 | 通知を送るため |
| トリガーの管理 | 1分ごとの定期実行のため |
| **このスプレッドシートのみ** | 設定と記録の保存のため（他のファイルは開けません） |
| 画面の表示 | このサイドバーとメニューのため |
| プロジェクトの管理 | **次の手順の「公開」を自動で行うため** |
| デプロイの管理 | 同上 |

> 最後の2つは V2 で増えました。**あなたのデータへ届く範囲は増えていません。**
> 「このスクリプト自身を公開する」ためだけに使います。以前は公開の操作を
> 手作業でお願いしていた部分で、間違えやすい工程を1つ減らすためのものです。

## 3. 公開する

承認が終わると、サイドバーが **「公開します」** に変わります。

1. **［🚀 公開する］** を押します。

### 「あと1回だけ、設定の許可が要ります」と出たとき

**初回だけ出ます。** Google 側で「Apps Script API」がオフになっているためです。

<!-- 撮影指示: サイドバーの「あと1回だけ、設定の許可が要ります」の画面。
     ［設定ページを開く］ボタンが見えること。 -->
> **［スクリーンショット③］** Apps Script API の許可を促す画面

1. **［設定ページを開く］** を押します
2. 開いたページで **「Google Apps Script API」をオン**にします
3. **サイドバーへ戻ります。何も押さなくて構いません。**
   数秒で自動的に次へ進みます

> 5分たっても進まない場合は、サイドバーが公開ボタンの画面に戻ります。
> もう一度［🚀 公開する］を押してください。

### うまく公開できないとき

サイドバーの下にある **「うまくいかないときは（手動で公開する）」** を開くと、
Google の画面から手で公開する手順が出ます。**自動化が失敗しても先へ進めます。**

## 4. 録音アプリで仕上げる

公開できると、サイドバーが **「最後に、録音アプリで仕上げます」** に変わります。

1. **［📱 録音アプリで仕上げる］** を押します
2. 録音アプリのタブが開き、**「通知の設定が完了しました」** と表示されます

<!-- 撮影指示: サイドバーの「録音アプリで仕上げる」画面と、

> **［スクリーンショット④］** 引き継ぎの画面

これで接続とライセンスの受け渡しが終わります。**貼り付ける作業はありません。**

> **このリンクには接続キーが含まれます。** 他の方へ転送しないでください。
> 開いた直後にアドレスバーから自動で消えます。
> あとから取り直したいときは、シートのメニュー「録音通知」→
> **「録音アプリへの引き継ぎリンクを表示」** で表示できます。

## 5. 通知を許可する

「ブラウザの通知許可」の行にある **［許可する］** を押し、
ブラウザが出す確認に **「許可」** と答えます。

そのあと **［接続テスト］** を押して、6つの項目がすべて ○ になれば設定は完了です。

| 項目 | ○ の意味 |
| --- | --- |
| GASへの接続 | 接続先が正しく、公開されている |
| 通知の鍵 | 通知を送るための鍵を受け取れている |
| ブラウザの通知許可 | このブラウザが通知を出せる |
| この端末の登録 | この端末が通知の宛先として登録された |
| 通知用シートの定期実行 | 1分ごとの処理が動いている |
| **ご契約（通知の利用）** | **ご契約が確認できている** |

<!-- 撮影指示: 6項目すべてが ○ になった状態のチェッカー部分。 -->
> **［スクリーンショット⑤］** すべて ○ になった状態

### 「ご契約」の表示について

| 表示 | 意味 | すること |
| --- | --- | --- |
| ご利用いただけます | 正常です | ― |
| 確認中（利用は継続しています） | 契約の確認に一時的に失敗しています。**通知は続きます** | 時間をおいて［接続テスト］ |
| ご契約を確認できません | 通知を停止しています | 表示されるリンクからご契約をご確認ください |
| 未確認 | まだ一度も確認していません | 5分ほど待つか［接続テスト］ |

> ご契約の状態が反映されるまで**最長6時間**かかります。
> 解約された場合も、この時間内に通知が止まります。

## 6. 通知する予定を選ぶ

同じパネルの下で、どの予定を通知するかを決めます。

| 項目 | 初期設定 | 説明 |
| --- | --- | --- |
| 参加予定 | ON | 出席すると回答した予定 |
| 仮参加 | ON | 「未定」で回答した予定 |
| 未回答 | ON | まだ回答していない予定 |
| **辞退** | **OFF** | 欠席すると回答した予定 |
| 時間指定の予定のみ通知する | ON | ONだと終日予定には通知しません |
| 通知タイミング | 5分前 | 開始時刻 / 5分前 / 10分前 / 15分前 |

変更したら **［設定を保存］** を押します。
「次回の判定から反映されます」と出れば保存できています。

> 予定の読み直しは5分ごとです。設定を変えた直後の予定には間に合わないことがあります。
> **［接続テスト］を押すと、その場で読み直します。**

## 7. 届く予定を確かめる

設定の下に **「次に届く通知」** が出ます。24時間以内に届く予定が最大5件並びます。

- 予定が並んでいれば、設定が効いています
- **［テスト通知を送る］** を押すと、すぐに1件届いて動作を確かめられます
  （テスト通知は1日1回までです）

<!-- 撮影指示: 「次に届く通知」に1〜2件並んでいる状態と、［テスト通知を送る］ボタン。 -->
> **［スクリーンショット⑥］** 「次に届く通知」

## 8. 動作確認

テスト用に、**通知タイミング＋2分後**が開始時刻になる予定をカレンダーへ作って確かめます。
（通知タイミングが「5分前」なら、いまから7分後に始まる予定を作ります。）

| # | 作る予定 | 期待する結果 |
| --- | --- | --- |
| 1 | 自分が**出席**で回答した、時間指定の予定 | 通知が出る |
| 2 | 自分が**欠席**で回答した予定 | 通知が出ない |
| 3 | まだ**回答していない**予定 | 通知が出る |
| 4 | **終日**の予定 | 通知が出ない |

さらに次の3つも確かめてください。

5. **通知をクリックする** → 録音アプリが開き、画面上部に
   「対象: （予定名）（10:00開始）」と出る。**録音は始まらない**
6. **録音アプリのタブを閉じた状態**で通知が届く（詳しくは次の §9）
7. **通知を受け取った予定を1時間ずらす** → もう一度通知が届く

> **7 は V2 で変わった点です。** 以前は、いちど通知した予定を動かしても
> 二度目の通知が出ませんでした。いまは**開始時刻が5分以上動いたときだけ**
> 出し直します（1〜2分の微調整では鳴りません）。

> 通知の時刻は、目標から**最大1分半ほど**ずれることがあります。
> Google側の定期実行が1分ごとに動く仕組みのためで、異常ではありません。

## 9. ブラウザを閉じているときの通知

パソコンの通知は「ブラウザがどこまで動いているか」で結果が変わります。
ここだけは仕組み上どうにもならない部分があるので、先に把握しておいてください。

| ブラウザの状態 | 通知 |
| --- | --- |
| 録音アプリのタブを開いている | 届く |
| **タブを閉じている**（ブラウザは起動中） | **届く** |
| ブラウザのウィンドウを全部閉じた（プロセスは常駐） | 届く |
| **ブラウザのプロセスが完全に終了している** | **その時点では届かない**（下記） |
| パソコンの電源が切れている / スリープ | その時点では届かない（下記） |

タブを閉じていても届くのは、通知を受け取る小さなプログラム
（Service Worker）がブラウザ側で動いているためです。
録音アプリを開いておく必要はありません。

### 届かなかった通知はどうなるか

**通知は最大5分だけ預けられます。** ブラウザが受け取れる状態に戻ったとき、

- **通知予定時刻から5分以内**なら、そこで届きます
- **5分を過ぎた分は破棄されます**（あとからまとめて届くことはありません）

これは意図的な設計です（送信時に `TTL: 300` 秒を指定しています）。
「10:55に知らせてほしい」という通知が12時に届いても、会議はもう始まっており、
役に立たないどころか混乱のもとになります。**遅れて届くくらいなら届かないほうがよい**、
という判断で5分にしています。

### 確実に受け取りたい場合の運用

**パソコンの起動と同時にブラウザも起動しておく**のが、いちばん確実です。

**Windows（Chrome / Edge）**

1. `Windows` キー + `R` を押し、`shell:startup` と入力して `Enter`
2. 開いたフォルダに、デスクトップの Chrome（または Edge）のショートカットを
   コピーして置きます
3. 次回のサインインから、自動で起動するようになります

あわせて、ブラウザ側も設定しておくと取りこぼしが減ります。

- **Chrome**: 設定 →「システム」→
  **「Google Chrome を閉じた際にバックグラウンド アプリの処理を続行する」を ON**
  （ウィンドウを閉じてもプロセスが残り、通知を受け取り続けます）
- **Chrome / Edge**: 設定 →「起動時」→「特定のページを開く」に
  録音アプリのURLを追加しておくと、起動直後から通知の準備が整います

**macOS（Chrome）**

- Dock の Chrome アイコンを右クリック →「オプション」→
  **「ログイン時に開く」** にチェック

> スリープからの復帰後も同じです。復帰した時点で、通知予定時刻から5分以内の分だけが届きます。
> 長時間の離席が分かっている場合は、この通知だけに頼らず、
> カレンダー側の通知も併用してください。

## 10. うまくいかないとき

### 通知が届かない

| 確かめること | 対処 |
| --- | --- |
| 「接続テスト」の6項目 | × の行に対処法が出ます。上から順に直してください |
| **「ご契約」が ×** | ご契約の状態をご確認ください。反映には最長6時間かかります |
| 「通知用シートの定期実行」が × | シートのサイドバーで［セットアップを実行］をもう一度押します |
| 予定の条件 | 「7. 通知する予定を選ぶ」の設定と、実際の予定の出欠が合っているか |
| 予定に自分が入っているか | 他の人のカレンダーから流れてきただけの予定は通知しません |
| 通知タイミング | 予定の開始が「通知タイミング」より近いと、その予定には間に合いません |
| OSの通知設定 | Windows の「集中モード」、macOS の「集中モード」がONだと表示されません |
| ブラウザが起動していたか | 完全に終了していた時間帯の通知は、5分を過ぎると破棄されます（§9） |

### 「この端末の登録」が × のまま

ブラウザの通知が**ブロック**になっている可能性があります。
アドレスバーの左のアイコンから、このサイトの通知を「許可」に変えてください。
一度ブロックすると、ページ側からは再度お願いできません。

### 「予定の通知」という中身のない通知が出る

通知の中身を取りに行けなかったときの表示です。
［接続テスト］を押して、接続が切れていないか確かめてください。
接続を解除したまま放置すると、この表示が続きます。

> **2台目以降の端末でこれが続く場合**は、以前の版の不具合です（V2 で解消しました）。
> シートが古い版のままになっていないかご確認ください。

### ［公開する］で「設定の許可が要ります」から進まない

Google 側の「Apps Script API」がオフのままです。§3 の手順でオンにしてください。
5分たっても進まないときは、サイドバーが公開ボタンの画面に戻るので、
もう一度［🚀 公開する］を押してください。

それでも進まない場合は、サイドバー下部の
**「うまくいかないときは（手動で公開する）」** から手で公開できます。

### 設定した接続情報が、ページを再読み込みすると元に戻る

**この版（2026-08-11 より前）の不具合です。** 手動で入力した接続先と接続キーが
保存されず、画面には前の値が復活していました。

見分け方: 「接続の設定」へ入力 →［接続する］→ ページを再読み込み。
入力した値が消えていれば、この不具合の版です。

対処: 録音アプリを**再読み込み**（`Ctrl` + `Shift` + `R`）して最新版にしてください。
それでも直らない場合は、通知用シートを作り直してください（§10 の最後）。

### 「通知の鍵」が × のまま直らない

「ご契約の情報がまだ通知用シートへ渡っていません」と出ている場合は、
**［接続テスト］をもう一度押してください。** 押すたびに引き渡しをやり直します。

それでも変わらないときは、いったん［接続を解除］してから、
シートのメニュー「録音通知」→「録音アプリへの引き継ぎリンクを表示」で
接続し直してください。

### 「別のデプロイに接続しています」と出る

シートが公開したURLと、この端末が繋いでいる先が**食い違っています**。
以前のセットアップで保存された古いURLが残っているときに出ます。

シートのメニュー「録音通知」→「録音アプリへの引き継ぎリンクを表示」から
接続し直してください。

### 「古い版に接続しています」と出る

繋いでいる先が、古いスクリプトのままです。
シートのサイドバーで **［公開する］をやり直して**ください。
そのあと引き継ぎリンクを取り直します。

### 引き継ぎリンクを開いても「確認できませんでした」と出る

リンクが途中で切れているか、書き換えられています。
シートのメニュー「録音通知」→
**「録音アプリへの引き継ぎリンクを表示」** で取り直してください。

> **リンクの一部だけを貼り付けると失敗します。** 全体をコピーしてください。

### 「セットアップを開く」でサイドバーが開かず、権限のエラーが出る

次のようなメッセージが出た場合、`appsscript.json` が古い版のままです。

```
Exception: 指定された権限では Ui.showSidebar を呼び出すことができません。
必要な権限: https://www.googleapis.com/auth/script.container.ui
```

画面（メニューとサイドバー）を出すための権限が足りていません。次の順で直します。

1. スプレッドシートの「拡張機能」→「Apps Script」を開きます
2. 左の **`appsscript.json`** を開きます
   （見当たらない場合は、左下の歯車「プロジェクトの設定」で
   「`appsscript.json` マニフェスト ファイルをエディタで表示する」を ON にします）
3. `oauthScopes` の一覧に、次の1行が入っているか確かめます。無ければ足して保存します

   ```
   "https://www.googleapis.com/auth/script.container.ui"
   ```

4. **スプレッドシートのタブを再読み込み**します（メニューが作り直されます）
5. もう一度「録音通知」→「セットアップを開く」→［セットアップを実行］を押します
6. **承認画面がもう一度出ます。** 権限が増えたためで、正常です。
   「2. 承認する」と同じ手順で許可してください

> **あなたのデータへ届く範囲は変わりません。**
> 追加した権限は「このスプレッドシートに画面を出してよい」というもので、
> カレンダーやドライブの見える範囲は増えません。

### 承認のときにエラーが出る

- **「スクリプト関数が見つかりません」** … シートを開き直して、
  メニュー「録音通知」から実行してください。

> 以前の版にあった署名ライブラリ（jsrsasign）の貼り付けは、**V2 で不要になりました。**
> `navigator is not defined` のエラーも出なくなっています。

### 通知が2回届く / 古い通知が出る

通知タイミングを変えた直後は、切り替わりの1回だけ両方が届くことがあります。
その後は新しいタイミングだけになります。

### 接続キーを作り直したい（他の方へ渡してしまったとき）

シートのメニュー「録音通知」→「録音アプリへの引き継ぎリンクを表示」で
表示されるリンクを、**他の方へ渡してしまった場合**の対処です。

録音アプリの「接続の設定（うまくいかないとき）」を開き、
［接続を解除］→ もう一度シートから引き継ぎリンクを開き直してください。
**古いリンクはその時点で使えなくなります。**

### 通知用シートを作り直したい

設定がどうしても直らないときは、作り直すのがいちばん早いです。

1. 録音アプリの「接続の設定（うまくいかないとき）」で［接続を解除］
2. 古い通知用シートを開き、**「拡張機能」→「Apps Script」→ 左の「トリガー」**から
   `tick` のトリガーを削除する（残すと、動かないまま毎分実行され続けます）
3. 古いシートをゴミ箱へ入れる
4. 録音アプリで［通知をセットアップ］から、§1 をやり直す

> **古いシートを消さずに新しいものを作ると、両方が動きます。**
> 同じ予定の通知が2回届く原因になるので、トリガーの削除は必ず行ってください。

### 通知をやめたい

録音アプリの「接続の設定（うまくいかないとき）」で **［接続を解除］** を押します。
完全に止める場合は、コピーしたスプレッドシートごと削除してください。

## 11. いまの制約

- **iPhone / iPad / Safari は対象外**です。
- 通知の時刻は目標から最大1分半ほどずれます。
- **ブラウザが動いていない間の通知は、5分を過ぎると破棄されます**（§9）。
  電源が切れている・スリープしている場合も同じです。
- 仕組みを更新した場合は、**シートをコピーし直していただく必要があります**。
  更新のご案内は別途行います。
- 通知が届く先は「設定したブラウザ」です。別のパソコンでも受け取るには、
  そのパソコンで **§4 の引き継ぎリンク**を開いてください
  （シートのコピーは1つで足ります）。**2台以上でも、それぞれに予定名入りの通知が届きます。**
- **ご契約が確認できないと通知は出ません。** 反映には最長6時間かかります。
