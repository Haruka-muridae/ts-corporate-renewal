# ブラウザ録音アプリ｜Googleカレンダー通知のセットアップ

作成: 2026年8月9日

予定が始まる少し前に、パソコンへ「そろそろ始まります。録音しますか？」という
通知を出すための設定手順です。10〜15分ほどで終わります。

> **通知から録音が自動で始まることはありません。**
> 通知はお知らせだけで、録音は今までどおり「録音開始」ボタンを押したときにだけ始まります。

---

## 0. はじめに

### この仕組みについて

通知は、**あなたのGoogleアカウントの中だけ**で作られます。
当社のサーバーは、あなたのカレンダーにも予定の内容にも一切触れません。

- 予定の読み取りも、通知の送信も、あなたのアカウント内のプログラムが行います
- 設定・通知の記録は、あなたのGoogleドライブにあるスプレッドシートに入ります
- カレンダーへの書き込み権限は要求しません（読み取りのみ）

### 動作する環境

| | |
| --- | --- |
| 対応ブラウザ | パソコンの Google Chrome / Microsoft Edge / Mozilla Firefox（いずれも最新版） |
| 対象外 | iPhone / iPad / Safari（現時点では通知の仕組みが異なるため未対応） |
| 必要なもの | Googleアカウント（会社のものでも個人のものでも構いません） |

### 準備するもの

- 録音アプリの画面（`https://tsam-ai.com/production-app/voice-recorder/`）
- 同じブラウザで開いた Google スプレッドシート

---

## 1. 通知用シートをコピーする

1. 録音アプリを開き、TSAM AI にログインします。
2. 下のほうにある **「Googleカレンダー連携（通知）」** を開きます。
3. 「接続の設定」の中の **「通知用シートをコピー」** を押します。
   新しいタブでコピー画面が開きます。

   <!-- 撮影指示: 録音アプリの「Googleカレンダー連携（通知）」パネル全体。
        「接続の設定」を開いた状態で、「通知用シートをコピー」のリンクが見えること。 -->
   > **［スクリーンショット①］** 録音アプリの「Googleカレンダー連携（通知）」パネル

4. **「コピーを作成」** を押します。あなたのドライブにシートができます。

> コピーのURLは録音アプリの画面から開いてください。
> この文書にはURLを書きません（コピー先が変わったときに、古いURLが残るのを避けるためです）。

---

## 2. 承認する

コピーしたシートを開くと、上部に **「録音通知」** というメニューが増えています。

1. **「録音通知」→「セットアップを開始」** を押します。
   右側にセットアップの画面（サイドバー）が開きます。
2. サイドバーの **「セットアップを実行」** を押します。
3. Googleの承認画面が出ます。アカウントを選んで進みます。

### 「このアプリは Google で確認されていません」と出たとき

**これは正常です。** あなたがコピーしたスクリプトを、あなた自身が承認する操作だからです。
一般に公開されているアプリではないため、Googleの審査を受けていません。

<!-- 撮影指示: 「このアプリはGoogleで確認されていません」の警告画面。
     「詳細」を展開して、「（プロジェクト名）に移動」のリンクが見える状態で撮る。 -->
> **［スクリーンショット②］** 「このアプリは Google で確認されていません」の画面

1. 左下の **「詳細」** を押します
2. 下に出る **「（プロジェクト名）に移動（安全ではないページ）」** を押します
3. 求められる権限を確認して **「許可」** を押します

求められる権限は次の5つだけです。これ以外は要求しません。

| 権限 | 何に使うか |
| --- | --- |
| Googleカレンダーの予定を**表示する** | 通知する予定を探すため。**変更・削除はできません** |
| 外部サービスへの接続 | 通知（Web Push）を送るため |
| トリガーの管理 | 1分ごとの定期実行を作るため |
| **このスプレッドシートのみ**の編集 | 設定と通知の記録を保存するため。**他のファイルは開けません** |
| このスプレッドシートへの画面表示 | メニューとセットアップ画面を出すため。**データには触りません** |

---

## 3. セットアップを実行する

承認が終わると、サイドバーの「セットアップを実行」がもう一度押せる状態になります。

押すと、次の4つが用意されます。**何度押しても同じ結果になります**（二重に作られません）。

- 4つのシート（`settings` / `subscriptions` / `notify_queue` / `sent_log`）
- 通知用の鍵
- 接続キー
- 1分ごとの定期実行（トリガー）

サイドバー上部の一覧が ○ になっていることを確認します。
この時点で「ウェブアプリの公開」だけが × のままです。次で公開します。

<!-- 撮影指示: サイドバー上部の状態一覧。「ウェブアプリの公開」だけが × の状態。 -->
> **［スクリーンショット③］** セットアップ実行後のサイドバー

---

## 4. 公開（デプロイ）する

この操作だけはGoogleの画面で行います。

1. スプレッドシートの **「拡張機能」→「Apps Script」** を開きます
2. 右上の **「デプロイ」→「新しいデプロイ」** を押します
3. 歯車アイコンから **種類「ウェブアプリ」** を選びます
4. 次のように設定します

   | 項目 | 選ぶもの |
   | --- | --- |
   | 次のユーザーとして実行 | **自分** |
   | アクセスできるユーザー | **全員** |

5. **「デプロイ」** を押します

<!-- 撮影指示: 「新しいデプロイ」ダイアログ。種類・実行ユーザー・アクセス権の3か所が見えること。
     発行されたURLは写さない（URLは利用者ごとに異なり、実物を載せる意味がない）。 -->
> **［スクリーンショット④］** ウェブアプリのデプロイ設定

> **「アクセスできるユーザー: 全員」で大丈夫なのか？**
> URLを知っていれば誰でも「接続できるか」だけは確認できますが、
> **予定の内容を読むには接続キーが必要**です。接続キーはあなたのスクリプトの中にだけあり、
> 第三者には分かりません。この設定にしているのは、通知を受け取るブラウザの裏側の仕組み
> （Service Worker）がログイン状態を持てないためです。

---

## 5. 接続コードを録音アプリへ貼る

1. スプレッドシートへ戻り、**「録音通知」→「接続コードを表示」** を押します
   （サイドバーの「接続コードを表示」でも同じです）
2. 表示された **GAS の URL** と **接続キー** をコピーします
3. 録音アプリの「Googleカレンダー連携（通知）」→「接続の設定」へ貼り付けます
4. **「接続する」** を押します

> **接続キーは第三者へ渡さないでください。** メールやチャットへの貼り付けも避けてください。
> 万一漏れた場合は、スプレッドシートのApps Scriptエディタで `resetConnectionKey` を実行すると
> 作り直せます（作り直したあとは、この手順をもう一度行ってください）。

---

## 6. 通知を許可する

「ブラウザの通知許可」の行にある **「許可する」** を押し、
ブラウザが出す確認に **「許可」** と答えます。

そのあと **「接続テスト」** を押して、5つの項目がすべて ○ になれば設定は完了です。

| 項目 | ○ の意味 |
| --- | --- |
| GASへの接続 | URLが正しく、公開されている |
| 通知の鍵 | 接続キーが合っていて、鍵が作られている |
| ブラウザの通知許可 | このブラウザが通知を出せる |
| この端末の登録 | この端末が通知の宛先として登録された |
| GAS側の定期実行 | 1分ごとの処理が動いている |

<!-- 撮影指示: 5項目すべてが ○ になった状態のチェッカー部分。 -->
> **［スクリーンショット⑤］** すべて ○ になった状態

---

## 7. 通知する予定を選ぶ

同じパネルの下で、どの予定を通知するかを決めます。

| 項目 | 初期設定 | 説明 |
| --- | --- | --- |
| 参加予定 | ON | 出席すると回答した予定 |
| 仮参加 | ON | 「未定」で回答した予定 |
| 未回答 | ON | まだ回答していない予定 |
| **辞退** | **OFF** | 欠席すると回答した予定 |
| 時間指定の予定のみ通知する | ON | ONだと終日予定には通知しません |
| 通知タイミング | 5分前 | 開始時刻 / 5分前 / 10分前 / 15分前 |

変更したら **「設定を保存」** を押します。
「次回の判定から反映されます」と出れば保存できています。

> 予定の読み直しは5分ごとです。設定を変えた直後の予定には間に合わないことがあります。

---

## 8. 動作確認

テスト用に、**通知タイミング＋2分後**が開始時刻になる予定をカレンダーへ作って確かめます。
（通知タイミングが「5分前」なら、いまから7分後に始まる予定を作ります。）

| # | 作る予定 | 期待する結果 |
| --- | --- | --- |
| 1 | 自分が**出席**で回答した、時間指定の予定 | 通知が出る |
| 2 | 自分が**欠席**で回答した予定 | 通知が出ない |
| 3 | まだ**回答していない**予定 | 通知が出る |
| 4 | **終日**の予定 | 通知が出ない |

さらに次の2つも確かめてください。

5. **通知をクリックする** → 録音アプリが開き、画面上部に
   「対象: （予定名）（10:00開始）」と出る。**録音は始まらない**
6. **録音アプリのタブを閉じた状態**で通知が届く
   （ブラウザ自体も閉じた状態で受け取るには、Chrome の設定
   「Google Chrome を閉じた際にバックグラウンド アプリの処理を続行する」が
   有効になっている必要があります。無効の場合は、次に起動したときに
   まだ有効な通知だけが届きます）

> 通知の時刻は、目標から**最大1分半ほど**ずれることがあります。
> Google側の定期実行が1分ごとに動く仕組みのためで、異常ではありません。

## 9. うまくいかないとき

### 通知が届かない

| 確かめること | 対処 |
| --- | --- |
| 「接続テスト」の5項目 | × の行に対処法が出ます。上から順に直してください |
| 「GAS側の定期実行」が × | スプレッドシートで「セットアップを実行」をもう一度押します |
| 予定の条件 | 「7. 通知する予定を選ぶ」の設定と、実際の予定の出欠が合っているか |
| 予定に自分が入っているか | 他の人のカレンダーから流れてきただけの予定は通知しません |
| 通知タイミング | 予定の開始が「通知タイミング」より近いと、その予定には間に合いません |
| OSの通知設定 | Windows の「集中モード」、macOS の「集中モード」がONだと表示されません |

### 「この端末の登録」が × のまま

ブラウザの通知が**ブロック**になっている可能性があります。
アドレスバーの左のアイコンから、このサイトの通知を「許可」に変えてください。
一度ブロックすると、ページ側からは再度お願いできません。

### 「予定の通知」という中身のない通知が出る

通知の中身をGASから取りに行けなかったときの表示です。
「接続テスト」を押して、接続が切れていないか確かめてください。
接続を解除したまま放置すると、この表示が続きます。

### 「セットアップを開始」でサイドバーが開かず、権限のエラーが出る

次のようなメッセージが出た場合、`appsscript.json` が古い版のままです。

```
Exception: 指定された権限では Ui.showSidebar を呼び出すことができません。
必要な権限: https://www.googleapis.com/auth/script.container.ui
```

画面（メニューとサイドバー）を出すための権限が足りていません。次の順で直します。

1. スプレッドシートの「拡張機能」→「Apps Script」を開きます
2. 左の **`appsscript.json`** を開きます
   （見当たらない場合は、左下の歯車「プロジェクトの設定」で
   「`appsscript.json` マニフェスト ファイルをエディタで表示する」を ON にします）
3. `oauthScopes` の一覧に、次の1行が入っているか確かめます。無ければ足して保存します

   ```
   "https://www.googleapis.com/auth/script.container.ui"
   ```

4. **スプレッドシートのタブを再読み込み**します（メニューが作り直されます）
5. もう一度「録音通知」→「セットアップを開始」→「セットアップを実行」を押します
6. **承認画面がもう一度出ます。** 権限が増えたためで、正常です。
   「2. 承認する」と同じ手順で許可してください

> 権限が5つに増えていても、**あなたのデータへ届く範囲は変わりません。**
> 追加した権限は「このスプレッドシートに画面を出してよい」というもので、
> カレンダーやドライブの見える範囲は増えません。

### 承認のときにエラーが出る

- **`navigator is not defined`** … 署名ライブラリ（jsrsasign）の貼り付け位置が違います。
  `lib_jsrsasign.gs` の**冒頭のスタブが、ライブラリ本体より上**にあるか確認してください。
  「録音通知」→「jsrsasign を検証」で確かめられます。
- **「スクリプト関数が見つかりません」** … シートを開き直して、
  メニュー「録音通知」から実行してください。

### 通知が2回届く / 古い通知が出る

通知タイミングを変えた直後は、切り替わりの1回だけ両方が届くことがあります。
その後は新しいタイミングだけになります。

### 接続キーを作り直したい

Apps Script エディタで `resetConnectionKey` を実行し、
新しい接続コードを録音アプリへ貼り直してください。

### 通知をやめたい

録音アプリの「接続の設定」で **「接続を解除」** を押します。
完全に止める場合は、Apps Script エディタの「トリガー」から `tick` のトリガーを削除するか、
コピーしたスプレッドシートごと削除してください。

---

## 10. いまの制約

- **iPhone / iPad / Safari は対象外**です。
- 通知の時刻は目標から最大1分半ほどずれます。
- パソコンの電源が切れている間の通知は届きません（起動後に、まだ有効な分だけ届きます）。
- 仕組みを更新した場合は、**シートをコピーし直していただく必要があります**。
  更新のご案内は別途行います。
- 通知が届く先は「設定したブラウザ」です。別のパソコンでも受け取るには、
  そのパソコンで「5. 接続コードを録音アプリへ貼る」以降をもう一度行ってください
  （シートのコピーは1つで足ります）。
