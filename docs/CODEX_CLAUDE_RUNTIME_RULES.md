# Codex × Claude Code 運用ルール（日次）

## 役割分担

- Codex は**実装しない**。アプリケーションコードの実装・修正は必ず Claude Code に委譲する。
- Codex の役割は Orchestrator 兼 Reviewer。Claude が出した diff・テスト結果・セキュリティ観点をレビューする。

## 往復回数の上限

- 通常の修正依頼：同一タスクにつき最大 **3 往復**。超えたら設計から見直す。
- 同じ設計上の問題が解決しない場合：最大 **2 往復**まで。それでも収束しなければ **Human Escalation**（人間に判断を仰ぐ）し、Codex 側で結論を出さない。

## Secret・push・デプロイ

- APIキー・トークン等の Secret は Claude Code や外部プロセスに渡さない。
- `git push` は行わない。
- 本番デプロイは行わない。

## モデル選択

- 実装のデフォルトは **Sonnet**。
- 複雑な設計判断・セキュリティレビュー・最終レビューは **Opus**。
- 長時間の自律作業・高複雑度タスクは **Fable**、軽量な読み取り専用・整形作業は **Haiku** を使ってよいが、これは CLI・アカウント側の対応を確認し、ラッパーの `ValidateSet` を更新した後に限る。現時点の kit は `sonnet` / `opus` のみサポート。
