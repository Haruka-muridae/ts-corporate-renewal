## 1. MVPの方針

本書は、要件定義書 v0.1 をもとに、最小限の構成で価値検証を行うためのMVP（Minimum Viable Product）の要件を定義する。

MVPで検証すること：

「ポータルから開いたブラウザ画面だけで最長90分の録音を行い、MP3としてGoogle Driveの指定フォルダに確実に保存できる」という中核体験が成立するか。

実装は、フロントエンドをClaude Codeにより一気通貫で作成することを前提とし、本書はその実装指示の基礎資料を兼ねる。

## 2. MVPスコープ

### 2.1 含むもの（Must）

1. TSAM AIポータル経由のアクセス制御（ポータル外からの直接利用の遮断）
2. Google OAuth 2.0によるアカウント連携（最小権限スコープ、トークンはブラウザのメモリ上のみ）
3. ブラウザ上での録音開始・停止、録音経過時間の表示（上限90分）
4. 録音後のプレビュー再生と録音破棄（再録音）
5. ブラウザ内でのMP3逐次変換（モノラル・128kbps）
6. ファイル名の自動生成と編集（`YYYYMMDD_HHmmss_録音.mp3`、同名時は連番付与）
7. 保存先フォルダ（`マイドライブ ＞ TSAM AI ＞ Voice Recorder`）へのアップロード（名前から解決し、無ければ作成）
8. アップロード進捗表示・保存完了表示（ファイル名、Google Driveリンク）
9. 保存完了後の一時録音データ削除（端末内ストレージ）
10. 主要エラーの表示（未連携／認証切れ／マイク未許可・未検出／録音失敗／通信切断／アップロード失敗／権限不足／空き容量不足／ブラウザ非対応）
11. 認証期限切れ時の再認証導線

### 2.2 含まないもの（MVPでは対象外）

* 文字起こし・要約・AI分析
* 音声編集（カット・結合）、複数マイク、バックグラウンド録音、録音予約
* 録音一覧・履歴管理、データベース管理、自動分類
* 共有設定変更、既存ファイルの削除・移動
* 利用者によるフォルダ選択UI（保存先は固定）
* 異常終了した録音の復旧（フラッシュ前のMP3が再生できる保証がなく、「復旧可能」と表示して過度な期待を与えないため）
* スマートフォン対応（動作すれば可だが保証しない）
* Chrome以外のブラウザの動作保証（Edge/Safariは後続で検証）
* 通信切断時のローカル退避・自動リトライ（手動再試行のみ）
* Google Driveカスタムプロパティ等の追加メタデータ

## 3. ユーザーと利用環境

* 対象ユーザー：TSAM AIポータルにログインでき、Googleアカウントを持つ関係者（少人数の限定ユーザー）
* アクセス経路：TSAM AIポータルからのみ。録音アプリのURLへ直接アクセスした場合、未認証であれば利用できない
* 対応環境：PC版 Google Chrome 最新版のみ動作保証
* 前提：マイク接続済み、インターネット接続あり、Googleアカウント保有

## 4. システム構成の概要

```
[ブラウザ（ポータル内 録音画面）]
   ├ ポータル認証の検証（セッショントークンをサーバーで確認）
   ├ 録音（getUserMedia → AudioContext → AudioWorklet でPCM取得）
   ├ MP3逐次変換（Worker + lamejs：モノラル・128kbps）
   ├ 端末内ストレージ（OPFS）へ逐次追記
   ├ プレビュー再生
   └ Google OAuth 2.0（トークンモデル：メモリ上のみ）
   ▼
[Google Drive API v3（resumable upload）]
   ▼
[Google Drive：マイドライブ ＞ TSAM AI ＞ Voice Recorder]
```

録音・変換・一時保存・プレビューはすべて端末内で完結し、当社のサーバーを音声が経由しない。保存操作時にかぎり、MP3が利用者自身のGoogle Driveへ直接送信される。

v1.1は「90分録音のブラウザ内変換はメモリ・処理時間のリスクが大きい」としてサーバー側変換を方式としていたが、録音全体をメモリに保持しない逐次エンコード方式によりこのリスクは解消できるため、ブラウザ内変換をMVPの方式とする（§14）。

## 5. 機能要件（MVP）

### FR-01 ポータル経由アクセス制御

* 録音画面は、TSAM AIポータルの認証を通過した利用者のみ利用できること。
* 画面の描画前にセッショントークンをサーバー（Apps Script）で検証し、検証が完了するまで保護対象の内容を描画しないこと。通信できなかった場合も画面に入れないこと。
* 認証されていない状態で録音画面のURLへ直接アクセスした場合は、ポータルのログインへ誘導すること。
* 本アプリはポータルと同一オリジンから配信するため、CORS設定は行わない。

> **このガードで守れるものと守れないもの**
>
> 静的配信であるため、HTMLとJSファイルそのものの取得は防げない。URLを直接叩けば、未認証でもファイルは取得できる。したがってこのガードは「画面に入れない」ための制御であって、機密の保護ではない。
>
> 実質的なアクセス制御はGoogle OAuthが担う。Driveのデータに触れるには利用者本人がGoogleの同意画面で許可する必要があり、許可されない限り保存先フォルダにもファイルにも到達できない。
>
> v1.1の「APIが全エンドポイントで検証し401/403を返す」要件は、該当するAPIが存在しないため成立しない（§6・§14）。

### FR-02 Google連携

* Google OAuth 2.0（Google Identity Services のトークンモデル）で認証する。要求スコープは `drive.file`（本アプリが作成したファイルのみ操作可能）に限定する。増やさないこと。
* OAuthのアクセストークンはブラウザのメモリ上でのみ保持し、localStorage / sessionStorage / Cookie / URL / ログ / 外部送信のいずれにも残さない。ページを再読み込みすれば消え、再認可が必要になる（意図した挙動）。
* リフレッシュトークンは受け取らない（暗黙フローでは発行されない）。client secret も使わない。
* 連携中のGoogleアカウント（メールアドレス）を画面に表示する。
* トークン期限切れ時は再認証を促し、再認証後に保存操作をやり直せる。
* アプリを開いただけでは認可を要求しない。利用者が「連携する」または保存を押した時点で要求する。

### FR-03 保存先

* 保存先は「マイドライブ ＞ TSAM AI ＞ Voice Recorder」とし、フォルダIDを固定登録しない。毎回「名前と親の関係」から解決し、無ければ作成する。
  * フォルダIDは利用者ごとに異なるため、固定値では他の利用者のドライブで必ず失敗する。
  * `drive.file` スコープでは、アプリが作成していないフォルダへは書き込めない。
* このフォルダ名は音声文字起こしアプリも読みに来る。片方だけ変更しないこと。
* 画面には保存先フォルダ名「マイドライブ ＞ TSAM AI ＞ Voice Recorder」を表示する。
* フォルダを作成できない、または書き込めない場合は保存を中止しエラー表示する。

### FR-04 録音

* 録音開始前にブラウザのマイク許可を取得する。拒否時は設定確認を促す。
* 使用マイクはOS/ブラウザの標準デバイスとする。
* 「録音開始」で録音を開始し、録音中表示と経過時間（hh:mm:ss）を表示する。録音中は開始ボタンを無効化する。
* 「録音停止」で録音を終了し、プレビュー可能な状態にする。
* 録音上限は90分（1時間30分）とし、上限到達時は自動停止して通知する。残り時間が5分になった時点で画面上に予告表示する。
* 録音データはブラウザのメモリを圧迫しないよう、約0.2秒ごとのPCMをWorkerへ渡し、1152サンプル単位でMP3化して端末内ストレージ（OPFS）へ追記する。録音全体のPCMもMP3もメモリに保持しない。
* 対応サンプルレートは 44,100Hz / 48,000Hz のみとし、規格外の場合は録音を開始せずOS設定の変更を案内する（MVPではリサンプリングしない）。
* 録音開始前に端末の空き容量を確認し、250MB未満では開始しない。録音中も定期的に確認し、安全下限（100MB）を割ったら自動停止して確定する。

### FR-05 プレビューと破棄

* 停止後、ブラウザ上で録音内容を再生できる。
* 「破棄」で録音データ（端末内ストレージの一時ファイルを含む）を削除し、再録音できる。

### FR-06 MP3変換（ブラウザ内・逐次）

* ブラウザはAudioWorkletでPCMを取得し、Worker内のlamejsによりMP3（モノラル・128kbps・audio/mpeg）へ録音と同時に変換する。90分の録音で約86MBとなる。
* 停止時にフラッシュして確定し、プレビューと保存に進む。
* 変換は録音と同時に進むため、変換失敗は録音失敗と同義になる。失敗時はエラーを画面に表示し、録音のやり直しを案内する（部分ファイルからの復旧は行わない。§2.2）。

### FR-07 ファイル名

* 初期値：`YYYYMMDD_HHmmss_録音.mp3`（録音開始時刻・ブラウザ日時基準）
* 利用者は保存前に編集できる。未入力時は初期値を使用し、拡張子がなければ `.mp3` を付与する。
* 保存先に同名ファイルがある場合は上書きせず `_2`, `_3`… の連番を付与する（保存前にDriveへ問い合わせて判定）。

### FR-08 保存

* 「Google Driveに保存」ボタンで保存処理を開始する（自動保存はしない）。
* 送信はresumable uploadとし、90分相当（約86MB）のデータでもタイムアウトしないこと。
* 処理中は「保存の準備中」「保存先フォルダの確認中」「アップロード中」「保存の確定中」の段階が分かる進捗表示を出し、保存ボタンを無効化する。v1.1にあった「変換中」の段階は無い（変換は録音時点で完了しているため）。
* 完了時に、完了メッセージ・ファイル名・保存先フォルダ名・DriveファイルURLを表示する。
* 失敗時は再試行ボタンを表示する。録音データは再試行可能な間、端末内ストレージで破棄しない。
* 保存完了後、端末内の一時データを削除し、「新しい録音」または「Driveで開く」を選択できる。
* 異常終了で残った一時ファイルは、次回この画面を開いたときに無条件で自動削除する（24時間の経過待ちはしない）。

## 6. 外部通信の要件

**本MVPにバックエンドAPIは存在しない。**

v1.1 §6 は8本のエンドポイント（`/api/session`、`/api/recordings` ほか）を定義していたが、v1.2で全廃した。現行のホスティングで90分・約86MBの受信とFFmpeg実行が成立しないこと、および逐次エンコード方式によりサーバー側変換の必要が無くなったことによる（§14）。

APIを追加すればこの構成を戻せると考える前に §14 を読むこと。復活させる場合はホスティングの変更（常駐プロセスと永続ディスク）が前提となり、MVPの範囲を超える。

外部との通信は次の2種類のみとする。

| 相手 | 用途 |
|---|---|
| Apps Script（当社の認証系） | セッショントークンの検証（§FR-01） |
| Google（`accounts.google.com` / `www.googleapis.com`） | OAuth認可、Drive API v3（フォルダの解決・作成、resumable upload） |

上記以外への通信を追加しないこと。第三者CDNからのスクリプト読み込みも行わない。

## 7. 画面要件（1画面構成）

配置要素：アプリ名／Google連携ボタン・連携アカウント表示／保存先フォルダ表示／録音開始・停止ボタン／録音状態（録音マーク）・経過時間（hh:mm:ss）／残り時間予告表示／推定ファイルサイズ・端末の空き容量／音声プレビュー／ファイル名入力欄／保存ボタン／破棄ボタン／進捗表示（フォルダ確認・アップロード・確定の段階表示）／保存結果表示／エラーメッセージ表示。

録音データ未保存の状態でページを閉じようとした場合は、離脱警告を表示する。

録音状態を色だけで示さず、「録音中」「待機中」などの文言を必ず併記する。点滅などのアニメーションは `prefers-reduced-motion` に対応する。

## 8. 非機能要件（MVP）

### 8.1 セキュリティ

* 通信はHTTPSのみ
* ポータル認証を通過しないアクセスは画面に入れない（§FR-01。ただし静的ファイルの取得自体は防げない）
* Google認証トークンはブラウザのメモリ上のみで保持し、画面・ログ・外部へ出力しない
* 端末内の一時音声ファイルは保存完了後に削除し、削除失敗に備え次回起動時にクリーンアップを行う
* 保存先以外のGoogle Driveデータを読み取らない（`drive.file` スコープで担保）
* OAuthクライアントIDは公開値であり秘密ではない。実質的な防御はGoogle Cloud側の「承認済みのJavaScript生成元」に本番オリジンと開発オリジンだけを登録することで行う

### 8.2 性能・安定性

* 録音開始操作から2秒以内に録音状態へ移行する
* 90分録音（MP3 約86MB）を安定して録音・変換・保存できること
* 録音データ全体を単一のメモリバッファに保持し続けず、PCMは約0.2秒ぶん、MP3は生成直後に端末内ストレージへ書いて破棄する。メモリ使用量は録音時間に依存せず一定とする
* Workerが追いつかない場合は未処理秒数を監視し、5秒で警告、10秒で安全停止する
* Google Driveへはresumable uploadを使用する
* 90分データのDrive保存の所要時間目安を画面に示す（処理中表示で代替可）

### 8.3 対応ブラウザ

PC版 Google Chrome 最新版のみ動作保証。Edge/Safari/スマートフォンは後続リリースで検証する。

必要なブラウザ機能：`getUserMedia` / `AudioWorklet` / `Web Worker` / OPFS（`navigator.storage.getDirectory`、Worker内 `createSyncAccessHandle`）／`navigator.storage.estimate`。いずれかが欠ける環境では録音を開始せず、不足している機能を画面に表示する。

## 9. エラー要件

v0.1 §10のエラー一覧に以下を追加して適用する。

| エラー | 表示内容の例 |
|---|---|
| ポータル未認証 | TSAM AIポータルからログインしてください |
| ポータルセッション切れ | セッションの有効期限が切れました。ポータルから再度アクセスしてください |
| Google未連携・認可拒否 | Googleドライブとの連携が許可されませんでした。「連携する」を押して、表示される画面で許可してください |
| Google認証切れ | Googleの認証の有効期限が切れました。「連携する」を押して認証しなおすと、保存をやり直せます |
| ブラウザ非対応 | お使いのブラウザではこのアプリを利用できません。パソコンの Google Chrome 最新版でお試しください |
| マイク未許可 | マイクの使用が許可されていません。ブラウザのアドレスバーのアイコンからマイクの使用を許可して、もう一度お試しください |
| マイク未検出 | マイクが見つかりません。マイクを接続してから、もう一度お試しください |
| サンプルレート非対応 | お使いのマイクの設定にこのアプリが対応していません。OSのサウンド設定で44.1kHzまたは48kHzに変更してお試しください |
| 空き容量不足（開始前） | 端末の空き容量が足りないため録音を開始できません。不要なファイルを削除してから、もう一度お試しください |
| 空き容量不足（録音中） | 端末の空き容量が不足したため録音を停止しました。ここまでの録音は保存できます |
| 録音・変換失敗 | 録音の処理に失敗しました。お手数ですが、録音をやり直してください |
| 保存先フォルダの権限不足 | 保存先フォルダを作成または利用できませんでした。Googleドライブの空き容量と権限をご確認ください |
| アップロード失敗 | 保存に失敗しました。録音は残っています。「Google Driveに保存」をもう一度お試しください |
| 通信切断 | 通信が中断しました。録音は残っています。接続を確認して、もう一度保存をお試しください |

各エラーは利用者が次の操作を判断できる文言とする。例外の `message` をそのまま画面へ出さない（英語文が漏れるため）。分岐に使うのはエラーコードだけとする。

## 10. MVPにおける暫定決定事項

| # | 事項 | MVP決定 |
|---|------|---------|
| 1 | マイドライブ／共有ドライブ | マイドライブ（利用者本人のドライブ）。`supportsAllDrives` は使わない |
| 2 | フォルダ特定方法 | 名前から解決し、無ければ作成（フォルダIDの固定登録はしない） |
| 3 | 対象アカウント | 組織アカウントに限定（OAuth同意画面を内部限定に設定） |
| 4 | スマホ対応 | 対象外（保証しない） |
| 5 | 録音時間上限 | 90分（1時間30分）。上限到達で自動停止、残り5分で予告表示 |
| 6 | ファイルサイズ | MP3換算 約86MB（128kbps モノラル × 90分）。自社サーバーの受信上限は存在しない |
| 7 | MP3変換場所 | ブラウザ内（Worker + lamejs による逐次エンコード） |
| 8 | 保存方式 | 手動保存（保存ボタン） |
| 9 | 通信切断時のローカル保持 | 保持する（端末内ストレージに残るため、手動で再試行できる） |
| 10 | ファイル名への会議名等の付与 | 行わない（手動編集で対応） |
| 11 | 保存完了通知 | 画面表示のみ |
| 12 | 追加メタデータ | 設定しない |
| 13 | アクセス経路 | TSAM AIポータル経由のみ（クライアント側ガード。同一オリジン配信のためCORS設定は不要） |
| 14 | 異常終了時の復旧 | 行わない。残った一時ファイルは次回起動時に自動削除する |

## 11. 受入条件（MVP）

1. ポータル経由でのみ録音画面を利用でき、未認証の直接アクセスはログイン画面へ誘導される
2. Google連携ができ、連携アカウントが表示される
3. マイク許可を経て録音開始・停止ができ、経過時間が表示される
4. 90分で自動停止し、残り5分で予告表示される
5. 停止後にプレビュー再生・破棄ができる
6. MP3（モノラル・128kbps）に変換される
7. ファイル名を編集でき、同名時は連番が付与される
8. 「マイドライブ ＞ TSAM AI ＞ Voice Recorder」にMP3が保存され、Drive上で再生できる
9. 保存完了後にファイルURLが表示され、端末内の一時データが削除される
10. 権限不足・通信失敗時に適切なエラーと再試行導線が表示される
11. 5分・30分・90分の録音をそれぞれ正常に保存できる

## 12. 実装体制に関する補足

フロントエンドはClaude Codeによる一気通貫実装を前提とする。本書§5〜§10をそのまま実装指示のインプットとして使用できる。ポータル側の認証方式は `public/auth/session.js` の `guardPage()` に実装済みであり、本アプリはこれを利用する（独自実装は禁止）。

実装は既存資産を複製して用いる。複製元と複製先は独立しており、片方を直しても他方には反映されない。

| 複製元 | 複製先 |
|---|---|
| `public/apps/voice-recorder/`（長時間録音モード） | `public/production-app/voice-recorder/recorder/` |
| `public/production-app/receipt-ocr/oauth.js` | `public/production-app/voice-recorder/oauth.js` |

本番アプリからテスト環境（`public/apps/`）を import しないこと（`docs/repository-structure.md` §1。流用はコピーで行う）。

## 14. 変更履歴

### v1.2（2026年8月5日）— バックエンド廃止とブラウザ完結への変更

v1.1はバックエンドAPI（Node.js + FFmpeg）を前提としていた。実装着手前の調査でこの前提が現行のホスティングでは成立しないことが判明したため、構成を変更した。

**変更の根拠：**

1. **現行ホスティング（Vercel）では成立しない。** 90分の録音はWebM/Opusで20〜80MB、MP3で約86MBになる。この規模の受信、FFmpegバイナリの実行、一時ファイルの永続化、24時間後のクリーンアップは、いずれもVercelの関数では実現できない（リクエストボディ上限・実行時間上限・揮発するファイルシステム）。別ホスティングを新設すれば実現できるが、インフラの新設と運用が発生する。
2. **サーバー側変換を選んだ理由が解消された。** v1.1 §4は「90分録音のブラウザ内変換はメモリ・処理時間のリスクが大きい」としていたが、逐次エンコード方式（AudioWorklet → Worker → OPFS）では録音全体をメモリに保持せず、メモリ使用量は録音時間に依存しない。同方式は既に60分の実績がある。
3. **リポジトリの方針と整合する。** 本リポジトリは外部SDKを追加せず `fetch` でRESTを直接叩く方針をとっており、`package.json` の dependencies を増やさない。ブラウザ完結の構成は追加依存ゼロで成立する。
