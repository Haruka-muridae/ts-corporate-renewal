## §1 結論 — どこに何を載せるか

**2か所に分ける。** 法的な条項と、操作の説明では、性質も更新の仕方も違う。

| | 載せるもの | 場所 | 更新の仕方 |
| --- | --- | --- | --- |
| **A. 利用規約** | 法的な条項（保存先・無料枠の開示） | 既存の `/legal/terms/` | **スプレッドシート「TSAM AI 法務文書」を直し、`publishLegalDocs()` で公開** |
| **B. ヘルプ** | §5.3 の明示事項、削除・連携解除の手順 | **アプリ内に新設**（`/production-app/card-ocr/help/`） | 通常のコード変更（PR） |

### なぜ規約を直接書かないのか

`public/legal/terms/index.html` は**スプレッドシートからの生成物**である。
手で編集しても、次の `publishLegalDocs()` で失われる
（[legal-cms-spec-v1.md](./legal-cms-spec-v1.md) §1-1、CLAUDE.md）。

したがって §2 の条文案は、**スプレッドシートの `terms` シートへ転記して
いただく形**で書いてある。列は `block_id` / `heading` / `body` /
`sort_order` / `enabled` の5つ（同 §2-2）。

### なぜヘルプをアプリ内に置くのか

3つ理由がある。

1. **操作の説明だから。** 「連携を解除するには」「保存したデータを消すには」は
   規約に書くものではない。読むのは困ったときで、そのとき開いているのは
   アプリである
2. **生成物ではないので、実装と一緒に更新できる。** 画面を変えたときに
   ヘルプが古いまま残る、が起きにくい
3. 規約の改定は周知の手続き（第19条）を伴う。**手順の書き換えのたびに
   それを回すのは重い**

### 既存の利用規約でどこまで足りているか

**ほとんど足りている。** 現行の `/legal/terms/` は次を既に定めている。

| 条 | 内容 | 名刺OCRとの関係 |
| --- | --- | --- |
| 第6条 | APIキーの取得及びAIプロバイダーとの契約 | ○ そのまま効く |
| 第7条 | API利用料金及び利用量の管理 | ○ 有料キーの課金はここ |
| 第8条 | AIプロバイダーへのデータ送信 | ○ 第三者の個人情報を送る権限の保証まで書いてある |
| 第9条 | 利用者データ（バックアップは利用者責任） | ○ |
| 第10条 | AI生成結果及び利用判断 | ○ 読み取り誤りの責任はここ |
| 第16・17条 | 保証の否認・責任制限 | ○ |
| 第18条 | 個人情報等の取扱い | ○ |

**足りないのは2点だけ**である。

1. **データが当社を通らないこと。** 既存の条項は「当社が利用者データを
   取り扱う」前提で書かれている。名刺OCRは**当社のサーバーを一切通らず、
   利用者自身のGoogleドライブにだけ保存される。** これは利用者の権利義務に
   関わる違いなので、条項として書く価値がある
2. **無料枠キーの具体的な開示。** 第8条は「各AIプロバイダーの契約条件に従う」
   という一般論。§5.3 と §14.6 は**「無料枠では学習に使われる場合がある」
   という具体的な開示と、業務利用での有料推奨**を求めている

§2 はこの2点だけを足す案である。**既存の条文には手を入れない。**

### 2-2. 第8条への追加項

## §3 アプリ内ヘルプの文面案

置き場所の案: `/production-app/card-ocr/help/`。
名刺OCRの画面から「ヘルプ」で開ける。**ログインが要る画面**にする
（本体と同じく `guardPage()` を通す）。

以下はそのまま画面に出す想定の文面である。

---

### 名刺OCR ヘルプ

#### このアプリでできること

名刺の写真から、会社名・氏名・連絡先などを読み取り、**あなた自身のGoogle
ドライブ**に保存します。表面だけでも、裏面と2枚でも登録できます。

保存先は次のとおりです。

```
マイドライブ
└─ TSAM AI
   └─ 名刺データ
      ├─ 名刺管理（スプレッドシート）
      └─ images（保存した画像）
```

#### 大切なこと（ご利用の前に）

- 名刺データと画像は、**あなたのGoogleドライブにのみ**保存されます。
  当社は受信も保管も閲覧もしません。
- バックアップ・整理・削除・共有設定・容量の管理は、**あなた自身で**
  行ってください。当社は復旧の義務を負いません。
- Gemini APIの利用費（有料キーの場合）は、**あなたに課金されます**。
- **無料枠のキーでは、送信したテキストがGoogleのプロダクト改善に
  使われる場合があります。** 名刺は第三者の個人情報ですので、
  業務でお使いの場合は**有料区分のキーをおすすめします**。
- 名刺情報（第三者の個人情報）の取り扱いに関する法令の遵守は、
  データを保有する**あなたの責任**で行ってください。
- 保存フォルダやスプレッドシートを削除・移動された場合、次回起動時に
  新しい保存先を作ります。**過去データとの連続性は保証しません。**

#### 読み取った内容を直す

登録の前に、すべての項目を画面で直せます。**保存されるのは、画面に
見えている内容です。**

「要確認」と付いた項目は、読み取りに自信がないか、表と裏で内容が違った
ものです。とくにご確認ください。

どの項目にも当てはまらなかった内容（資格、2つ目の肩書、SNS、標語など）は
「その他」に入ります。不要であれば消してから登録してください。

#### 保存したデータを消すには

**このアプリに削除の機能はありません。** データはあなたのドライブにある
ので、**ドライブ側で消していただきます。**

| 消したいもの | 方法 |
| --- | --- |
| 1件だけ | `名刺管理` シートを開き、その行を削除する。画像も消す場合は `images` フォルダから該当のファイルを削除する |
| すべて | `TSAM AI／名刺データ` フォルダごとゴミ箱へ入れる |

**フォルダごと消すと、次にアプリを開いたとき新しい保存先が作られます。**
過去のデータは戻りません。

シートの行を消しても、画像はドライブに残ります。**画像も消したい場合は
別途削除してください**（行の `front_file_url` 列のリンクから開けます）。

#### Googleとの連携を解除するには

**2段階あります。** どちらか一方だけでは残ります。

**1. アプリの画面から**

「準備」→「Googleドライブと連携しています」→「連携を解除する」。
この操作で、ブラウザが持っている接続の権限がその場で消えます。
アプリを閉じるだけでも消えます（権限をブラウザの中にしか置いていないため）。

**2. Googleアカウント側から**

上の操作は、Googleアカウントに登録された「アプリの許可」までは消しません。
完全に外すには次を行ってください。

```
Googleアカウント → セキュリティ → サードパーティ製アプリとの連携
→ 「TSAM AI 名刺OCR」を選ぶ → アクセス権を削除
```

**アクセス権を削除しても、保存済みのデータは消えません。**
データを消す場合は、上の「保存したデータを消すには」を行ってください。

#### APIキーについて

このアプリは、**あなたのGemini APIキー**を使って読み取りを行います。

- キーはポータルの「APIキー」から保存します
- キーは**お使いの端末の中にだけ**保存され、当社のサーバーへは送りません
- キーを消すには、ポータルの同じ画面から削除します

無料枠でも使えますが、**上の「大切なこと」に書いたデータの扱いを
ご確認ください。**

#### うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| 「Gemini APIキーが未設定です」 | ポータルでキーを保存し、アプリ一覧から開き直してください |
| 「HEIC形式の写真は読み取れません」 | iPhoneの「設定 › カメラ › フォーマット」を「互換性優先」にするか、この画面のカメラで撮り直してください |
| 「文字を読み取れませんでした」 | 明るい場所で、名刺全体が入るように撮り直してください |
| 「利用上限に達しています」 | 無料枠の上限です。時間をおくか、有料区分のキーをご検討ください |
| 「シートの見出しが変更されているため、書き込みを停止しました」 | `名刺管理` シートの1行目を元に戻すか、シート名を変えて新しく作らせてください |
| 「同じ会社の同じ方が、すでに登録されています」 | 名刺を作り直された場合や、同姓同名の別の方の場合は、そのまま登録して構いません |
