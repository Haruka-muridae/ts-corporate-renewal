## 2. Threads 版との差分

### 2.1 タイトル・本文の別枠(v1.1)

- note のエディタはタイトルと本文が別枠のため、本アプリも
  **タイトル入力欄と本文欄を分ける**。下書き・履歴もタイトル付きで保存する
  (タイトルは空でも保存できる。note 側も無題を許すため)。

### 2.2 「コピーして作成画面を開く」方式(intent なし・2段階)

- **note には本文プリフィルの URL が存在しない**(2026-08-12 実機確認)。
  クリップボードは一度に1つしか持てないため、流し込みは2段階とする。
  1. 「note で書く(タイトルをコピー)」— タイトルをコピーして
     作成画面 `https://note.com/notes/new` を別タブで開く
     (エディタの最初のカーソルはタイトル欄)。タイトルが空なら本文をコピーする。
  2. 「本文をコピー」— このタブに戻って押し、本文欄へ貼り付ける。
- 手順は画面に常時表示する。
- 未ログイン時は note が `/login?redirectPath=/notes/new` でログインへ誘導し、
  ログイン後にエディタが開くことを実機確認済み(同日)。
- クリップボードが許可されない環境では、コピーだけ諦めて作成画面は開き、
  その旨を画面に出す。
- 履歴の種別は「作成画面を開いた」(タイトルも記録する)。

### 2.3 記事向けの生成と上限

- 生成は投稿文ではなく**記事**: 目安 1500〜2000 字、見出し(`## 見出し`)を
  入れる、未確認情報を断定しない(既存の note 記事生成
  note-auto-fill-gas の方針を引き継ぐ)。出力トークン上限は 4096。
- **タイトルと本文を別々に生成する**(v1.1)。`responseMimeType:
  'application/json'` で `{ "title", "body" }` の JSON を受け取り、
  タイトル欄・本文欄へそれぞれ入れる(note-auto-fill-gas と同じ考え方)。
  コードフェンス付きで返っても剥がして読む。本文が無ければ生成失敗として扱う。
- 本文の上限は 30,000 字(note 側の仕様上の上限は非公開のため、
  貼り付け事故を防ぐ頭打ちとして設定)。

### 2.4 その他

- 保存キーは `tsam-note-post-v1`。
- Portal 掲載は `id: 'note-post'`、名前「note 下書き」、アイコン「n」。

## 3. 採用しなかった提案とその理由

| 提案 | 不採用の理由 |
| --- | --- |
| note API での下書き作成 | note の公開 API は投稿作成を提供していない。非公式 API への依存は互換性が保証されず、認証情報の扱いも増える |
| 本文を URL パラメータで渡す | note にその受け口が無い(実機確認)。クリップボード経由が唯一の現実解 |
| Threads 版との共有モジュール化 | 基底仕様 §9 と同じ判断(複製で運ぶ) |
