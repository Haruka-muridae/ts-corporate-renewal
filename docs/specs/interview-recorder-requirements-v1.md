## §1 目的と位置づけ

### §1-1 目的

本アプリは、オンライン面談（Web会議）の音声を、ブラウザだけで録音するPortalアプリである。

タブ音声共有とマイクをその場でミックスし、MP3へ逐次エンコードしてから、利用者自身のGoogle Driveへ保存する（v1.1）。録音データを当社サーバーへ一切送信しない点、および録音前に相手への通告・同意確認を必須とする点が、本アプリの中心的な設計方針である。

保存先・保存形式は、ブラウザ録音アプリ（`public/production-app/voice-recorder/`、要件は `docs/requirements/mvp-requirements.md`）と同一にする。同じフォルダに両アプリの録音が並び、音声文字起こしアプリ（audio-transcriber）がそこを読みに来るためである。**片方だけ仕様を動かさないこと。**

### §1-2 移植元との関係

本アプリは、単体公開版として先行運用していた interview-recorder リポジトリ（`/home/yuki9/projects/interview-recorder/public/`）を、TSAM AI Portal 配下の本番アプリとして移植したものである。

- 録音同意モーダル・タブ音声＋マイクのミックス・MP3逐次エンコード（WebM安全網付き）という状態機械（idle / capture-guide / no-tab-audio / recording / done）は移植元と同一であり、v1.1 でも変更していない。
- 移植（v1.0）で追加したのは、guardPage によるログイン確認、CSP、Portal導線（フッターの「ポータルへ戻る」）のみである。
- v1.1 で追加したのは、結果画面からの Google Drive 保存と、保存形式（ビットレート・ファイル名）の変更である。これらは移植元にはない Portal 版だけの機能であり、**移植元との差分はここから広がっていく**。以後、移植元の更新を機械的に取り込むことはできない。
- 移植元リポジトリはこの移植によって変更されない（v1.1 の改修でも触れていない）。

## §2 スコープ

### §2-1 含む機能

- 録音前の同意確認モーダル（通告・同意の明示確認）
- `getDisplayMedia` によるタブ音声＋動画の共有取得（動画は保存しない）
- タブ音声が無い場合の警告画面とマイクのみでの続行
- タブ音声とマイクの AudioContext 上でのミックス
- MediaRecorder による WebM 録音（安全網）
- AudioWorklet + lamejs によるリアルタイム MP3 逐次エンコード（既定の保存形式）
- **利用者自身のGoogle Driveへの MP3 保存（v1.1。主たる保存経路）**
- **保存名の編集（v1.2。「面談相手名」欄と「ファイル名」欄。§4-2）**
- 録音結果（MP3、MP3が作れない場合はWebM）と記録情報（JSON）のローカルダウンロード（Drive保存の代替・控えとして維持する）
- 離脱確認（beforeunload）による未保存録音の保護

### §2-2 含まない機能

- 録音データ・記録情報の**当社サーバー**または当社が管理する外部サービスへの送信
- Google Drive への自動保存（保存は利用者が結果画面で押した時点でのみ行う。§4-3）
- 記録情報（JSON）・WebM の Google Drive への保存（ローカルダウンロードのみ。§4-3）
- 文字起こし・議事録生成（audio-transcriber / meeting-minutes へは自動連携しない。ただし保存先フォルダが同一のため、文字起こしアプリからは**利用者の操作で選べる状態になる**）
- 複数トラックの個別録音、話者分離
- モバイル・タブレット向けの `getDisplayMedia` 対応（非対応ブラウザでは開始ボタンを無効化する）

> v1.0 の §2-2 にあった「Google Drive 等への自動保存（voice-recorder アプリとは独立した機能である）」は v1.1 で撤回した。撤回の理由と、それでも自動保存にしなかった理由は §12 を参照。

## §3 同意確認ゲート仕様

- 開始画面で「録音を開始」を押すと、録音同意モーダルを表示する。
- モーダルの確認文言は「面談相手に、録音することを通告しましたか？」とする。
- 「はい、通告して同意を得ました」を選んだ場合のみ、音声キャプチャ手順（画面共有ダイアログ）へ進む。
- 「いいえ、まだです」を選んだ場合、録音は開始できない旨の案内を表示し、録音フローへは進まない。
- 背景クリックまたは Esc キーでモーダルを閉じられるが、いずれも「はい」として扱わない。
- 同意確認の日時（`consentConfirmedAt`、ISO 8601）を録音セッションのメタデータとして保持し、結果画面と記録情報（JSON）ダウンロードの両方に記録する。
- この同意確認は当社サーバーへの通告記録ではなく、利用者の自己申告に基づくローカルなゲートである。相手への実際の通告・同意取得責任は利用者にある（`legal.html` §2 を参照）。

## §4 録音方式と保存

### §4-1 録音方式

| 項目 | 仕様 |
| --- | --- |
| 音源 | タブ音声（`getDisplayMedia` の audio track）＋マイク（`getUserMedia`） |
| ミックス | Web Audio API（`AudioContext`）上で各ソースにゲイン（既定 0.7）をかけてから加算 |
| 主形式 | MP3（lamejs、**モノラル・128kbps**）。AudioWorklet で PCM を逐次取得し、1152サンプル×8（約0.21秒）ごとにエンコードする |
| 安全網 | MediaRecorder による WebM（`audio/webm;codecs=opus` 優先）を並行して録音し、MP3生成に失敗した場合はWebMを既定の保存形式にする |
| タブ音声が無い場合 | マイクのみでの続行を選べる。結果画面にその旨の警告を残す |
| マイクが拒否された場合 | タブ音声のみで続行できる。タブ音声も無い場合は録音を開始しない |
| 停止 | 「録音を停止」操作、または共有停止バーからのタブ共有終了 |

ビットレートは v1.0 の 64kbps から 128kbps へ引き上げた（v1.1）。voice-recorder の §FR-06 と同一にするためで、**同じフォルダに音質の異なる MP3 が混在すると、録音元によって文字起こしの品質が変わる**ことを避ける。チャンネル数は `lamejs.Mp3Encoder(1, ...)` によるモノラル固定で、AudioWorklet（`pcm-capture-worklet.js`）が1チャンネルで渡すため2にしてはならない。

### §4-2 ファイル名

**初期値**

- 形式は `YYYYMMDD_HHmmss_面談録音.mp3`（例: `20260819_143000_面談録音.mp3`）。基準は**録音開始時刻・ブラウザのローカル日時**（voice-recorder の §FR-07 と同一の基準）。
- 接尾辞を voice-recorder の `_録音` ではなく `_面談録音` にしているのは、**同一フォルダ内で両アプリの録音を区別できるようにする**ため。

**面談相手名（v1.2）**

- 結果画面に「面談相手名（任意）」欄を設ける。入力すると初期値は `YYYYMMDD_HHmmss_<入力値>_面談録音.mp3` になる（例: `20260819_143000_田中様_面談録音.mp3`）。未入力時は上の初期値のまま。
- 入力値の位置は voice-recorder の「お客様名・イベント名」欄（§FR-07）と同じ**日時の直後**にする。ただし voice-recorder は入力値で接尾辞 `_録音` を**置き換える**のに対し、本アプリは `_面談録音` を**残す**。残さないと、相手名を入れた面談録音と、お客様名を入れたブラウザ録音が同じ名前になり、同一フォルダ内で区別できなくなるためである（§12-2）。
- サニタイズは voice-recorder と同じ（制御文字と `/` `\` を落とす。記号・空白・ドットは落とさない）。
- **この欄の内容は録音データにも端末にも当社サーバーにも保存しない。** ファイル名の初期値を組み立てるためだけに使う。画面にもその旨を注記する。

**ファイル名の編集（v1.2）**

- 結果画面に「ファイル名」欄を設け、保存前に編集できるようにする。初期値は上記で組み立てたもの。
- 未入力（空欄・空白のみ・サニタイズ後に空）のときは初期値を使う。拡張子が無ければ `.mp3` を付ける。
- 「面談相手名」欄を打ち替えると、「ファイル名」欄の値を初期値で置き換える（voice-recorder と同じく、欄を編集済みかどうかは判定しない。§12-2）。
- Drive 保存の実行中は両欄を編集できないようにし、保存が完了したら確定（編集不可）にする。Drive にある名前と画面の名前を食い違わせないためで、保存に失敗したときは編集できる状態へ戻す。
- 「新しい録音を開始」で両欄を空に戻す（前の面談相手の名前を次の録音へ持ち越さない）。

**共通**

- ローカルダウンロードも同じ名前にそろえる。WebM は `.webm`、記録情報は `.json`（**編集後の名前**から拡張子だけを差し替える）。同じ録音の3ファイルが名前で並ぶ。
- Drive の保存先に同名ファイルがある場合は上書きせず `_2`, `_3`… の連番を付与する（保存前に Drive へ問い合わせて判定）。編集した名前にも同じように付く。
- 実装は `filename.js`（voice-recorder からの複製）。日時部分の書式・サニタイズ・連番を1文字も違えないため、import ではなく複製している。複製元との差は「接尾辞を残す」点と、拡張子を差し替える `withExtension`（WebM・JSON 用。複製元には無い）の2つだけ。

### §4-3 Google Drive 保存（v1.1）

- 保存先は「マイドライブ ＞ TSAM AI ＞ Voice Recorder」。**voice-recorder と同一のフォルダ**であり、音声文字起こしアプリ（audio-transcriber）が読みに来る場所そのものである。
- フォルダIDを固定登録しない。毎回「名前と親の関係」から解決し、無ければ作成する（IDは利用者ごとに異なり、`drive.file` スコープではアプリが作成していないフォルダへ書き込めないため）。
- OAuth は Google Identity Services の暗黙フロー。**スコープは `drive.file` のみとし、増やさない。** アクセストークンはメモリ上でのみ保持し、localStorage / sessionStorage / Cookie / URL / ログのいずれにも書かない。refresh token と client secret は使わない。
- クライアントIDは voice-recorder と**同一の公開値**を用いる。`drive.file` の可視範囲はクライアントIDごとに分かれるため、IDが異なると同じ名前のフォルダを見つけられず、別フォルダを新規作成してしまう。
- 認可は結果画面の「Googleドライブへ保存」（v1.3 で voice-recorder と文言を統一。旧「Googleドライブに保存」）を押した時点で要求する。アプリを開いただけでは要求しない。（voice-recorder のように録音前に連携させないのは、アクセストークンの寿命が約1時間で面談の長さより短く、事前連携しても停止時には期限切れになっているため。§12）
- 保存するのは **MP3 のみ**。記録情報（JSON）と WebM 安全網は Drive へ上げず、ローカルダウンロードのみとする。同フォルダを文字起こしアプリが読みに来るため、あの場所に音声（MP3）以外を置かない。
- アップロードは resumable upload（分割送信）。進捗は「保存の準備」「Googleと連携」「保存先フォルダの確認」「アップロード」「保存の確定」の段階で表示する。
- 保存に成功したら、ファイル名・保存先フォルダ名・連携アカウント・DriveのファイルURLを表示する。保存済みボタンは再度押せなくする（同じ録音を二重に上げない）。
- 失敗時は再試行ボタンを出す。**録音は結果画面に残し、ローカルダウンロードで退避できる状態を保つ**（保存の失敗と録音の消失を混同させない）。認証期限切れの場合は「連携しなおして保存」から再開する。
- 保存したファイルに共有設定を付与しない（`permissions.create` を呼ばない）。
- MP3 を作れなかった場合（WebM 安全網）は保存ボタンを無効化し、ローカルダウンロードを案内する。
- 離脱確認（beforeunload）は、Drive 保存の完了かローカルダウンロードのいずれかで解除する。

### §4-4 結果画面の情報量（v1.3）

表示だけの取り決めである。**録音・MP3変換・Drive 保存・ローカルダウンロードの挙動は §4-1〜§4-3 のままで、v1.3 では1つも変えていない。**

- **ファイル名欄の注記に書くのは「保存前に編集できます。未入力のときは初期値を使います。」の2文だけとする。** 拡張子の補完・同名時の連番・JSON/WebM の命名（§4-2）は、いずれもアプリが黙って正しく行うことで、読んでも利用者の操作は変わらない。仕様としては §4-2 に残す。
- **保存後に並べる操作は「音声をダウンロード」と「新しい録音を開始」の2つとし、「記録情報をダウンロード」「元データ（WebM）をダウンロード」は `<details>`「その他のダウンロード」へ畳む。** 面談直後にほぼ必ず使うのは前者の2つで、後者は必要な人だけが必要なときに開けばよい。
  - **畳んでも退避経路は塞がらない。** MP3 を作れなかった場合（WebM 安全網）は「音声をダウンロード」自体が WebM を渡す設計で、「元データ（WebM）」ボタンは MP3 を作れたときだけ出る控えである（§4-1）。
- **「当社サーバーへ録音データを送らない」旨は開始画面で一度だけ述べる。** 結果画面の「面談相手名」欄の注記は、その欄に固有の事実（入力そのものをどこにも残さない。§4-2）だけを書く。文言は本番アプリ共通の「データは当社のサーバーを経由せず、当社が内容を受け取ることはありません。」を用いる。
- 説明文は1段落に3文以上詰めない（開始画面の2段落が手本）。

## §5 データの送信範囲

- **当社サーバー（および当社が管理する外部サービス）へは、録音データ・記録情報・同意確認日時を含むいかなるデータも送信しない。** v1.0 からの不変点であり、v1.1 でも変わらない。当社が録音の内容を知ることはできない。
- v1.1 で追加した唯一の外部送信先は、**利用者自身のGoogle Drive**である（§4-3）。送信は利用者が結果画面で保存を押した場合にのみ行い、自動では行わない。
- 録音・ミックス・MP3変換は、引き続きすべて利用者の端末内で行う。
- Cookie・アクセス解析（アナリティクス）を使用しない。
- 通信は次の3種類のみ。
  1. Portal共通の認証確認（guardPage によるセッション検証。§6）
  2. Google Identity Services（`accounts.google.com`。認可）
  3. Google Drive API（`www.googleapis.com`。フォルダ解決とMP3のアップロード）
- `legal.html` §1 の記述もこの範囲に合わせる。「外部へ送信しない」と一括りに書かないこと（実際にGoogleへ送っている以上、誤りになる）。

## §6 認証・画面ガード

ページロード時に次を実行する（他の本番アプリと同じ約束）。

```js
import { guardPage } from '../../auth/session.js';
import { setScreenDepth } from '../../auth/config.js';
import { SCREEN_DEPTH } from './config.js';

setScreenDepth(SCREEN_DEPTH);   // production-app/interview-recorder/ は深さ2

async function init() {
  const user = await guardPage();
  if (!user) return;            // すでにログイン画面へ遷移している
  el.authLoading.hidden = true;
  el.appMain.hidden = false;
  // ここから既存の初期化（開始画面の機能検出表示など）
}
init();
```

- 認証確認が完了するまで、`#app-main`（アプリ本体）を描画しない。`#auth-loading` のみを表示する。
- 無効な場合はローカルの認証セッションを消去し、`/login/?next=portal` へ遷移する。
- URLへの直接アクセスでも同じ確認を行う。
- 録音同意モーダル・状態機械・録音／MP3エンコード処理は、この認証ガードとは独立して変更していない。

## §7 CSP（Content-Security-Policy）

```
default-src 'self'; script-src 'self' https://accounts.google.com; worker-src 'self'; style-src 'self';
img-src 'self' data:; media-src 'self' blob:;
connect-src 'self' https://www.googleapis.com https://auth-verify.potenitas-lp.workers.dev;
frame-src https://accounts.google.com;
object-src 'none'; base-uri 'none'; form-action 'none'
```

- `script-src` / `frame-src` の `accounts.google.com` は Google Identity Services（認可）に必要（v1.1 で追加）。**認可そのものの提供元であるため許容する。第三者CDNは読まない。**
- `connect-src` に許可するのは次の2つだけ（v1.1）。
  - `www.googleapis.com` … Drive API（フォルダ解決・resumable upload）
  - `auth-verify.potenitas-lp.workers.dev` … guardPage のセッション検証の宛先。`*.workers.dev` へ広げないこと
- `script.google.com` / `script.googleusercontent.com` は**許可しない**。voice-recorder の CSP には入っているが、あちらは Apps Script を直接叩く経路が残っているためで、本アプリにその経路は無い。`generativelanguage.googleapis.com` 等のAI APIも含めない。
- `worker-src 'self'` は AudioWorklet（`pcm-capture-worklet.js`）の読み込みに必要。
- `media-src 'self' blob:` は録音結果の `<audio>` 再生（`URL.createObjectURL` によるblob URL）に必要。
- インラインスクリプトは使用しない。lamejs（`vendor/lamejs/lame.min.js`）は非moduleスクリプトとして `app.js` より先に読み込む。

### §10-2 単体テストで見る範囲

`config.js` の公開値と `filename.js` の純粋な文字列処理（Node から直接importできる範囲）のみを対象にする。

- `SCREEN_DEPTH === 2`
- `MP3_BITRATE_KBPS === 128`、かつ voice-recorder の `BITRATE_KBPS` と一致すること
- `PCM_FLUSH_SAMPLES` が1152の倍数であること（MP3の1フレーム単位）
- `MP3_WORKLET_URL` が同一オリジンの相対パスであること
- `MIX_SOURCE_GAIN` が0より大きく1以下であること
- `OAUTH.clientId` が `.apps.googleusercontent.com` で終わり、**voice-recorder の値と一致する**こと
- `OAUTH.scope` が `drive.file` のみで、`drive` 全体・`drive.readonly` を含まないこと
- `DRIVE_NAMES` の `root` / `app` が **voice-recorder の値と一致する**こと
- `FILE_NAME_SUFFIX` が `_面談録音` で、voice-recorder の `_録音` と**異なる**こと
- `buildDefaultFileName()` が `YYYYMMDD_HHmmss_面談録音.mp3` を返すこと。`withSequence()` が拡張子の前へ連番を入れること
- （v1.2）`buildDefaultFileName(date, label)` が相手名を**日時の直後へ入れ、接尾辞を残す**こと。空・空白のみ・未指定は初期値へ戻ること。制御文字と `/` `\` だけを落とし、記号・空白は残すこと
- （v1.2）`resolveFileName()` の未入力フォールバックと `.mp3` の自動付与。`withExtension()` が編集後の名前から `.webm` / `.json` を作ること。編集した名前にも `withSequence()` が効くこと

voice-recorder との一致（クライアントID・フォルダ名・ビットレート）は、両方の `config.js` を読み比べて確認する。**複製であって import ではないため、片方だけ動いても実行時には気づけない。** ここで固定する。

`app.js` は `document` / `navigator.mediaDevices` / `AudioWorklet` 等の実ブラウザ機能に強く依存するため、Node環境でのユニットテスト対象にしない。`oauth.js` / `drive.js` も GIS と実通信が要るため対象にしない。状態機械（idle / capture-guide / no-tab-audio / recording / done）と同意ゲート、Drive への実アップロードの確認は、実ブラウザでの手動確認に委ねる。

### §10-3 実機確認（リリース前）

- Portalグリッドに「面談録音」が表示される
- Portalからアプリを開ける（未ログイン時はログイン画面へ遷移する）
- 「いいえ」を選ぶと録音を開始できない
- タブ音声＋マイクで録音し、MP3としてダウンロードできる
- タブ音声を共有しない場合の警告とマイクのみ続行ができる
- AudioWorklet非対応環境相当（MP3生成失敗）でもWebMで録音が完了する
- 記録情報（JSON）に同意確認日時が含まれる

v1.1 で追加した確認項目。

- 結果画面の「Googleドライブへ保存」で認可画面が開き、保存が完了する（CSPで遮断されないこと）
- 保存先が「マイドライブ ＞ TSAM AI ＞ Voice Recorder」であり、**voice-recorder が作成した既存フォルダと同じ場所**へ入る（同名フォルダが新しく作られないこと）
- 保存されたファイル名が `YYYYMMDD_HHmmss_面談録音.mp3` であり、同名がある場合に `_2` が付く

- 未連携・通信断・認証期限切れのそれぞれで、エラー文言と再試行導線が出て、**ローカルダウンロードで退避できる**

- Drive 保存の完了後にページを離れても離脱確認が出ない（保存済みとして扱われる）
- 記録情報（JSON）と WebM が Drive へ**上がっていない**こと

v1.2 で追加した確認項目。

- ファイル名欄を空にして保存すると初期値に戻る。拡張子を消して保存すると `.mp3` が付く

## §11 既知の制約

- モバイル・タブレットのブラウザでは `getDisplayMedia` が使えず、録音を開始できない場合がある（開始ボタンが無効化され、案内が表示される）。
- 同意確認はローカルなゲートであり、相手への実際の通告・同意取得の適法性は利用者自身の責任である。
- 当社サーバーにデータを保存しないため、端末をまたいだ録音の共有・復旧は提供しない（Drive へ保存した後は利用者自身のドライブで扱える）。
- 録音した MP3 は保存の時点でメモリ上の Blob として存在する。voice-recorder のように OPFS へ逐次書き出す仕組みを持たないため、極端に長い面談ではメモリを圧迫し得る。上限時間の制御も持たない（§12）。
- Drive 保存の途中でページを閉じると、そのアップロードは中断される（再開機能は持たない）。録音自体は結果画面に残っているので、開いたままなら押し直せる。
- 同一フォルダに voice-recorder の録音と混在する。区別できるのはファイル名の接尾辞（`_録音` / `_面談録音`）だけである。

## §12 v1.1 で変更した判断と、採らなかった選択肢

### §12-1 撤回した v1.0 の判断

| v1.0 の記述 | v1.1 での扱い | 理由 |
| --- | --- | --- |
| §2-2「Google Drive 等への自動保存（voice-recorder アプリとは独立した機能である）」 | 撤回。Drive 保存を §2-1 へ移した | 独立した機能として分けた結果、面談の録音だけが端末に取り残され、文字起こしアプリへ渡すのに手作業が要っていた。プロジェクトオーナーによる仕様変更 |
| §5「一切のデータを、当社サーバーまたは外部サービスへ送信しない」 | 「当社サーバーへは送信しない」へ限定して改訂 | Google Drive は利用者自身の保管場所だが、**当社から見て外部であることに変わりはない**。旧文のままでは `legal.html` を含めて事実と食い違う |
| §4「既定ビットレート 64kbps」 | 128kbps へ | 同一フォルダで voice-recorder（§FR-06）と音質が揃わないため |
| §4「出力ファイル名 `面談録音_YYYYMMDD_HHMMSS`」 | `YYYYMMDD_HHmmss_面談録音` へ | 日時が先頭に来ないと、フォルダの名前順が録音順にならない。voice-recorder と同じ並びにする |

### §12-2 採らなかった選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| voice-recorder の `oauth.js` / `drive.js` / `filename.js` を import して共有する | 本番アプリ同士を相互参照しない流儀（`docs/repository-structure.md` §1）による。片方の都合でもう片方が壊れる関係を作らない。代わりに**複製し、値の一致を `tests/unit/interview-recorder.mjs` が読み比べて固定する** |
| 保存先を「TSAM AI ＞ Interview Recorder」など別フォルダにする | 文字起こしアプリが読みに来るのは Voice Recorder フォルダのみ。分けると連携の手間が残り、今回の変更の目的が果たせない。区別はファイル名の接尾辞で足りる |
| 録音停止後に自動でアップロードする | 認可のポップアップは利用者の操作からしか開けず、自動実行はブラウザに遮断される。加えて「同意なく外部へ送られた」と受け取られかねない。押した時点でのみ送る |
| voice-recorder と同じく録音前に Google 連携を済ませる | アクセストークンの寿命は約1時間で、面談の長さより短いことが普通。事前連携させても停止時には期限切れで、操作が1つ増えるだけになる（voice-recorder 自身がこの問題を踏んでいる。同アプリ `app.js` の `refreshOauthState` を参照） |
| WebM（安全網）も Drive へ上げる | 同フォルダを文字起こしアプリが読みに来る。**保存形式を揃える**という今回の目的に照らして、あの場所に置くのは MP3 のみとする |
| 記録情報（JSON）も Drive へ上げる | 同上。音声以外を置かない。JSON はローカルダウンロードのみ |
| ファイル名の接尾辞を voice-recorder と同じ `_録音` にする | 同一フォルダで見分けがつかなくなる。日時が同じになることは無いにせよ、どちらのアプリの録音か分からないのは運用上不便 |
| ~~保存名の入力欄（voice-recorder の「お客様名・イベント名」欄）を設ける~~ | **v1.2 で撤回し、実装した（§4-2）。** v1.1 では「面談直後の操作を増やしたくない」として見送ったが、面談ごとに相手が違い、日時だけでは後から探せないという運用上の要請が優った。どちらの欄も任意入力で、触らなければ v1.1 と同じ名前になるため、操作を増やしたくないという当初の理由も損なわれない |
| 録音を OPFS へ逐次書き出す（voice-recorder 方式）へ作り替える | 今回の変更は保存経路と形式に限る。録音の仕組み（状態機械・ミックス・AudioWorklet）は触らない。メモリ上限の問題は §11 に残す |

### §12-3 v1.2（保存名の編集UI）で採らなかった選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| voice-recorder と完全に同じく、相手名で接尾辞 `_録音` を**置き換える** | 置き換えると、相手名を入れた面談録音（`20260819_143000_田中様.mp3`）と、お客様名を入れたブラウザ録音が**同じ名前になり、同一フォルダ内で区別できなくなる**。`_面談録音` は v1.1 §4-2 で「両アプリを見分ける唯一の目印」として決めたものなので、これを消す変更は採れない。入る位置（日時の直後）だけ複製元に合わせた |
| 「ファイル名」欄が編集済みかどうかを判定し、編集済みなら相手名の入力で上書きしない | 「利用者が消した」と「こちらが書いた」の区別が要り、仕組みが増えるわりに間違いやすい。voice-recorder も判定していない（同アプリ `app.js` の `vr-customer` の input 監視）。相手名は名前を組み立てるための欄であり、打った結果がその場で見えるほうが分かりやすい |
| 相手名を記録情報（JSON）にも書き出す | この欄は**どこにも保存しない**（§4-2）。面談相手の氏名は個人情報であり、ファイル名という利用者が自分で決めた形以外で残さない。JSON に入れると、当社サーバーへは送らないとはいえ端末に別の形で残る |
| 保存完了後も名前を編集できるままにする | Drive にある名前と画面の名前が食い違う。編集不可にして、名前を変えたいなら Drive 側で変更してもらう |
| 相手名の候補を localStorage に覚えて補完する | 面談相手の氏名を端末へ残すことになる（§4-2 に反する）。利便性より、残さないことを優先する |

### §12-4 v1.3（結果画面の情報量）で採らなかった選択肢

| 案 | 採らなかった理由 |
| --- | --- |
| 「記録情報をダウンロード」「元データ（WebM）をダウンロード」を消す | 使う人には要る。同意確認日時を含む記録情報（§3）は、あとから確認できることに意味がある。**消さずに畳む**（`<details>`）ことで、要る人は1操作で辿れる |
| ボタン名を「記録（JSON）をダウンロード」等に言い換えて4本のまま並べる | 名前を変えても並ぶ数は減らない。面談直後に見る画面で選択肢が4つあること自体が負荷だった |
| ファイル名の注記から連番の説明を落とすかわりに、同名時の連番付与そのものをやめる | 上書き事故が起きる。**説明を落としても挙動は残す**（§4-2） |
| 「当社サーバーへ送らない」を結果画面にも残す（保存の直前に読ませたい） | 保存先は利用者自身の Drive であり、押す直前に必要なのは保存先フォルダ名（表示済み）。同じ約束を2度読ませるより、開始画面で一度きちんと述べるほうが伝わる |
