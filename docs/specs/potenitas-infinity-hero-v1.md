# POTENITAS INFINITY LP ファーストビュー「焔から文字が浮かび上がる」演出 仕様 v1.0

対象: `public/potenitas/infinity/index.html` ＋ `public/potenitas/infinity/ignite.js`（公開URL `/potenitas/infinity/`）
本文（ファーストビュー以降）の掲載内容は同ページに直接記述しており、原本は 2026-09-18 に受領した紹介文。数値・固有名詞は原本のまま。
テスト: `tests/unit/potenitas-infinity.mjs`

この文書は 2026-09-18 に受領した実装指示書を、実装の正として整理したもの。
節番号は指示書の番号と揃えてある（§1〜§23）。

## §1 目的

LP へアクセスした際、指定の背景画像をファーストビュー全面に表示し、
`POTENITAS INFINITY` と `人の可能性を、無限に。` の 2 つの文字が、
焔・火の粉の中から徐々に形成され、最終的に安定した文字として残る。

コンセプトは「眠っていた可能性に火が灯り、形になって現れる」。
単純なフェードインではなく、**火が生まれる → 文字になる → 炎が収まり文字だけ残る**。

## §2 背景

- 指定画像を `public/potenitas/infinity/hero.jpg` に置く（画像はリポジトリ外で受領。ファイル名だけをここで固定する）。
- `background-size: cover; background-position: center; background-repeat: no-repeat;`
- `min-height: 100svh`（スマートフォンのブラウザ UI による高さズレ対応。`100vh` を先に書いてフォールバックにする）。
- 画像にタイトル文字を焼き込まない。文字とアニメーションは HTML 側で重ねる。
- 指定画像は縦長（約 0.9:1）で、∞ と時計が中央、人物が下中央、周囲にアイコンという構図。
  横長画面では上下が切れるため、`background-position: center 62%` で ∞ と人物の両方を残す（上端のアイコンは切れてよい）。
  縦長画面では `center`。

## §3 構造とレイヤー順

```html
<section class="hero">
  <div class="hero-background"></div>
  <canvas class="fire-particles"></canvas>
  <div class="hero-copy">
    <h1>POTENITAS INFINITY</h1>
    <p>人の可能性を、無限に。</p>
  </div>
</section>
```

下から 背景画像 → 炎・火の粉（canvas） → 文字。

## §4 時間割（全体 約 4 秒、`TIMELINE` 定数）

| 時刻 | 内容 |
| --- | --- |
| 0.0〜0.4s | 背景のみ。タイトル非表示。文字位置にごく弱いオレンジの光 |
| 0.4〜1.2s | タイトル周辺に小さな火の粉（下から上、左右にランダム、わずかに揺れる）。まだ文字は読めない |
| 0.8〜2.0s | `POTENITAS INFINITY` が 火の粉 → 炎 → 輪郭 → 文字本体 と形成される。左 → 右へ、ただし機械的なワイプに見せず、文字ごとにばらつきのある遅延で不規則に形成する |
| 2.0s | タイトル完成（演出のピーク） |
| 2.4〜3.4s | サブコピー出現 |
| 2.0〜3.8s | 炎 100% → 50% → 10% → ほぼ消える |
| 4.0s | 通常状態へ |

## §5 タイトル演出

- 初期状態 `opacity: 0; filter: blur(10px);`
- 形成中は 赤橙 → 金 → 白〜淡い金 の順に色が変わる。
- 形成中の `text-shadow` は `0 0 6px #ffffff, 0 0 12px #ffd27a, 0 0 24px #ff8a00, 0 0 48px rgba(255,80,0,.8)`。最終状態では弱める。

## §6 焔の実装方式

CSS ＋ Canvas 2D。Three.js / WebGL は現段階では導入しない
（LP として十分な表現ができる・モバイル負荷を抑える・実装が過剰にならない・後から高度化できる）。

## §7〜§8 火の粉

- Particle は最低限 `x, y, vx, vy, size, life, maxLife, alpha` を持つ。
- タイトル周辺、特に文字下部から発生。基本は ↑、↖ ↑ ↗ 程度のばらつき。
- 色は `#ffffff` `#ffd27a` `#ff9d32` `#ff6200` からランダム。1〜4px、一部だけ 5〜6px の明るい粒。
- 派手な焚き火ではなく上品な火の粉。大量に出さない。

## §9 炎の揺らぎ

文字の真上ではなく輪郭周辺から出る疑似炎を canvas に描く。高さは文字高の 10〜25%。巨大な炎にしない。

## §10 タイトル形成後

約 2 秒でタイトル完全表示。以後、炎を 100% → 50% → 10% → ほぼ消えるまで落とす。
最終状態は `POTENITAS INFINITY` だけが残り、色は 白＋わずかな金。

## §11 サブコピー

タイトル完成の 0.3〜0.5 秒後に `人の可能性を、無限に。` を表示。強い炎は使わず、小さな火の粉 → 柔らかな発光 → 文字出現。
`opacity 0→1 / translateY(12px)→0 / blur(6px)→0`、約 1 秒。

## §12 最終表示

炎はほぼ消える。ただし完全な静止画にはせず、タイトル周辺に数秒に 1 粒程度の小さな火の粉が流れてよい（かなり控えめ）。

## §13 文字位置

背景の重要部分（中央の ∞・時計・人物）を極力隠さない。PC では左〜中央左。
指定画像は ∞ が画面中央にあるため、タイトルは PC でも 2 行（POTENITAS / INFINITY）にして左 1/3 の列に収める。
可読性のため左側だけ薄い暗色グラデーションを重ね、中央から右には重ねない。

## §14 スマートフォン

タイトルは 2 行、横にはみ出さない。`font-size: clamp(36px, 10vw, 72px)`、サブコピー `clamp(16px, 4vw, 28px)`。
縦長画面では画像の左右が切れて ∞ と人物が中央に残るため、文字は上寄せ。

## §15 フォント

英字は高級感・未来感・可読性（極端な SF フォントにしない）: Cormorant Garamond。
日本語は明朝系: Noto Serif JP。英字と日本語で世界観を揃える。

## §16 再生条件

ページ表示時に 1 回のみ。スクロールで再生しない。リロードでは再生してよい（保存しない）。

## §17 URL 遷移

ページ遷移 → 背景表示 → 約 0.4 秒 → 焔発生 → タイトル形成 → サブコピー、の順。

## §18 背景を先に

演出開始前に背景画像がロード済みであること。`<link rel="preload" as="image">` と JS の事前読込で待つ。
画像が取得できない場合は CSS のフォールバック背景（深い夜色）で続行する（画像待ちで文字が永遠に出ないことは避ける。上限 10 秒）。

## §19 reduced-motion

`prefers-reduced-motion: reduce` なら炎を再生せず、背景・タイトル・サブコピーを通常のフェードインで表示する。

## §20 パフォーマンス

- Particle 上限: PC 150〜200、スマホ 50〜80（`PARTICLE_CAP`）。画面外の粒は即削除。
- 演出後は粒が残っている間だけ描画し、タブが隠れている間・ヒーローが画面外の間は止める。

## §21 禁止事項

炎 GIF の貼り付け／炎動画の全面再生／タイトルが読めなくなるほどの炎／赤一色／爆発／大きな煙／永遠に燃え続ける／背景を炎で隠す／ページ操作を 4 秒間禁止する。
**演出中もスクロール可能**（`html`/`body` に `overflow:hidden` を付けない。canvas は `pointer-events:none`）。

## §22〜§23 完成イメージと最重要事項

背景 → 小さな火の粉 → 炎の軌跡 → タイトルが焔から形成 → サブコピーが静かに出現 → 炎が消える → ブランド文字だけが残る。
「燃えている文字」ではなく「何もなかった場所から可能性に火が灯り、POTENITAS INFINITY という言葉が生まれる」演出。
ピークは文字が完成する瞬間。以後は炎を収束させ、LP 本文へ自然につなぐ。

## 完了条件

- 指定背景画像が全面表示される
- URL アクセス後に自動再生される
- `POTENITAS INFINITY` が炎から形成される
- `人の可能性を、無限に。` が続いて表示される
- 約 4 秒以内で演出が完了する
- 最後は通常の読みやすい文字になる
- PC / スマートフォン両対応
- 背景の ∞ と人物を極力隠さない
- `prefers-reduced-motion` 対応
- アニメーション終了後も通常操作できる
- ページを重くしすぎない

## 採用しなかった提案とその理由

| 提案 | 理由 |
| --- | --- |
| Three.js / WebGL | §6 のとおり現段階では過剰。Canvas 2D で足りる |
| 炎の GIF / 動画 | §21 で禁止 |
| `clip-path` で左 → 右へワイプ | 機械的に見える。文字ごとの遅延にばらつきを与える方式にした |
| 演出をセッションで 1 回に限定（localStorage） | §16 でリロード時の再生は許容されており、保存する理由が無い |
| 演出中の `overflow:hidden` | §21 に反する |
