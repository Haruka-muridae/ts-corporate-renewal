## 2. Threads 版との差分

### 2.1 投稿先と intent リンク

- 向き先は `https://x.com/intent/post?text=…`。
- 未ログイン時は X が `redirect_after_login=<intent URL>` でログインへ誘導し、
  本文(改行・ハッシュタグ込み)が保持されたままログイン後に作成画面が開く
  ことを実機確認済み(2026-08-12)。
- 最後の「ポスト」は利用者が押す。X の API・トークンは使わない。

### 2.2 文字数の数え方(280ウェイト)

- X の上限は文字数ではなく **280「ウェイト」**。twitter-text の既定に合わせ、
  次の範囲のコードポイントを 1、それ以外(日本語・絵文字を含む)を 2 と数える。
  `U+0000–U+10FF / U+2000–U+200D / U+2010–U+201F / U+2032–U+2037`
- 日本語だけの本文なら実質約140字。
- Gemini への指示も「日本語なら140文字以内(全角=2の説明つき)」とする。

**画面のカウント表示(v1.1)**

- 表示は「残り約N字」とし、**ウェイトの説明を画面に出さない**。ウェイトは X 側の
  数え方であって、利用者が知りたいのは「あと何字書けるか」だけである。
- **数え方と上限判定は変えない。** 従来どおり `countWeight`(全角=2)で数え、
  `WEIGHT_LIMIT`(280)で判定する。表示するときだけ 2 で割って「日本語なら何字か」
  に直す。半角中心の文では実際にはもっと書けるため、必ず「約」を付ける。
- 超過時は「約N字オーバー」とし、超過分は切り上げる(1ウェイト超過を
  「約0字オーバー」と表示しないため)。超過の強調(赤字)は従来どおり。

### 2.3 その他

- 保存キーは `tsam-x-post-v1`(Threads 版と別。下書き・履歴は混ざらない)。
- Portal 掲載は `id: 'x-post'`、名前「X 投稿」、アイコン「X」。

## 3. 採用しなかった提案とその理由

| 提案 | 不採用の理由 |
| --- | --- |
| twitter-text ライブラリの導入 | 外部ライブラリを増やさない方針。必要なのは重み判定のレンジ4つだけで、自前実装で足りる(URL の23ウェイト特例は、URL 入り投稿が要件化された時点で検討) |
| Threads 版との共有モジュール化 | 基底仕様 §9 と同じ判断(複製で運ぶ) |
