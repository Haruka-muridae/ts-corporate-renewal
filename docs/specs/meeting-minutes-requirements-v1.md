## §1 目的と位置づけ

### §1-1 目的

本アプリは、会議・面談・打ち合わせ等の文字起こし結果をGeminiで整理し、確認・編集可能な議事録を生成するPortalアプリである。

利用者が長い文字起こしを読み直して要点、決定事項、担当タスク等を手作業で整理する負担を軽減する。ただし、AIの出力を確定情報として扱わず、利用者が原文と照合して完成させることを前提とする。

### §1-2 Portal内での役割

本アプリは次の既存アプリの後段に位置する。

1. voice-recorder（ブラウザ録音）で音声を作成する
2. audio-transcriber（音声文字起こし）で音声をテキスト化する
3. meeting-minutes（本アプリ）で文字起こしを議事録へ整理する

本アプリは録音機能および音声認識機能を再実装しない。

### §1-3 アプリ基本情報

| 項目 | 定め |
| --- | --- |
| アプリID | meeting-minutes |
| 表示名 | AI議事録 |
| 配置先 | public/production-app/meeting-minutes/ |
| Portalのhref | production-app/meeting-minutes/ |
| 想定アイコン | 議（実装時に既存Portalとの視認性を確認して確定） |
| UI言語 | 日本語 |
| 対象利用者 | TSAM AI Portalへ有効なアカウントでログインした利用者 |
| 実行方式 | 静的ホスティング、ブラウザ内処理、Gemini APIへの直接通信 |

### §1-4 適用文書と優先順位

本書にはPortalアプリ群の共通要件基準が適用される。矛盾がある場合は、共通要件書 §11 の定めに従い本書を優先する。

既存の voice-recorder、audio-transcriber、KeyStore、認証系の仕様は、それぞれの個別要件書を参照する。本書は既存アプリの内部仕様を変更しない。連携機能を追加する場合は、影響を受ける既存アプリの仕様書も同時に改訂する。

## §2 スコープ

### §2-1 MVPに含める機能

- 文字起こしテキストの貼り付け
- .txt および .md ファイルの読込み
- audio-transcriber からの文字起こし引継ぎ
- 会議情報の任意入力
- 議事録テンプレートの選択
- Geminiによる議事録生成
- 原文と生成結果の並列確認
- 生成結果のブラウザ上での編集
- 再生成（全文または指定セクション）
- Markdown形式でのコピーおよびダウンロード
- Googleドライブへの明示的な保存（利用者操作による。§4-15。v1.2で追加）
- 作業中データの端末内一時保存と消去

### §2-2 MVPに含めない機能

- ブラウザ録音
- 音声ファイルからの文字起こし
- リアルタイム議事録生成
- 発言者の音声識別
- Zoom、Google Meet、Microsoft Teams等との直接連携
- 複数人での同時編集
- 当社管理サーバーへの議事録保存
- 利用者間の議事録共有
- WordまたはPDFへの直接出力
- Google Driveへの自動保存
- 議事録の承認ワークフロー
- 会議予定や参加者情報の自動取得

### §2-3 将来拡張候補

- Google Docsへの書き出し
- 議事録テンプレートの利用者定義
- 生成履歴のIndexedDB保存
- 複数の文字起こしファイルの結合
- 長時間会議向けの分割処理と統合
- 固有名詞辞書、用語集、表記ルール
- 決定事項・タスクのみの再抽出

将来拡張はMVPの受入条件に含めない。

## §3 利用シナリオ

### §3-1 既存アプリ連携

1. 利用者が voice-recorder で録音する
2. 利用者が録音ファイルを audio-transcriber で文字起こしする
3. 文字起こし完了画面で「AI議事録を作成」を選ぶ
4. 文字起こしデータが同一オリジン内の一時領域へ保存される
5. 本アプリへ遷移する
6. 本アプリが引継ぎデータの概要を表示し、利用者が取込みを確定する
7. 利用者が会議情報とテンプレートを設定する
8. 利用者が送信内容を確認し、「議事録を生成」を実行する
9. Geminiが議事録案を返す
10. 利用者が原文と照合して編集する
11. 利用者がコピーまたはMarkdownファイルとして保存する

### §3-2 単体利用

1. 利用者がPortalから本アプリを開く
2. 文字起こしを貼り付ける、または .txt / .md ファイルを選ぶ
3. 会議情報とテンプレートを設定する
4. 以降は §3-1 の手順8〜11と同じ

### §3-3 誤操作からの復帰

- ページ再読込み時は、端末内にドラフトが存在する場合のみ復元候補を表示する
- 新しい入力で既存ドラフトを置き換える前に確認する
- 生成失敗時も、入力原文と編集済み内容を保持する
- 「最初からやり直す」で、当該ドラフトと引継ぎデータを明示的に消去する

「最初からやり直す」は**確認・編集画面（ステップ4）に1つだけ置く**（v1.4）。
出力画面（ステップ5）にも同じボタンを置いていたが、そこには「編集に戻る」が
あり、後退の導線が2つ並ぶことで戻り先を取り違えやすかった。出力画面から
やり直す場合は「編集に戻る」を経由する。作業データの消去そのものは
§4-14 の「端末内の作業データを削除」からも行える。

## §4 機能要件

### §4-1 認証・画面ガード

ページロード時に次を実行する。

```js
import { guardPage } from '../../auth/session.js';
import { setScreenDepth } from '../../auth/config.js';

setScreenDepth(2);
const user = await guardPage();
if (!user) return;
```

- 認証確認が完了するまで、アプリ本体を描画しない
- 無効な場合はローカルの認証セッションを消去し、/login/?next=portal へ遷移する
- URLへの直接アクセスでも同じ確認を行う

### §4-2 入力方式

本アプリは次の3方式を提供する。

| 入力方式 | 要件 |
| --- | --- |
| テキスト貼り付け | 複数行テキストエリアへ文字起こしを貼り付ける |
| ファイル読込み | 端末上の .txt または .md を1件読み込む |
| アプリ間引継ぎ | audio-transcriber が一時保存した文字起こしを利用者の確認後に取り込む |

ファイルはブラウザのFile APIで読み込み、当社サーバーへアップロードしない。

### §4-3 入力検証

| 条件 | 動作 |
| --- | --- |
| 入力が空 | 生成ボタンを無効化し、入力方法を案内する |
| 空白文字のみ | 空として扱う |
| 対応外拡張子 | 読込みを中止し、.txt または .md を選ぶよう案内する |
| ファイル読込み失敗 | 貼り付け入力を代替手段として案内する |
| バイナリと判断される内容 | 読込みを中止する |
| 文字コードを正しく解釈できない | UTF-8形式で保存し直すよう案内する |
| モデルの入力上限を超える可能性 | 生成前に警告し、短縮または分割を案内する |

最大文字数はGeminiモデルの仕様とプロンプト分を考慮して実装時に定数化する。上限値をUI文言へ直書きしない。

確定値は60,000字（`config.js` の `TRANSCRIPT_MAX_CHARS` 定数）とする。根拠は §14 を参照。

### §4-4 会議情報

以下を任意入力とする。

- 会議名
- 開催日
- 開始時刻・終了時刻
- 参加者
- 会議の目的
- 補足事項（固有名詞、専門用語、出力上の注意）

未入力の項目をAIに推測させない。原文から明確に特定できない情報は「記載なし」または空欄とする。

全項目が任意であるため、**入力画面では `<details>` で畳み、既定を閉とする**
（v1.4）。必須の「文字起こし」と同じ高さで7項目が常時開いていると、
埋めないと進めないと読めてしまい、ステップ1が縦に長くなるため。
`<details>` は閉じても DOM を保持するので入力値は破棄されない。
開閉は details / summary のネイティブ機能に任せ、button + aria-expanded の
自前実装はしない。

ただし**値が入っているのに畳んだままにはしない**。ドラフト復元・引継ぎでの
会議名採用など、利用者の入力以外で値が入る場面では開いた状態にする
（復元したはずの参加者・目的・補足が画面から見えず、入力し直される事故を
避けるため）。全体リセット後は空になるので畳み直す。

### §4-5 議事録テンプレート

MVPでは次のプリセットを提供する。

| テンプレート | 用途 | 主な出力項目 |
| --- | --- | --- |
| 標準 | 一般的な社内会議 | 概要、議題、決定事項、タスク、未決事項 |
| 要点重視 | 短時間で内容を確認 | 要約、決定事項、タスク |
| 詳細 | 経緯を残す会議 | 議題別の要旨、主な意見、決定事項、タスク、未決事項 |
| 1on1・面談 | 面談や定期対話 | 話題、本人の認識、合意事項、次回までの行動 |

テンプレートは固定プリセットとし、利用者によるテンプレート編集はMVPに含めない。

### §4-6 Gemini APIキー

- Portal共通のKeyStoreからGemini APIキーを取得する
- キーが未設定の場合は生成を開始せず、KeyStoreの設定導線を表示する
- キーは当社サーバーへ送信しない
- API通信では x-goog-api-key ヘッダーを使用する
- APIキーをURLパラメータ、ログ、エラー表示へ含めない
- キーの有効性は別建ての疎通確認を行わず、初回の生成リクエスト自体で確認する（不採用とした理由は §14-1 を参照）
- 生成リクエストがキー不正（401/403）で失敗してもKeyStoreから自動削除しない

### §4-7 AIへの送信前確認

生成前に、次の内容を利用者へ表示する。

- 文字起こしおよび入力した会議情報がGoogle AI APIへ直接送信されること
- 当社サーバーを経由せず、当社が入力内容・生成結果を保存しないこと
- 機密情報・個人情報を含む場合は、利用者自身の組織ルールを確認すること
- AI出力には誤りや抜けがあり得るため、原文との照合が必要であること

初回生成時は、利用者が送信内容を確認してボタンを押す明示操作を必須とする。設定のみで自動送信しない。

**表示の割り当て**（v1.4）。上の4点は、送信確認画面（ステップ2）の注意書きへ
4段落で並べていたが、次のとおり整理した。読む量を減らすためであって、
伝える内容は削っていない。

| 内容 | 出す場所 |
| --- | --- |
| Google AI API へ直接送信されること／当社サーバーを経由せず当社が内容を受け取らないこと | ステップ2の注意書き 第1段落（2文まとめて。送信先の説明と保証は一体で読ませる） |
| 機密情報・個人情報は組織ルールを確認すること | ステップ2の注意書き 第2段落 |
| AI出力には誤りや抜けがあり得るため原文と照合すること | **ヘッダーの説明文**。ヘッダーはステップ1〜5のどこにいても表示され続けるため、ステップ2でも読める。同じ文をステップ2へ重ねて置かない |

「当社サーバーを経由しない」旨は、**画面内に1回だけ**書く。ファイル読込みの
注記やドライブ保存の注記へ同趣旨の文を重ねない（それぞれの注記は、
その操作そのものの説明に徹する）。

### §4-8 議事録生成

生成処理はブラウザからGemini APIへ直接リクエストする。

AIへの指示には少なくとも次を含める。

- 入力にない事実、担当者、期限、決定を補完しない
- 不明な情報は不明と示す
- 発言者表記がある場合のみ発言者を関連付ける
- 雑談、重複、言い直しを要約対象から適切に除外する
- 決定事項と提案・検討事項を区別する
- タスクには内容、担当者、期限、根拠を持たせ、不明項目を推測しない
- 日本語で、選択テンプレートの構造に従う
- 原文に反する内容を生成しない

### §4-9 構造化出力

API応答はJSONの構造化出力を基本とし、次の概念を保持する。

```text
meeting
  title
  date
  time
  participants[]
  purpose
summary
topics[]
  title
  summary
  keyPoints[]
decisions[]
actionItems[]
  task
  assignee
  dueDate
  evidence
openIssues[]
notes[]
```

- 実装時にJSON Schemaを定義する
- 必須・任意項目をSchemaとUIで一致させる
- 不正なJSONを受け取った場合は1回だけ安全な再解析または再生成を試みる
- 修復できない場合は原文を保持したままエラーを表示する
- evidence は原文確認の補助情報であり、完成版Markdownへの出力は既定で省略してよい

### §4-10 根拠確認

- 決定事項およびタスクには、可能な範囲で対応する原文の短い根拠を関連付ける
- 根拠はAIが新規に作る引用ではなく、入力文字起こし内の該当箇所に限る
- 根拠が見つからない項目は「根拠を確認できません」と表示する
- 利用者が原文検索または該当箇所への移動を行える設計を優先する

原文にタイムスタンプがある場合は保持し、根拠箇所の案内に利用する。タイムスタンプがない場合に擬似的な時刻を生成しない。

### §4-11 編集

- 生成結果の全項目を利用者が編集できる
- 編集内容はHTMLではなくプレーンテキストとして扱う
- 項目の追加・削除・並べ替えを行える
- 未保存の編集がある状態でページを離れる操作には警告する
- 編集中に再生成する場合、置換対象を明示する

### §4-12 再生成

次を提供する。

- 議事録全体を再生成
- 要約のみ再生成
- 決定事項のみ再抽出
- タスクのみ再抽出

再生成前に、現在の編集内容が置き換わる範囲を表示する。対象外のセクションは保持する。

### §4-13 コピー・ダウンロード

| 操作 | 要件 |
| --- | --- |
| Markdownをコピー | 完成した議事録をMarkdownとしてクリップボードへコピー |
| Markdownを保存 | UTF-8の .md ファイルとして端末へダウンロード |

ファイル名の既定値は、会議日と会議名がある場合に `YYYY-MM-DD_会議名_議事録.md` とする。ファイル名に使用できない文字は安全な文字へ置換し、会議名がない場合は `YYYY-MM-DD_議事録.md` とする。

### §4-14 ドラフト

- 入力原文、会議情報、選択テンプレート、生成結果、編集内容を端末内へ保存できる
- MVPの保存先は同一オリジンのlocalStorageまたはIndexedDBとする
- 大容量の原文はlocalStorageへ保存せず、IndexedDBを優先する
- 自動保存の有無と保存期間は実装時にUIと合わせて定数化する
- 「端末内の作業データを削除」で本アプリのデータだけを消去する
- APIキーおよび認証セッションは本アプリの削除対象に含めない

「端末内の作業データを削除」は**ステップの外、画面末尾の「データの管理」区画に
置く**（v1.4）。入力画面（ステップ1）の「確認へ進む」の直前に並べていたが、
先へ進む操作と作業を消す操作が隣り合うのは誤操作の代償が大きい。この区画は
ステップ表示の対象外で、どのステップでも表示されたままとする。削除の結果
（成功・失敗）は同じ区画のメッセージ欄へ出す（ステップ1のメッセージ欄では、
ステップ5から押したときに案内が隠れたままになるため）。実行前の確認と、
APIキー・ログイン状態を消さない扱いは従来どおり。

### §4-15 Googleドライブへの保存（v1.2追加）

| 項目 | 要件 |
| --- | --- |
| 操作 | 出力画面（ステップ5）の「Googleドライブへ保存」ボタン。利用者の明示操作でのみ実行し、アプリを開いただけでは認可を求めない |
| 保存先 | 利用者自身のGoogleドライブ「マイドライブ ＞ TSAM AI ＞ 議事録データ」。フォルダIDをコードへ固定せず、名前と親の関係で毎回解決し、無ければ作成する |
| 形式 | §4-13 と同じファイル名規則の .md（text/markdown、UTF-8）。画面に表示中のMarkdown（根拠を含める設定を反映した内容）を保存する |
| 保存方式 | 毎回新しいファイルとして作成する。既存ファイルの上書き・更新はしない（誤って前の版を失わないことを優先） |
| 認可 | Google Identity Services のトークンモデル。スコープは drive.file のみで、ドライブ全体が見えるスコープを要求しない。アクセストークンはメモリ上のみに保持し、Storage・Cookie・URL・ログへ書かない |
| クライアントID | voice-recorder / audio-transcriber と同一のOAuthクライアントを意図して共用する。同じ作業（録音→文字起こし→議事録）の系統であり、将来、文字起こしTXTを drive.file のまま読む拡張を可能にするため。一致は自動テストで検知する |
| 失敗時 | §9-2 の文言で案内し、入力・生成結果を失わない。認可の期限切れ（401）はトークンを破棄し、再度のボタン操作で認可し直させる。ボタン押下から離れた非同期処理の途中で認可ポップアップを自動で開かない |
| CSP | script-src / frame-src へ accounts.google.com を、connect-src へ www.googleapis.com / accounts.google.com を追加する。Google Picker（apis.google.com / docs.google.com）は使用せず、許可しない |

保存の実装は audio-transcriber の oauth.js / drive-client.js からの複製・適合とし、本番アプリ間で共通層を作らない方針（リポジトリ構成宣言 §4）に従う。

## §5 アプリ間連携要件

### §5-1 基本方針

アプリ間連携は同一オリジン内で完結し、当社サーバーへ文字起こしを送信しない。URLのクエリ文字列またはハッシュへ文字起こし本文を含めない。

### §5-2 引継ぎデータ

引継ぎデータは少なくとも次を持つ。

```text
version
sourceApp
createdAt
transcript
metadata
  title
  recordedAt
  durationSeconds
  speakers[]
```

- version により将来の形式変更を判定する
- sourceApp は audio-transcriber とする
- transcript 以外の項目は任意とする
- 本アプリは未知の項目を無視し、未知のメジャーバージョンは取り込まない
- 引継ぎデータは信頼できない入力として検証する

### §5-3 一時保存と消去

- 引継ぎにはsessionStorageまたはIndexedDBを使用する
- 本文そのものをlocalStorageへ恒久保存する方式は避ける
- 引継ぎキーは実装時に一意な固定名を定め、双方の仕様書に記載する
- 正常取込み後は引継ぎデータを消去する
- 取込みをキャンセルした場合も消去する選択肢を提示する
- 有効期限を過ぎた引継ぎデータは自動で無効化する

確定値は次のとおり（audio-transcriber側の実装と一致させること）。

- 保存先: sessionStorage
- 引継ぎキー: `tsam-meeting-minutes-handoff-v1`
- 有効期限（TTL）: createdAt から30分

### §5-4 既存アプリ側の変更

audio-transcriber に「AI議事録を作成」を追加する場合は、次を同時に行う。

- audio-transcriber-requirements-v1.md の改訂
- アプリ間引継ぎの単体テスト追加
- 既存の文字起こし保存・コピー機能に影響がないことの回帰確認

voice-recorder から本アプリへ直接遷移させない。音声しかない場合は audio-transcriber へ案内する。

## §6 画面要件

### §6-1 画面構成

単一ページ内を次のステップで構成する。

1. 入力
2. 設定・送信確認
3. 生成中
4. 確認・編集
5. 出力

現在位置を見出しとステップ表示で伝える。ステップ表示だけに依存せず、読み上げ可能な見出し構造を持たせる。

### §6-2 入力画面

- アプリ名と短い説明（ヘッダー。全ステップで表示され続ける）
- audio-transcriber からの引継ぎ通知
- テキスト入力欄
- ファイル選択ボタン
- 入力文字数の表示
- 会議情報入力欄（`<details>` で畳む。既定は閉。§4-4）
- テンプレート選択
- 端末内ドラフトの復元（保存済みのドラフトがあるときだけ出る復元バナー）
- 「確認へ進む」ボタン

端末内の作業データの**削除**はこの画面に置かない。画面末尾の
「データの管理」区画へ移した（§4-14。v1.4）。

### §6-3 送信確認画面

- 入力内容の概要（文字数、会議名、テンプレート）
- Google AI APIへ送信される情報の説明（当社サーバーを経由しない旨を同じ段落に含める）
- 機密情報・個人情報に関する注意
- 「戻る」と「議事録を生成」のボタン

注意書きはこの2段落までとする（v1.4）。AI出力の確認責任はヘッダーの説明文が
常時担うため、この画面へ重ねて置かない（§4-7 の表を参照）。

### §6-4 生成中画面

- 処理中であることをテキストで通知
- 経過時間を表示してもよいが、完了時刻を断定しない
- 二重送信を防止する
- キャンセル可能な実装であれば中止ボタンを表示する
- prefers-reduced-motion: reduce では不要なアニメーションを停止する

### §6-5 確認・編集画面

デスクトップでは、原文と議事録を左右に並べる。狭い画面ではタブまたは縦積みに切り替え、横スクロールを発生させない。

- 原文表示・検索
- 議事録プレビュー
- 各項目の編集
- 根拠確認
- セクション別再生成
- コピー・ダウンロード
- 最初からやり直す（本アプリで唯一この画面にだけ置く。§3-3）

出力画面（ステップ5）に置くのは「編集に戻る」だけとし、「最初からやり直す」は
並べない（v1.4。§3-3）。

### §6-6 レスポンシブ

320px、375px、768px、1024px、1440pxで確認する。

- 320pxでも主要操作が利用できる
- 固定幅の入力欄やダイアログを使用しない
- ボタンの文字が欠けない
- 長い会議名・参加者名・URL・英単語で横スクロールしない
- 1024px以上では原文と議事録の並列表示を基本とする

### §6-7 アクセシビリティ

- button、input、textarea、select 等のネイティブ要素を使用する
- すべての入力に可視ラベルを付ける
- Tabキーで主要操作へ到達できる
- Enter / Spaceでボタン操作ができる
- フォーカス位置を視覚的に確認できる
- エラーは色だけで伝えない
- 生成完了・失敗は適切なライブリージョンで通知する
- 見出しレベルを飛ばさない
- ライトテーマ（固定）でコントラストを確認する

### §6-8 デザイン

- 背景は常に純白（#FFFFFF）とする。ダークテーマは持たず、OSの配色設定（prefers-color-scheme）で配色を変えない（v1.3。`<meta name="color-scheme" content="light">` と対で運用する）
- 共通スタイルのカスタムプロパティのみで色を指定する
- 本アプリ専用CSSを public/production-app/meeting-minutes/ 配下に置く
- 共通スタイルへ本アプリ専用クラスを追加しない
- 既存Portalアプリと一貫したヘッダー、余白、ボタン表現を使用する

### §6-9 画面文言（v1.4。本番アプリ共通の基準）

- Googleドライブ保存のボタン文言は「Googleドライブへ保存」とする。
  画面上の日本語表記は「Googleドライブ」に揃え、「Google Drive」と混在させない
  （APIそのものを指す「Google Drive API」だけは製品名としてそのまま使う）。
- 説明文は1段落に3文以上詰めない。趣旨の単位で段落を分け、必要なら
  `<br>` で文単位に改行する。
- **同じことを同じ画面で2度書かない。**注記を足す前に、既存の注記・
  ヘッダーの説明文で同じ内容を言っていないかを確かめる。
- 「当社サーバーへ送らない」旨は、データの流れが同じ箇所では
  「データは当社のサーバーを経由せず、当社が内容を受け取ることは
  ありません。」に揃える。本アプリのように実際の送信先（Google AI API・
  利用者自身のドライブ）がある場合は**正確さを優先**し、
  誇張した保証にしない（§4-7・§7-1）。
- 破壊的操作（作業データの削除など）は、先へ進む操作の直前に並べない
  （§4-14）。後退の導線を同じ画面に2つ以上並べない（§3-3）。

## §7 データ・プライバシー要件

### §7-1 データフロー

| データ | 送信・保存先 | 当社サーバーでの保存 |
| --- | --- | --- |
| Gemini APIキー | 利用者端末のKeyStore、Google AI API | なし |
| 文字起こし | 利用者端末、利用者の明示操作時のみGoogle AI API | なし |
| 会議情報 | 利用者端末、利用者の明示操作時のみGoogle AI API | なし |
| 生成結果 | 利用者端末 | なし |
| 編集内容 | 利用者端末 | なし |
| 完成した議事録（Drive保存時） | 利用者の明示操作時のみ、利用者自身のGoogleドライブ（drive.file スコープ） | なし |
| 匿名の利用統計 | 実装する場合のみ別途定義 | 本文・個人情報を含めない |

### §7-2 共通要件 §5-3 の個別解釈

共通要件にある「ファイルの中身（画像・音声・テキスト）をユーザーの端末外へ出さない」は、本アプリのAI生成処理とは両立しない。本アプリでは次のように定める。

- ファイルおよび文字起こしを当社サーバーへ送信しない
- 利用者が「議事録を生成」を明示的に実行した場合に限り、必要なテキストを利用者自身のGemini APIキーでGoogle AI APIへ直接送信する
- 利用者が「Googleドライブへ保存」を明示的に実行した場合に限り、完成した議事録を利用者自身のGoogleアカウントのドライブへ直接送信する（§4-15）
- 送信前に送信先と送信内容を説明する
- 保存や再生成のために当社側へ複製しない

本項は本アプリに限る個別要件である。共通要件書の表現は、外部AI APIへの直接送信を許容する旨が明確になるよう、別途改訂を推奨する。

### §7-3 データ最小化

- 選択したテンプレートに不要な情報を送信しない
- 認証情報、APIキー、Portalの利用者IDをプロンプトへ含めない
- ファイル名は会議名として利用者が明示的に採用しない限り送信しない
- 生成に不要なアプリ内部情報、エラー履歴、画面状態を送信しない

### §7-4 ログ

- console.log にAPIキー、文字起こし、会議情報、生成結果を出力しない
- エラー報告にリクエスト本文またはレスポンス本文を含めない
- 匿名ログを実装する場合も、文字数などから内容を推測できない集計粒度を採用する

## §8 セキュリティ要件

### §8-1 XSS対策

- 利用者入力とGemini応答を信頼しない
- 表示には textContent を使用する
- MarkdownはHTMLへ変換して挿入せず、安全なDOM生成またはプレーンテキスト表示とする
- innerHTML、outerHTML、insertAdjacentHTML を使用しない
- AI応答内のURLをリンク化する場合は https:// または http:// を検証する
- ファイル名をDOM、属性、ダウンロード名へ使用する前に正規化する

### §8-2 API通信

- HTTPSのみ使用する
- x-goog-api-key ヘッダーでキーを送信する
- APIリクエストに認証セッション情報を含めない
- リクエストのタイムアウトまたは中止手段を設ける
- リトライは一時的な失敗に限定し、無制限に行わない
- 429等のレート制限時は、時間をおいて再度試すよう案内する

### §8-3 プロンプトインジェクション対策

文字起こしは命令ではなく処理対象データとして扱う。

- システム指示と文字起こし本文を明確に分離する
- 文字起こし内の「前の指示を無視」等の文を実行しないようモデルへ明示する
- 応答形式をJSON Schemaで制約する
- 外部URLの取得、ツール実行、追加API呼び出しをモデルへ許可しない
- モデル応答をコードとして実行しない

### §8-4 大容量入力・可用性

- 生成前に入力サイズを検査する
- 極端に大きい入力をそのままDOM複製しない
- API呼び出し中の多重実行を防ぐ
- AbortController 等で不要になった通信を終了できる設計とする
- 失敗時に利用者の原文を失わない

## §9 エラー要件

### §9-1 基本文型

エラーは「○○ができませんでした。××をご確認ください。」を基本とし、利用者が次に行える操作を示す。

### §9-2 主なエラー

| 条件 | 表示例 | 利用者の操作 |
| --- | --- | --- |
| APIキー未設定 | 議事録を生成できませんでした。Gemini APIキーを設定してください。 | KeyStoreを開く |
| APIキー無効 | Geminiに接続できませんでした。APIキーが有効かご確認ください。 | 設定を確認、再試行 |
| 入力なし | 議事録を生成できません。文字起こしを入力してください。 | 貼り付けまたはファイル選択 |
| 対応外ファイル | ファイルを読み込めませんでした。txtまたはmd形式をご確認ください。 | 別ファイルを選択 |
| 入力上限超過 | 議事録を生成できませんでした。文字起こしを短くするか分割してください。 | 短縮・分割 |
| ネットワーク障害 | Geminiに接続できませんでした。通信状態を確認して再度お試しください。 | 再試行 |
| レート制限 | 議事録を生成できませんでした。時間をおいて再度お試しください。 | 待って再試行 |
| API応答不正 | 議事録を正しく生成できませんでした。もう一度生成してください。 | 再生成 |
| 引継ぎデータ不正 | 文字起こしを引き継げませんでした。音声文字起こしアプリからもう一度お試しください。 | 元アプリへ戻る |

| コピー失敗 | 議事録をコピーできませんでした。Markdownファイルとして保存してください。 | ダウンロード |

| Drive認可の期限切れ | Googleドライブの利用許可の期限が切れました。もう一度「Googleドライブへ保存」を押して、許可し直してください。 | 再度保存を実行 |

| Drive保存の通信失敗 | 通信に失敗しました。ネットワークの状態を確認してください。 | 再試行、またはダウンロード |

## §10 非機能要件

### §10-1 性能

| 項目 | 目安 |
| --- | --- |
| HTMLロード | 1秒未満 |
| JS解析・初期実行 | 500ミリ秒未満 |
| 初回描画 | 2秒未満 |
| 入力操作 | 通常サイズの文字起こしで入力・スクロールを妨げない |
| 生成開始 | ボタン操作後、即時に処理中表示へ切り替える |

API処理時間は外部サービスと入力長に依存するため、完了時間の保証値を設けない。

### §10-2 依存関係

- 新しい外部ライブラリを原則追加しない
- Gemini APIはSDKを追加せず fetch で直接呼び出す
- Googleドライブ保存も同様に、Drive APIを fetch で直接呼び出す。Google Identity Services（accounts.google.com。認可の提供元であるGoogle本体のスクリプト）以外の外部スクリプト・第三者CDNを追加しない
- Markdown処理のためだけに依存を追加しない
- 依存追加が必要な場合は、バンドルサイズ、保守性、セキュリティ影響を評価し、事前承認を得る

### §10-3 対応ブラウザ

Portal本体の対応ブラウザ方針に準拠する。少なくとも最新安定版のChrome系ブラウザでゴールデンパスを確認する。File API、Clipboard API、IndexedDB等が利用できない場合は、可能な代替手段または説明を提示する。

### §11-1 テスト配置

- 空入力、空白のみ、対応外形式を拒否する

実APIを常時呼ばず、fetch をモックして次を検証する。

- APIキーを x-goog-api-key で送る
- URL、ログ、画面へAPIキーを露出しない
- 選択テンプレートに合うリクエストを作る
- 正常な構造化応答を描画できる
- 不正JSON、空応答、タイムアウト、ネットワーク障害を処理する

- 二重送信を防ぐ
- 再生成時に対象外セクションを保持する

### §11-6 編集・出力テスト

- 生成結果を編集できる
- 項目を追加・削除・並べ替えできる
- Markdownコピーが正しい
- .md をUTF-8で保存できる
- ファイル名を安全に生成する
- Drive保存のフォルダ解決が「検索→無ければ作成」の順で行われる（fetch差し替えで検証）
- Drive保存のクライアントID・最上位フォルダ名が録音・文字起こし系と一致している
- Drive APIの401がUNAUTHORIZEDとして分類され、エラーへトークンが漏れない
- 編集中の再生成で置換範囲を確認できる
- 「最初からやり直す」で本アプリの作業データだけを消去する
- （v1.4）「端末内の作業データを削除」がステップの外にあり、どのステップからでも
  押せて、結果の案内が同じ区画に出る（実機確認。DOM を伴うため Node の
  単体スイートでは検証しない）

## §15 既知の制約

- AI出力の正確性は保証できず、利用者による原文確認が必要である
- 発言者情報が文字起こしに含まれない場合、発言者を正確に復元できない
- 入力が長いほどAPIの処理時間と利用者負担のコストが増える
- BYOK方式のため、利用可否、利用量、料金、レート制限は利用者のGoogle AI API設定に依存する
- ブラウザまたは端末のデータ消去により、未ダウンロードのドラフトを失う場合がある
- 当社サーバーにデータを保存しないため、端末間同期、復旧、共有をMVPでは提供しない
- 外部AI APIへの送信を禁止する組織では本アプリを利用できない
- （v1.2）Drive保存は drive.file スコープの制約により、同一OAuthクライアントのアプリが作成したフォルダ・ファイルだけが見える。利用者が手動で作成した同名フォルダは見えないことがあり、その場合は同名の別フォルダが作られうる
- （v1.2）Drive保存は毎回新しいファイルを作成する（上書きしない）。同じ議事録を保存し直すと、同名ファイルがドライブ上に複数並ぶ場合がある
