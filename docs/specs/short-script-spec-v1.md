## 0. 本書の前提と設計原則

### 0.1 設計原則（名刺OCR・領収書OCR と同じBYOK・同一オリジン）

**利用者の資格情報（Gemini APIキー）も、生成した台本も、当社サーバーへ送信しない。** 当社が提供するのは「道具（静的アプリ）」であり、鍵の器は利用者の端末（ブラウザ）、生成の相手は Google（Gemini）だけである。サーバーコードはゼロ。

この原則の帰結として、本アプリは Portal と**同一オリジン**（`https://tsam-ai.com/production-app/short-script/`）に配置する。これは KeyStore（[keystore-spec-v1.md](./keystore-spec-v1.md)）が保存した Gemini キーを参照するための必須条件である。別オリジン（例: `localhost`）からは同じ localStorage を読めない。

### 0.2 Gemini APIキーの取り扱い（BYOK）

* キーは利用者本人が発行し、本人が課金される。当社は預からない。
* 保管は KeyStore（`public/auth/keystore.js`。localStorage キー `tsam-api-keys`）のみ。設定・削除は Portal の「API設定」で行う。本アプリは**キーの設定UIを持たない**（設定はポータルに一本化する）。
* 本アプリがキーの値を読むのは**生成の瞬間の1回だけ**であり、モジュールに保持しない・console やログ・URL に出さない。Gemini へは `x-goog-api-key` ヘッダーで送る。
* **無料枠のキーでは、送信したテキストが Google のプロダクト改善に使われる場合がある。** この旨をヘルプに明示する。機密のテーマは避けるよう案内する。
* 生成物を利用できる範囲・商用利用の可否は Google の利用規約に従う。**当社が規約解釈を断定しない**（ヘルプでは利用者へ規約確認をうながす表現にとどめる）。

### 0.3 未確定事項

* 実 Gemini API が本書 §7.3 の `responseSchema` を受理し、期待どおりの JSON を返すことは、名刺OCR（`../card-ocr/`）の同型実装で確認済みだが、本アプリでの実 API 疎通は本書作成時点で未検証。
* ログイン後の実UI（フォーム→生成→表示）の目視確認は、要ログイン環境またはプレビュー配信で行う（ローカルは別オリジンのため不可）。

## 1. 背景・目的

「ショートAIスタジオ」（テーマから台本→音声→字幕→縦型動画を自動生成するアプリ）を、TSAM AI Portal の本番アプリとして段階的に移植する。本書はその**第1段階＝台本生成**を規定する。台本を単体で作れること、後段（音声・字幕・動画）がそのまま食える形で台本を出力できることを目的とする。

音声（VOICEVOX）・動画（FFmpeg）は将来拡張（§13）とする。**VOICEVOX はローカルエンジンが必須でブラウザ版が存在しない**ため、本アプリは名刺OCRのような「ローカル依存ゼロの静的アプリ」には原理的になれない。第1段階の台本生成はこの制約と無関係にブラウザ完結できるため、先に単体で提供する。

## 2. アプリ名称・配置

* 名称：ショート動画 台本メーカー
* アプリID：`short-script`
* 配置：`public/production-app/short-script/`（Portal と同一オリジン＝KeyStore 参照の必須条件）
* **Portal への掲載は「アプリ一覧」スプレッドシート（暫定DB）への行追加で行う**（[apps-grid-spec-v1.md](./apps-grid-spec-v1.md) §7-4「第3便：アプリ一覧の取得元をスプレッドシートへ＝完了」、§15）。ライブのポータルは `public/portal/app-source.js` 経由でこのシートを CSV 取得して一覧を描く。列は **A:アプリID / B:アプリ名 / C:アプリURL / D:アイコンURL**。
  * 本アプリの行：`short-script` ／ `ショート動画 台本メーカー` ／ `https://tsam-ai.com/production-app/short-script/` ／（D は空でよい＝名前の1文字目に落ちる）。
  * **C 列は http(s) の絶対URLでなければ弾かれる**（`app-source.js` の `safeUrl`）。相対パスは不可。**D 列もURL**であり、文字1字は入らない（不正なら icon は空になる）。
  * C 列が本番の絶対URLである以上、**カードが機能するのは本番デプロイ後**。未デプロイのあいだ、この URL は 404 になる。
  * シートID は本書に書かない（[README.md](./README.md) の「スプレッドシートID を仕様書へ書かない」ルール。実値は `app-source.js` にある）。
* `APP_REGISTRY`（`public/portal/app-registry.js`）は、**シート取得に失敗したときの組み込みフォールバック**（§15）。本アプリも1件加えてあるが、そちらの `href` は相対（`production-app/short-script/`。先頭 `/` 不可・`apps/` を含めない）、`icon` は文字1字「台」で、シート版とは形式・役割が異なる。**掲載の正はシートである。**
* `id` は配置データ（`tsam-app-layout` の `order`）が指す先であり、**あとから変えない**（apps-grid-spec-v1.md §4-c）。アプリIDと同じ `short-script` とする。シート・`APP_REGISTRY` の両方で同じ `short-script` を用いる。
* テスト環境 `/apps/` のコードを import しない。流用するロジック（Gemini 呼び出し・エラー分類）は本番側へ**複製**する（[repository-structure.md](../repository-structure.md) §4-1）。

## 3. 対象範囲

### 3.1 MVPスコープ（第1段階）

1. 入力方法の選択：**AIで作る**／**台本を貼り付け**／**セグメント編集**。
2. AI：テーマ（最大100文字）と尺（30秒／60秒）から Gemini で台本生成（タイトル＋シーン配列。各シーンは秒数とナレーション文）。
3. 貼り付け：既存の台本を Gemini を介さず取り込む（**全文を1シーンとして扱う**。Gemini キー不要＝ログインのみ）。
4. 生成・取り込み結果の画面表示。
5. 台本のプレーンテキストのコピー、および JSON での保存。
6. **音声・動画：** 台本から、ローカル補助サービス（ai-video-app）でナレーション音声（VOICEVOX）つきの縦型動画（FFmpeg）を生成（§13）。

### 3.2 対象外（第1段階では作らない）

* 音声・動画の**ブラウザ内完結**（VOICEVOX はローカルエンジン必須のためローカル補助サービスに委ねる。§13・§14）。
* 台本の保存・履歴・アカウントへの紐付け。台本・動画はその場でコピー／ダウンロードするのみ。
* シーン分割編集・BGM・背景画像の指定。→ 後段フェーズで扱う。

## 7. 台本生成仕様

### 7.1 入力

* テーマ：文字列、前後空白を除き空でないこと。最大100文字（`THEME_MAX_LENGTH`）。
* 尺：`30` または `60`（`DURATIONS`）。既定は `30`。

### 7.2 指示（プロンプト）

`prompt.js` の `buildSystemInstruction(durationSec)` が組み立てる。要点：

* シーン数の目安は 30秒＝3〜4、60秒＝5〜7。
* 各シーンの秒数の合計が、およそ指定尺になること（**厳密一致は求めない**。最終尺は後段で実音声に同期させる前提）。
* 各シーンの `text` は話し言葉のナレーション、最大60文字。
* 最初のシーンはフック、最後はまとめ／行動喚起。
* 誇大表現・不確かな断定を避ける。

版は `PROMPT_VERSION = 'short-script-1'`。指示を変えたら版を上げ、`config.js` の `APP_VERSION` も上げる。

### 7.3 構造化出力（responseSchema）

`SCRIPT_SCHEMA`。**`type` は大文字**（proto 列挙型。小文字は 400 で弾かれる。名刺OCR prompt.js の注記と同じ）。

```
OBJECT {
  title: STRING
  scenes: ARRAY of OBJECT { seconds: NUMBER, text: STRING }   // required: seconds, text
}                                                              // required: title, scenes
```

`generationConfig`：`responseMimeType='application/json'`、`temperature=0.8`（台本は創作のため揺れを許容）、`maxOutputTokens=1024`。

### 7.4 モデルと呼び出し

* 主モデル `gemini-2.5-flash-lite`、フォールバック `gemini-3.5-flash-lite`（`config.js`）。
* **404（モデル不在）のときだけ**フォールバックへ1回切り替える。廃止への備えであって混雑時の退避ではない。503 では切り替えない。
* 401/403 等では再試行しない（結果は変わらず無料枠のクォータを削るだけ）。

### 7.5 台本の正規化（`normalizeScript`）

モデルは指示に反した値を返すことがある。画面・後段へ渡す前に、必ず次の形へ寄せる（prompt だけに頼らない）。

* `title` が空 → `BAD_JSON`。
* `scenes` が配列でない → `MISSING_FIELDS`。
* 各シーン：`text` を trim し最大60文字へ切り詰め、空なら落とす。`seconds` は 2〜20 に丸める（`SCENE_SECONDS_MIN`/`MAX`）。
* 残ったシーンが0件 → `MISSING_FIELDS`。

### 7.6 貼り付けの取り込み（`paste.js`）

Gemini を介さない。本文（前後空白を除き空でないこと）を **1シーン**として取り込む。

* `scenes = [{ seconds, text }]`。`text` は原文のまま（改行含む）。**60文字への切り詰めはしない**（AI 生成と異なる。字幕は後段で自動的に折り返す前提）。
* `seconds` は本文の長さの目安（空白を除いた文字数 × 0.15、下限2秒）。最終尺は後段で実音声に同期させる。
* `title` は入力があればそれ、無ければ「ペーストした台本」。
* 生成物に `source: 'pasted'` を持たせ、表示（§8.1）と保存（§8.3）を分岐する。
* 貼り付けは Gemini キーを要さない。§4 のキー・ガードは AI モードにのみかかる。

### 7.7 セグメント編集（`app.js`）

Gemini を介さない。各セグメントに **〔ナレーション文＋背景画像（任意）〕** を指定し、上から順に並べる。

* 1セグメント＝1シーン。`scenes = [{ seconds, text }]`（`seconds` は文長の目安）、`segmentImages = [dataURL|'']`（scenes と1:1。空＝そのセグメントは既定背景）。生成物 `source: 'segments'`。
* 表示時間は各ナレーションの実音声長で決まる（§0 の音ズレ防止方針どおり。**秒数の明示指定はしない**。§14）。
* 空文字のセグメント（本文なし）は取り込み時に落とす。最大20セグメント。
* 動画化時、`segmentImages` を背景として補助サービスへ渡す（全体アップロード欄 §13.3 は使わない）。キー不要。

## 8. 出力

### 8.1 画面表示

タイトル、メタ情報、シーンの並び（シーン番号・秒数・ナレーション文）を表示する。メタは由来で変える：AI は「テーマ・尺の目安・シーン数・合計」、貼り付けは「入力＝貼り付け・シーン数・合計」。「作り直す」は AI のときだけ出す（貼り付けでは意味がないため隠す）。生成のたびに前の結果を隠してから描画する。

### 8.2 コピー

プレーンテキスト（タイトル＋「シーンN（M秒）」＋本文）を `navigator.clipboard` でコピー。使えない環境では失敗を利用者へ知らせる。

### 8.3 JSON保存

後段（音声・字幕・動画）がそのまま食える JSON をダウンロードする。後段が必ず要るのは `title` と `scenes`。付随情報は由来（`source`）で変える。

```
共通    : { title, scenes: [{ seconds, text }], appVersion, source }
AI      : + theme, durationSec, promptVersion
貼り付け : （付随情報なし。source='pasted'）
```

ファイル名はタイトルから禁止文字を除いたもの（最大40文字、空なら `script`）。Blob URL は `click()` 後、**次tickで解放**する（同期解放は一部ブラウザで保存を失敗させる）。

## 9. エラーコード（表示用）

`gemini.js` の `describeGeminiError` が、コードと**原因の要約（detail）**を必ず返す。「不明なエラー」だけの画面を作らない。

| コード | 意味 | HTTP | 案内 |
| --- | --- | --- | --- |
| KEY-001 | キー未設定 | — | ポータルで設定 |
| KEY-002 | キーが拒否された | 401/403 | キーの正しさ・有効性を確認 |
| AI-001 | 通信失敗／サーバーエラー | 5xx・通信断 | 時間をおいて再試行 |
| AI-002 | 利用上限 | 429 | 無料枠は時間をおく |
| AI-003 | リクエスト不正／応答不正 | 400・不正JSON | 再試行（キーの問題ではない） |
| AI-004 | 応答に必要項目が不足 | — | 再試行 |
| AI-005 | モデル利用不可 | 404 | — |
| SYS-999 | 不明 | — | — |

**400 をキーの問題にしない**（キーが悪いときは 401/403）。混ぜると原因から遠ざかる。

## 10. セキュリティ要件

### 10.1 鍵の取り扱い

§0.2 のとおり。KeyStore の外で localStorage を直接触らない。エラーの detail に鍵が混入する経路がないこと（Gemini はキーを本文へ返さず、URL にも載せていない）。

### 10.2 CSP（meta で宣言）

`next.config.ts` は `public/` 全体に効くため、このアプリのために触ると本体を巻き込む。よってページごとに meta で宣言する（名刺OCRと同じ方針）。

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:;
connect-src 'self' https://generativelanguage.googleapis.com
            https://script.google.com https://script.googleusercontent.com;
object-src 'none'; base-uri 'none'; form-action 'none'
```

* **本アプリは Google OAuth（GIS）を使わない**ため、名刺OCRと違い `accounts.google.com` は入れない。`script-src` は `'self'` のみ（インライン・eval なし）。
* `connect-src` の外部は Gemini（生成）と、認証確認が用いる Apps Script（`script.google.com` / リダイレクト先 `script.googleusercontent.com`）だけ。

## 11. 非機能要件

* レスポンシブ：320 / 375 / 768 / 1024 / 1440px で確認（AGENTS.md）。操作要素は 44px 以上。
* アクセシビリティ：ラベルと入力の対応、`role="status"` / `aria-live` で進捗・エラーを読み上げ、結果見出しへフォーカス移動（`tabindex="-1"`）。`prefers-reduced-motion` に配慮。
* 尺セレクタの選択ハイライトは `:has()` を用いる。ラジオ自体は全ブラウザで機能し、古いブラウザではハイライトのみ出ない（機能低下なし）。

6. 触れた範囲に新しい lint 警告を足さない（CLAUDE.md）。

## 13. 第2段階：音声・動画（ローカル補助サービス連携）

台本ができたら、利用者のPCで動く**ローカル補助サービス（ai-video-app）**へ台本を渡し、ナレーション音声（VOICEVOX）つきの縦型動画（FFmpeg）を作る。**方式Aを採用**（§14）。VOICEVOX にブラウザ版がなく、`ffmpeg.wasm` は字幕焼き込み等に難所があるため、実証済みのローカルパイプラインを流用する。

### 13.1 補助サービスとの契約

* 既定の原点は `http://127.0.0.1:3000`（`config.js` の `COMPANION_BASE_URL`。秘密ではない）。
* `POST /api/generate` … 台本JSON（`{ title, scenes }`）＋声設定（`speakerId` / `speedScale` ほか）を受け取り、**AI生成を飛ばして**音声・動画だけ作る。進捗は NDJSON（`stage` / `script` / `done` / `error`）で1件ずつ返す。
* 背景画像は `backgrounds`（data URL の配列。png/jpeg/webp）で任意に渡せる。**渡された場合は補助サービスの `public/bg` より優先**。マッピングは要素数で決まる：**シーン数とちょうど同数なら「1シーン1枚」で対応づけ**（空要素はそのシーンだけ既定へフォールバック。セグメント編集で使う）、それ以外は**ローテーション**（アップロード欄で数枚渡す場合）。無ければ `public/bg`（同梱グラデ）→ 単色。いずれの背景にも **Ken Burns（ゆっくりズーム/パン）** が自動で付く（補助サービス側の処理。FFmpeg zoompan・完全ローカル）。
* `GET /api/speakers` … 話者一覧（`{ id, label }` の配列）。声設定の充填に使う。エンジン未起動でもフォールバック一覧が返るため、**応答があったことを「エンジンが使える」証拠にしない**。実態はレスポンスヘッダ `X-Engine-Status: online | offline | mock`（`Access-Control-Expose-Headers` で公開）で返る。**ヘッダ欠落＝このヘッダを持たない旧版の補助サービスで、後方互換のため online 相当として扱う**（従来は speakers の成否だけで判定していたため、旧版の利用者を弾かない）。
* `GET /api/engine/status` … 音声エンジン（VOICEVOX）の稼働状況。**接続可否の判定はこちらが正。** `running` は実際に VOICEVOX へ疎通した結果のみが入る（`{ installed, running, version, mock }`）。
* `POST /api/engine/start` … エンジンの起動を依頼する（冪等。起動済みなら何もせず成功）。ボディは読まれない。応答まで最大60秒かかりうる。404 は当該 API を持たない旧版の検出に使う。**409（`reason: not_installed`）は VOICEVOX 未インストール**で、応答ボディに公式サイトの `downloadUrl` が付く（`companion.js` は非2xx応答の `reason` / `downloadUrl` を呼び出し側へ透過する。ボディが JSON でなければ null）。
* `GET /api/video/:id` … 完成MP4（Range 対応）。

### 13.2 通信とセキュリティ

* `companion.js` がブラウザから直接呼ぶ。NDJSON をバッファしつつ1行ずつ解釈する。
* https(tsam-ai.com)→http(localhost) を通すため、**補助サービス側が CORS ＋ Private Network Access ヘッダを返す**（許可オリジンは `https://tsam-ai.com` と `localhost`/`127.0.0.1` のみ echo。`*` にしない）。`localhost` は Chrome の mixed-content 例外。
* ポータル側 CSP の `connect-src`・`media-src` に `http://127.0.0.1:3000`・`http://localhost:3000` を追加。

### 13.3 画面と失敗時（3状態の出し分けとエンジン起動）

台本ができると「音声・動画を作る」パネルを出し、`/api/speakers` の成否と `X-Engine-Status` で補助サービスの状態を **3状態** に分ける。「アプリに届かない」と「アプリは動くがエンジンが止まっている」を1本の真偽値に潰さない。

| 状態 | 条件 | 案内と操作 |
| --- | --- | --- |
| offline | `/api/speakers` に到達できない | 「ai-video-app に接続できません。起動してから再確認」。**起動ボタンは出さない**（押しても届かない）。「再確認する」で復帰。 |
| engine-offline | 応答あり、かつ `X-Engine-Status` が `offline` または `mock` | 「ai-video-app は起動しているが VOICEVOX が停止」。**「エンジンを起動」ボタンを表示**。「動画を作る」は無効のまま。 |
| online | 応答あり、かつ `X-Engine-Status` が `online` **またはヘッダ欠落（旧版の後方互換）** | 話者を充填し「動画を作る」を有効化。 |

「エンジンを起動」の挙動：

* 押すと `POST /api/engine/start` を送り、`GET /api/engine/status` を **2秒間隔・最大30秒**（`config.js` の `ENGINE_START_POLL_INTERVAL_MS` / `ENGINE_START_TIMEOUT_MS`。実測7.9秒の約4倍のマージン）でポーリングして online を待つ。ポーリングは `setInterval` ではなく await の直列（fetch のタイムアウト4秒＞間隔2秒で確認が重なるため）。
* 実行中は起動・再確認の両ボタンを無効化し、多重クリックを防ぐ（`engineStarting` フラグ）。進行文言は `aria-live` 領域に出す。
* 通信断（起動依頼が届かない）は疎通確認をやり直して offline の案内へ。**404 は当該 API を持たない旧版**なので「ai-video-app が古いため画面からは起動できない。VOICEVOX を手動起動して再確認」を案内する。
* **409（`reason: not_installed`）は VOICEVOX 未インストール**なので、ポーリングせず**即座に**「VOICEVOX がインストールされていません。公式サイトからインストールして再確認」を案内する（待たせても起動しないため。以前は30秒待った末に汎用のタイムアウト文言になっていた）。応答の `downloadUrl` が http(s) の URL なら案内の「公式サイト」をリンクにする（`innerHTML` は使わず DOM 操作で生成。`rel="noopener"`）。
* ポーリング中に `/api/engine/status` への**到達失敗（ok=false）が2回連続**したら、ai-video-app 自体が落ちたとみなして期限を待たずに打ち切り（`waitForEngineOnline` が `unreachable: true` を返す）、疎通確認をやり直して offline 表示へ収束させる。そのまま offline なら「ai-video-app への接続が失われました。起動し直して再確認」を案内する（エンジンではなくアプリ側の問題に、誤って「VOICEVOX のインストール確認」を案内しないため）。1回だけの失敗（瞬断）では打ち切らない。
* タイムアウト時は「起動を確認できませんでした。VOICEVOX のインストールを確認のうえ手動起動して再確認」を案内する。
* 成功時の画面遷移は `refreshCompanion()` の呼び直しに集約する（online へ直接書き換える経路を作らない）。

声設定は話者（`/api/speakers` から充填）と話速。**背景画像は任意でアップロードできる**（複数可・シーンごとにローテ）。選ばなければ補助サービスの既定背景（`public/bg` か同梱グラデ）を使う。完成動画は 9:16 枠で再生・ダウンロードできる。

### 13.4 将来拡張（第3段階以降）

* 台本のシーン分割編集、BGM・背景画像の指定、SNS投稿。
* 補助サービスURLの画面からの変更（いまは `config.js` 固定）。

## 14. 採用しなかった提案とその理由

| 案 | 却下の理由 |
| --- | --- |
| APIキーを `.env.local`（サーバー環境変数）に置く | 本アプリはサーバーを持たない静的アプリ。ポータルの他アプリと同じ「鍵はブラウザ・当社サーバーに送らない」原則（§0.1）に反する。KeyStore に一本化する。 |
| キーの値をアプリ独自の入力UIで受ける | 設定箇所が増えると「どこかで送っていないか」の確認コストが増える。設定は Portal「API設定」に一本化し、本アプリは有無だけを見る。 |
| 旧 `apps/shared/ai-config.js`（`tsam-ai-gemini-key`・`AIza` 形式検証）を流用 | それは `/apps/` テスト環境の層であり、本番の鍵層は `auth/keystore.js`（`tsam-api-keys`）。実際のキーは `AIza` 以外の形式もあるため、`AIza` 前提の検証は採用しない（KeyStore は形式検証しない）。 |
| 503（混雑）でフォールバックモデルへ切り替える | 混雑は待って直すもの。切り替えは廃止（404）への備えに限る（名刺OCRの判断を踏襲）。 |
| 第1段階で音声・動画まで一気に作る | VOICEVOX がローカル必須・`ffmpeg.wasm` の字幕焼き込み等に技術的難所があり、方式決定が要る。台本は無関係にブラウザ完結できるため、先に単体で出す。 |
| 貼り付けを空行や改行で自動的にシーン分割する | 利用者の選択により**全文を1シーン**とした。分割規則を機械が決めると意図とずれやすく、字幕は後段で自動的に折り返せる。シーンを分けたい場合は AI 生成を使うか、後段フェーズで分割編集を用意する。 |
| 補助サービスの疎通判定を `/api/speakers` の成否1本のままにする | `/api/speakers` はエンジン停止中でもフォールバック一覧を返すため、「アプリに届かない」と「エンジンが止まっている」の失敗が1つに潰れ、利用者への案内も対処も誤る（実際に誤判定が起きていた）。`X-Engine-Status` と3状態（§13.3）で分ける。 |
| エンジン起動後は固定8秒（実測値）だけ待つ | 起動時間は環境依存（低速機・コールドスタート）で、固定待ちは速い環境では無駄に待ち、遅い環境では早すぎて失敗扱いになる。`/api/engine/status` のポーリング（2秒間隔・最大30秒）で実際の online を確認する。 |
| `mock`（`VOICEVOX_MOCK=1`）を online 扱いにする | mock は無音のダミー音声で合成される動作確認用モード。online 扱いにすると**無音の動画が黙って生成され**、利用者が気づくのは書き出し後になる。engine-offline と同じく生成を止め、実エンジンの起動を促す。 |
