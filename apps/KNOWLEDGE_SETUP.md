# ナレッジ管理・検索アプリ 設定手順（/apps/knowledge/）

Google Drive のファイルを、**ブラウザの中だけで**解析・保存・検索するツール。

- サーバー、外部データベース、外部の生成AI APIは使わない。
- 通常の探索・同期・検索では、Google Drive へ **一切書き込まない**（GETしか呼ばない）。
- Drive へ書き込むのは、利用者が明示的にボタンを押した次の2つだけ。
  どちらも**新規作成のみ**で、既存ファイルの編集・移動・削除はできない
  （更新・削除のAPIを実装していない）。
    1. 不足フォルダの作成（`POST /drive/v3/files`）
    2. サンプルファイルの作成（`POST /upload/drive/v3/files`／01_ナレッジ を新規作成したときの初回だけ）
- 抽出テキスト・検索インデックスはブラウザ内（IndexedDB）にのみ保存する。

公開URL（予定）: <https://tsam-ai.com/apps/knowledge/>

## 最短手順（これだけやれば動く）

**コードの修正は不要。** 手作業が必要なのは Google Cloud Console の設定だけ。

| # | やること | 所要 | 詳細 |
| --- | --- | --- | --- |
| 1 | Google Cloud Console で Drive API を有効化 | 2分 | [第1章](#1-google-cloud-console-での作業手作業はここだけ) |
| 2 | OAuth同意画面に `drive.readonly` を追加 | 3分 | 同上 |
| 3 | OAuthクライアントIDの「承認済みJavaScript生成元」にURLを登録 | 3分 | 同上 |
| 4 | テストユーザーに動作確認者のGoogleアカウントを登録 | 1分 | 同上 |
| 5 | Driveに `TSAM AI / ローカルLLM / 01_ナレッジ` を作り、テスト用ファイルを置く | 10分 | [第5章](#5-動作確認用のサンプルファイルを用意する) |

そのあと <https://tsam-ai.com/apps/knowledge/> を開く。
**初回はセットアップウィザードが開く**ので、上から順にボタンを押していけばよい
（[第4章](#セットアップウィザード初回のみ)）。

```
1. Googleにログイン        読み取り権限だけを要求する
2. フォルダ構成を確認       読み取り専用で確認する
3. 不足フォルダを作成       欠けているときだけ。確認画面で内容を確かめてから
   （3.5 サンプルファイル） 01_ナレッジ を新規作成したときだけ
4. 初回同期
5. 検索テスト
6. 診断                    OAuth / Drive / フォルダ / 同期 / 検索 / IndexedDB / 権限
7. ナレッジ管理を開始       以降は通常画面が開く
```

うまくいかないときは、ウィザードの「診断」か、通常画面の
**設定タブ →「接続診断」→「診断を実行」**。
どの段階で失敗しているかが日本語で表示される（[第6章](#6-接続診断うまく動かないとき)）。

## 1. Google Cloud Console での作業（手作業はここだけ）

### 1-1. プロジェクトを選ぶ

<https://console.cloud.google.com/> を開き、`/apps/` のGoogleログインで使っているものと
**同じプロジェクト**を選ぶ（`apps/AUTH_SETUP.md` 参照）。新規作成でもよい。

### 1-2. Google Drive API を有効にする

「APIとサービス」→「ライブラリ」→ `Google Drive API` を検索 →「有効にする」。

> 有効化していないと、画面に
> 「Google Drive APIが有効になっていません。」と表示される。

### 1-3. OAuth同意画面にスコープを追加する

「APIとサービス」→「OAuth同意画面」→「データアクセス」→「スコープを追加または削除」。

追加するのは **2つ**。

```
https://www.googleapis.com/auth/drive.readonly    ← 通常の探索・同期・検索（常に使う）
https://www.googleapis.com/auth/drive             ← 不足フォルダの作成のときだけ
```

`drive` を追加しても、**普段の動作は `drive.readonly` のまま**である。
アプリが `drive` を要求するのは、利用者が初期設定画面で
「不足フォルダを作成」を押した瞬間だけで、作成が終わればトークンを破棄する
（詳細は[第4章の「不足フォルダの作成」](#不足フォルダの作成)）。

> **なぜ `drive.readonly` では作成できないのか**
>
> Drive API v3 のディスカバリ文書（`https://www.googleapis.com/discovery/v1/apis/drive/v3/rest`、
> revision 20260720 で実測）によると、`files.create` が受け付けるスコープは次の3つだけ。
>
> ```
> https://www.googleapis.com/auth/drive
> https://www.googleapis.com/auth/drive.appdata
> https://www.googleapis.com/auth/drive.file
> ```
>
> `drive.readonly` と `drive.metadata` は含まれない。
> 作成には追加スコープの認可が必ず要る。

> **フォルダ作成を使わない場合**
>
> `drive` を追加したくない場合は、Drive上で
> `TSAM AI / ローカルLLM / {01_ナレッジ, 02_未整理, 03_アーカイブ, 99_システム}` を
> 手で作れば、`drive.readonly` だけで従来どおり動く。
> その場合「不足フォルダを作成」を押すと同意画面で拒否され、
> 「フォルダを作成する権限が許可されませんでした。」と表示されるだけで、
> Drive には何も書き込まれない。

> **注意**: `drive.readonly` と `drive` はどちらも Google の分類で「制限付きスコープ」。
> User Type が「外部」で本番公開する場合、**Googleの審査が必要**。
> 社内利用（User Type「内部」）なら審査は不要。
> より狭い `drive.file` の検討結果は[第8章](#8-より狭い権限drivefileへ切り替える)。

### 1-4. 承認済みのJavaScript生成元を登録する

「APIとサービス」→「認証情報」→ 対象のOAuthクライアントID（ウェブアプリケーション）を開く。

「承認済みのJavaScript生成元」に、**オリジンだけ**を登録する（パスや末尾スラッシュは付けない）。

```
https://tsam-ai.com
http://localhost:5173
http://localhost:8123
http://127.0.0.1:8123
```

> `localhost` と `127.0.0.1` は**別のオリジン**として扱われる。
> どちらで開くか分からない場合は両方登録する。
> 登録漏れがあると `The given origin is not allowed for the given client ID` で失敗する。

リダイレクトURIの登録は不要（ポップアップ方式のため）。

### 1-5. テストユーザーを登録する

公開ステータスが「テスト」の場合、登録したアカウントでしかログインできない。
「対象」→「テストユーザー」に、動作確認する人のGoogleアカウントを追加する。

> 未登録だと、同意画面が `access_denied` で閉じ、
> 「Googleアカウントへのアクセスが許可されませんでした。」と表示される。

### 1-6. （任意）Google Picker を使う場合

Picker を使わなくても、Drive APIによるフォルダ一覧で選択できる。使う場合のみ:

1. 「ライブラリ」→ `Google Picker API` →「有効にする」。
2. 「認証情報」→「APIキーを作成」。
3. 作ったキーを開き、**必ず制限をかける**。
   - アプリケーションの制限: **HTTPリファラー**（`https://tsam-ai.com/*`）
   - APIの制限: **Google Picker API のみ**
4. `apps/knowledge-src/src/config.js` の `pickerApiKey` に貼り、再ビルドする。

制限のかかっていないAPIキーはコミットしないこと。

## 2. 設定値の正本（どのファイルを編集するか）

**同じ値を2か所へ書かない。** 各設定値の正本は次のとおり。

| 設定値 | 正本ファイル | 備考 |
| --- | --- | --- |
| **OAuthクライアントID** | `apps/auth-config.js` の `GOOGLE_AUTH_CONFIG.clientId` | `/apps/` のログインと共有。**knowledge側には書かない** |
| Picker用APIキー | `apps/knowledge-src/src/config.js` の `AUTH_CONFIG.pickerApiKey` | knowledge専用 |
| プロジェクト番号（appId） | `apps/knowledge-src/src/config.js` の `AUTH_CONFIG.pickerAppId` | `SCOPE_MODE = 'file'` のときのみ必要 |
| 使用スコープ | `apps/knowledge-src/src/config.js` の `SCOPE_MODE` | `'readonly'` / `'file'` |
| 固定フォルダパス | `apps/knowledge-src/src/config.js` の `KNOWLEDGE_FOLDER_PATH` | 既定 `['TSAM AI', 'ローカルLLM', '01_ナレッジ']` |

この表はアプリの **設定タブ →「設定値の正本」** にも表示される。

### クライアントIDが二重管理にならない仕組み

`/apps/` はビルド無しの素のESM、knowledge はViteバンドルで、配信形態が違うため
実行時に同じファイルを読めない。そこで **ビルド前に正本から取り込む**。

```
apps/auth-config.js                                  ← 正本（ここだけ編集する）
        │  npm run build / npm run dev が自動実行
        ▼
apps/knowledge-src/scripts/generate-auth-config.mjs
        ▼
apps/knowledge-src/src/generated/google-config.js     ← 自動生成（Git管理外）
        ▼
apps/knowledge-src/src/config.js が import
```

- 生成ファイルは `.gitignore` 済み。**手で編集しない。**
- クライアントIDを変えたら、`apps/auth-config.js` を直して**再ビルド**する。
- 単独で再生成する場合: `npm run generate:config`

### コミットしてよいもの / いけないもの

| 種別 | 可否 | 理由 |
| --- | --- | --- |
| OAuthクライアントID | 可 | 公開情報。保護は「承認済みJavaScript生成元」で行う |
| Picker用APIキー（制限あり） | 可 | 公開前提。リファラー制限とAPI制限が前提 |
| プロジェクト番号 | 可 | 公開情報 |
| client secret | **不可** | このアプリでは不要。置く場所もない |
| refresh token / アクセストークン | **不可** | メモリ上にのみ保持する |
| サービスアカウント秘密鍵 | **不可** | 使用しない |

## 4. 固定フォルダパスの自動探索

対象は次の固定パス。

```
マイドライブ
└─ TSAM AI
   └─ ローカルLLM
      └─ 01_ナレッジ      ← ここが同期対象
```

### 探索方法

**フォルダ名だけの全体検索はしない。** 親フォルダIDを指定しながら1階層ずつ降りる。

| 段 | 親 | 条件 |
| --- | --- | --- |
| 1 | `root`（マイドライブ） | 親ID + フォルダ種別 + ゴミ箱除外 + 名前 `TSAM AI` |
| 2 | 1で得たフォルダID | 同上 + 名前 `ローカルLLM` |
| 3 | 2で得たフォルダID | 同上 + 名前 `01_ナレッジ` |

Drive API の名前一致は大文字小文字を区別しないことがあるため、
取得後にクライアント側で**完全一致**を再確認している。

### 結果ごとの動作

| 状況 | 動作 |
| --- | --- |
| 一意に解決 | 「マイドライブ / TSAM AI / ローカルLLM / 01_ナレッジ」と表示し、フォルダIDを保存。配下のファイルを一覧表示 |
| 見つからない | **どの階層で失敗したか**を表示し、フォルダ選択へ誘導。名前が近いフォルダがあれば候補を出す |
| 同名が複数 | **自動選択しない。** 候補を並べて利用者に選ばせる |
| `SCOPE_MODE = 'file'` | 自動探索できない旨を表示し、Pickerでの選択を促す |

**探索そのものは絶対にフォルダを作らない。** 作成は次項の操作を明示的に行ったときだけ。

既にフォルダを選択済みなら、ログイン時の自動探索は結果を表示するだけで
**選択を上書きしない**。切り替えるときは「固定パスを再探索」を押す。

### 不足フォルダの作成

初期設定タブの「3.5 フォルダ構成の確認と作成」で、次の構成が揃っているかを
**読み取り専用のまま**確認する。

```
マイドライブ
└─ TSAM AI
   └─ ローカルLLM
      ├─ 01_ナレッジ      ← 同期対象
      ├─ 02_未整理
      ├─ 03_アーカイブ
      └─ 99_システム
```

欠けているものがあるときだけ「**不足フォルダを作成（n 件）**」ボタンが出る。

| 段階 | 何が起きるか | 権限 |
| --- | --- | --- |
| 1. 確認 | 1階層ずつ読み取りで探索し、既存 / 不足 / 同名複数 を仕分ける | `drive.readonly` |
| 2. 確認画面 | 作成後の階層・既存フォルダ・新規作成するフォルダ・「編集や削除はしない」ことを表示 | なし |
| 3. 作成 | **ここで初めて** `drive` を要求。上から順に、作る直前に毎回再検索してから作る | `drive`（一時的） |
| 4. 後始末 | 書き込みトークンをアプリ内部から破棄し、固定パスを再探索して対象フォルダIDを更新 | なし |

守っていること。

- 作成順序は **TSAM AI → ローカルLLM → 01_ナレッジ → 02_未整理 → 03_アーカイブ → 99_システム** で固定
- **既にあるフォルダは作り直さない**（再検索して再利用する）
- **同名フォルダが複数あるときは、自動選択も自動作成もしない**。作成ボタンを無効化して候補を出す
- 送るのは `POST https://www.googleapis.com/drive/v3/files` **だけ**。
  本文は `name` / `mimeType`（フォルダ）/ `parents`（1件）の3つのみ、
  `fields` は `id,name,mimeType,parents,webViewLink`
- **PUT / PATCH / DELETE は実装そのものが存在しない**。既存ファイルの編集・移動・削除はできない
- 途中で失敗しても、成功した分はそのまま。「作成を再実行」で**続きから**やり直す
- 連打・複数タブ・同期中の作成・作成中の同期は、すべて止める
- 429 / 5xx は再試行（Retry-After 尊重）、**401 / 403 は再試行しない**

確認画面には、次の4点を必ず表示する。

1. **フォルダのみ作成します**（ファイルは作らない）
2. **既存ファイルは編集・削除しません**（移動もしない）
3. **同期は開始しません**（フォルダを作るだけ）
4. **GoogleのDrive編集権限を一時的に使用します**（終わったら破棄する）

> **権限の後始末について**
>
> 作成が終わると、書き込み用トークンはアプリのメモリから即座に消える。
> ただし Google アカウント側の「アプリへの許可」自体は残る
> （取り消すと同じ許可にぶら下がる読み取り権限まで無効になり、再ログインが必要になるため）。
> 完全に外したい場合は <https://myaccount.google.com/permissions> から手動で削除する。

### サンプルファイルの作成（01_ナレッジ を新規作成したときだけ）

`01_ナレッジ` を **このアプリが新しく作った** 場合に限り、
セットアップウィザードに「サンプルファイルを作成」という手順が1つ増える。

| ファイル | 中身 |
| --- | --- |
| `README.md` | フォルダの使い分けと、対象になるファイル形式の説明 |
| `サンプル.txt` | 検索テスト用のキーワード `テスト用キーワードあいうえお` を含むテキスト |

- **初回の1度だけ**。既にフォルダがあった場合はこの手順自体が出ない。
- 作る前にフォルダ内を一覧し、**同じ名前のファイルがあれば作らない**（上書きしない）。
- 使うのは `POST /upload/drive/v3/files?uploadType=multipart` のみ。
  更新・削除のAPIは実装していないため、既存ファイルには触れられない。
- この手順もスキップできる。スキップしてもセットアップは完了できる。

## 4-3. AIナレッジチャット（/apps/knowledge/chat/）

同期済みの資料を検索し、**ブラウザ内で動くAI**が根拠付きで回答する画面。

公開URL: <https://tsam-ai.com/apps/knowledge/chat/>

### 何が起きるか / 起きないか

| | 内容 |
| --- | --- |
| **起きない** | 質問・資料本文・回答を外部の生成AIサービスへ送らない（OpenAI / Gemini / Anthropic 等は使わない） |
| **起きない** | Google Drive への書き込み。チャット画面は Drive API を一切呼ばない |
| **起きる** | 初回だけ、AIモデルのファイルを取得する通信（**GETのみ**） |

推論はすべて利用者のGPU（WebGPU）で行う。
質問文も資料も、端末の外へは出ない。

### 使用ライブラリとモデル

| 項目 | 内容 |
| --- | --- |
| ライブラリ | `@mlc-ai/web-llm` 0.2.84（Apache-2.0） |
| 実行方式 | WebGPU（WebAssembly は補助。CPU のみでの実行は提供しない） |
| モデル配信元 | `huggingface.co` → `*.hf.co`（重み）、`raw.githubusercontent.com`（推論ライブラリ .wasm） |

選べるモデルは3つ。いずれも WebLLM が実際に配布しているものだけを載せている
（起動時にライブラリ側の一覧と突き合わせ、無いものは表示しない）。

| 段階 | モデル | 初回DL | 必要VRAM | ライセンス |
| --- | --- | --- | --- | --- |
| **軽量（初期値）** | `gemma-2-2b-jpn-it-q4f16_1-MLC` | 約1.4 GB | 約1,895 MB | Gemma 利用規約 |
| 標準 | `Qwen2.5-3B-Instruct-q4f16_1-MLC` | 約1.6 GB | 約2,505 MB | Apache-2.0 |
| 上級 | `Qwen3-4B-q4f16_1-MLC` | 約2.1 GB | 約3,432 MB | Apache-2.0 |

初期値を Google 公式の**日本語チューニング版 Gemma 2 2B** にしているのは、
日本語の資料を扱ううえで最も素直に動き、ダウンロードも最小のため。

### 動作条件

- **WebGPU 対応ブラウザが必須**（Chrome / Edge の最新版）
- HTTPS（または localhost）であること
- IndexedDB と Cache Storage が使えること
- モデルに応じた空きVRAM（RTX 4060 8GB なら3つとも動く）

> **CPUだけでの実行は提供していない。**
> GitHub Pages では COOP/COEP ヘッダーを設定できず `SharedArrayBuffer` が使えないため、
> WebAssembly のみでの推論は実用的な速度にならない。
> 「動いているように見えて終わらない」状態を避けるため、
> WebGPU が使えない場合は明確に案内して止める。

### 初回の流れ

1. 画面を開く。**この時点ではモデルをダウンロードしない。**
2. 「ブラウザ内で動くこと」「初回のみ通信が発生すること」などの説明を読む。
3. モデルを選ぶ（既定は軽量）。
4. 「**モデルを準備する**」を押す。ここで初めてダウンロードが始まる。
5. 進捗（％・取得済み容量・ファイル番号・初期化段階）が表示される。中止も可能。
6. 準備完了後、質問できるようになる。

2回目以降はブラウザのキャッシュから読み込むため、ダウンロードは発生しない。

### 回答の作り方（RAG）

```
質問 → 質問の正規化（「〜について教えて」等を除去）
     → 既存の全文検索（OR結合で関連度順）
     → 偏りの解消（各ファイルの1位 → 各ファイルの2位 … の順に拾う）
     → 資料の選定（Top K / 1ファイルあたり上限 / 重複排除 / 関連語の裏取り）
     → 隣り合うチャンクの連結 → 前後チャンクで文脈を補完
     → コンテキスト上限で安全に切り詰め
     → 根拠の強さを判定（★1〜5）── 弱ければここで止める
     → プロンプト構築 → ブラウザ内LLM → ストリーミング回答
     → 引用番号の検証 → 引用元表示
```

既定値: Top K = 5 ／ 1ファイルあたり 2 チャンク ／ 資料は最大 6,000 文字。
詳細設定で変更できる（通常は変更不要）。

#### 検索結果の偏りを抑える

スコア順に上から取ると、長いファイルが上位を独占し、
「別のファイルに書いてある答え」を取りこぼす。
そこで **各ファイルの1位 → 各ファイルの2位 …** という順に拾い直してから選定する。
各ラウンドの中ではスコア順を保つため、上位が不当に下がることはない。

選定後、同じファイルの**隣り合うチャンクは1件に連結**する。
分割位置はただの都合なので、別々の資料として渡すと同じ話が2件あるように見え、
引用番号も無駄に増えるため。

#### ハルシネーション（作り話）への対策

小さなローカルLLMは、資料に書かれていないことでもそれらしく書く。
**検索が外したときほど、もっともらしい嘘になりやすい。**

そこでモデルを呼ぶ前に、質問の語が資料にどれだけ現れるかを機械的に測り、
**5段階の根拠レベル**として開示する。

| 表示 | 意味 |
| --- | --- |
| ★★★★★ / ★★★★☆ | 質問の語のほとんどが資料に出てくる |
| ★★★☆☆ | 半分程度が一致する |
| ★★☆☆☆ | 一部だけ一致する |
| ★☆☆☆☆ 以下 | ほとんど、あるいはまったく一致しない |

**★★☆☆☆ を下回る場合は、AIを動かさずに次の文言を返す。**

```
同期済みナレッジから回答できませんでした。
```

言い回しの違いに強くするため、語の切り出しは助詞（の・は・を・に…）で区切ってから
2文字ずつに分けている。「経費精算の申請期限」を素朴に2文字ずつ切ると
「算の」「の申」のような、区切り方の都合でしかない組ができてしまい、
質問に答えている資料まで「一致しない」と誤判定してしまうため。

この最低ラインは詳細設定の「**回答する最低の根拠レベル**」で変更できる
（0にすると常に生成する。推奨しない）。

**資料は命令ではなく引用対象として扱う。**
資料本文に「これまでの指示を無視しろ」のような文があっても従わないよう、
システムプロンプトで明示し、資料内の区切りタグらしき文字列は無害化している。

#### 引用の表示

回答には `[1]` `[2]` のように資料番号が付く。番号は**クリックすると引用元へ飛ぶ**。

引用元を展開すると、資料ごとに次を確認できる。

- ファイル名
- チャンク番号（連結した場合は範囲。例: `チャンク 3〜4`）
- 関連度（検索スコア）
- **一致率**（質問の語のうち、その資料に出てきた割合）
- 回答で実際に引用されたか（「回答で引用」／「未引用」）
- 前後を補完したか / 一部のみか
- 抜粋
- **Driveで開く**リンク

モデルが**渡していない番号**（例: 資料は3件なのに `[7]`）を書いた場合は、
その番号を取り消し線で示し、回答の上に警告を出す。

### 会話履歴

- 保存先は **IndexedDB のみ**（localStorage には本文を置かない）
- 保存するのは 質問 / 回答 / 参照したチャンクID / モデルID / 日時
- **資料の本文は複製しない**（参照はIDだけ持ち、表示時に引き直す）
- アクセストークンは保存しない
- 「会話をこのブラウザに保存する」を外せば、再読み込みで消える
- 会話は30件まで。超えると古いものから消える

### モデルのキャッシュ

モデルは Cache Storage と WebLLM 専用の IndexedDB に保存される。
チャット画面の「**モデルキャッシュを削除**」で消せる（確認あり）。

> ナレッジ（同期済みの資料）とモデルのキャッシュは**別**。
> モデルを消してもナレッジは消えないし、その逆も同じ。

右側の「AIモデル」欄では次を確認できる。

- モデル名 / パラメータ数 / 量子化 / 必要VRAM / 最大コンテキスト
- ライセンスと、その全文へのリンク
- 配信元
- **前回の準備時間**（2回目以降が速いことを確認できる）
- 「**キャッシュ容量を確認**」で、保存済みモデルの実サイズとファイル数
- 検出できた GPU

### 診断（12分類）

右側の「診断」→「**診断を実行**」で、次の12項目を実際に確かめる。
外部への通信は発生しない。

| 分類 | 何を見るか |
| --- | --- |
| WebGPU | 利用可否と、使えない理由 |
| GPU | アダプター情報と `shader-f16` の有無 |
| IndexedDB | 接続と、同期済みの件数 |
| Cache Storage | 保存領域と空き容量（2GB未満なら注意） |
| モデル | 状態・読込済みモデル・初期化時間 |
| 全文検索 | 一時データを索引へ入れて**実際に引く**（終了後に必ず削除） |
| RAG | 資料選定を実データ無しで通し、偏り抑制と根拠判定が動くか |
| プロンプト防御 | 区切りタグの無害化と、命令に従わない指示が入っているか |
| コンテキスト長 | 設定値がモデルの上限に近づいていないか |
| 権限とトークン | 保存領域にトークンらしき値が残っていないか |
| ネットワーク | オンライン / オフライン（未取得なら対処も表示） |
| Google Drive | この画面のCSPが Drive API を許していないこと |

異常・注意のときは、**原因**と**対処**を同じ行に表示する。

### CSP について

チャットページだけ、次の2点を追加している。
**ナレッジ管理画面（`/apps/knowledge/`）の CSP は変更していない。**

```
script-src  … 'wasm-unsafe-eval' を追加
connect-src … huggingface.co / *.hf.co / raw.githubusercontent.com を追加
```

`'wasm-unsafe-eval'` は `'unsafe-eval'` とは別物で、
**WebAssembly のコンパイルだけ**を許可する。JavaScript の `eval()` は許可されないまま。
`'unsafe-inline'` / `'unsafe-eval'` は追加していない。
チャットページから `www.googleapis.com`（Drive API）へは接続できない設定にしてある。

### 既知の制約（先に知っておくとよいこと）

| 事項 | 内容 | 回避策 |
| --- | --- | --- |
| WebGPU 必須 | 非対応ブラウザ・端末では利用できない | ナレッジ管理画面の全文検索は使える |
| 初回1.4GB | 最初の準備に時間と通信量がかかる | 中止しても取得済み分は再利用される |
| モバイル | メモリ不足で初期化に失敗することがある | PCの Chrome / Edge を使う |
| 回答の速度 | 生成は端末のGPU性能に依存する（数十秒かかることがある） | 軽量モデルを選ぶ／最大トークン数を下げる |
| 資料の言い回し | 質問と資料で言葉が違いすぎると「回答できませんでした」になる | 資料で使われている語に近づけて質問する |
| 要約・横断的な質問 | 「この資料の要点は？」のような、語の重なりが乏しい質問は断られやすい | 対象を特定する語（ファイル名・見出し語）を含める |
| 小さなモデルの限界 | 根拠★が高くても、読み違いは起こりうる | 引用元を開いて原文を確認する導線を常に出している |
| 会話履歴 | 30件を超えると古いものから消える | 必要なものはコピーして保管する |
| 複数タブ | 同時に2つのタブでモデルを載せるとVRAMを二重に使う | 使わないタブを閉じる |

> **★の数は「資料との語の重なり」であって、「回答が正しい保証」ではない。**
> 最終的な確認は、必ず引用元の原文で行うこと。
> この画面は、そのための導線（Driveで開く／ナレッジ管理で検索）を常に出している。

## 8. より狭い権限（drive.file）へ切り替える

`drive.readonly` は Drive 全体の読み取り権限。もっと絞りたい場合の手順。

1. Google Picker API を有効化し、APIキーを作って制限をかける（1-6）。
2. OAuth同意画面のスコープに `https://www.googleapis.com/auth/drive.file` を追加する。
3. `apps/knowledge-src/src/config.js` を編集する。
   ```js
   export const SCOPE_MODE = 'file';
   export const AUTH_CONFIG = Object.freeze({
     clientId: GOOGLE_CLIENT_ID,
     pickerApiKey: 'AIza…',        // 必須
     pickerAppId: '000000000000',  // Cloudプロジェクト番号（必須）
   });
   ```
4. `npm run build` して配信する。
5. **別のブラウザプロファイル（またはシークレットウィンドウ）で確認する。**
   `drive.readonly` を許可済みのアカウントだと、広い権限が残っていて正しく判定できない。

### フォルダ作成に drive.file を使えるか（方式Bの検討結果）

不足フォルダの作成について、次の2方式を比較した。

| | 方式A（採用） | 方式B（保留） |
| --- | --- | --- |
| 通常の探索・同期・検索 | `drive.readonly` | `drive.readonly`（変えられない） |
| 作成時 | `drive` を一時的に追加要求 | Pickerで親を選ばせて `drive.file` |
| 権限の広さ | 広い（ただし保持は作成中のみ） | 狭い |
| 追加のGCC作業 | 同意画面にスコープ1つ追加 | Picker API有効化＋APIキー＋プロジェクト番号 |
| 現時点で動くか | **動く** | **動かない**（`pickerApiKey` / `pickerAppId` が未設定） |
| 既存の `TSAM AI` 配下へ作れるか | 作れる | **未測定**（下記） |

**測定できた事実**（`https://www.googleapis.com/discovery/v1/apis/drive/v3/rest`、revision 20260720）

- `files.create` は `drive` / `drive.appdata` / `drive.file` を受け付ける
- `drive.readonly` と `drive.metadata` は受け付けない
- 認証なしの `POST /drive/v3/files` は `401 required`、無効トークンでは `401 authError`（到達性は確認済み）

**測定できていない事実**

`drive.file` で、**アプリが作っていない既存フォルダ**（利用者が手で作った `TSAM AI` など）を
`parents` に指定して作成できるかどうか。これは資源単位の権限の話なので、
実際のGoogleアカウントでしか確かめられない。推測で決めず、下の手順で測ってから判断する。

#### 測定手順（実アカウントが要る・10分）

1. 1-6 の手順で Picker API を有効化し、APIキーとプロジェクト番号を設定する。
2. `src/config.js` を編集する。

4. **別のブラウザプロファイル**で開く（`drive` を許可済みのアカウントだと判定できない）。
5. Drive上で `TSAM AI / ローカルLLM` まで手で作り、`02_未整理` は作らない。
6. 「不足フォルダを作成」を押す。
7. F12 → Network で `POST /drive/v3/files` の応答を記録する。

| 応答 | 意味 | 判断 |
| --- | --- | --- |
| `200` | drive.file でも既存フォルダ配下に作れる | 方式Bへ切り替えてよい |
| `404 notFound` | 親フォルダがアプリから見えていない | 方式Bは不可。`'drive'` に戻す |

記録欄: 応答 ______ / `reason` ______ / 判断 ______

作成前に「現在の設定ではフォルダを作成できません。」と表示して止まる（Driveへは何も送らない）。

## 12. 既存機能への影響と制約

- **既存の `/apps/` のファイルは1つも変更していない。**
  ポータル、お気に入り、音声レコーダーには影響しない。
- OAuthクライアントIDは `apps/auth-config.js` が正本。knowledge側は自動生成で取り込む。
- ポータルのアプリ一覧（Googleスプレッドシート、`apps/app-store.js` の `SEED_APPS`）へは
  **未登録**。掲載する場合はシート側に `appUrl: knowledge/` の行を追加する。

### 現在の版で対象外

Googleスプレッドシート / Googleスライド / 画像OCR / 旧形式Word（.doc） /
埋め込みベクトル検索 / 要約・回答生成。
いずれも `src/future/README.md` に追加時の変更箇所をまとめてある。

### メンテナンス操作（ストレージタブ）

| 操作 | 内容 |
| --- | --- |
| 再同期（差分） | 更新されたファイルだけを取り直す |
| 検索インデックス再構築 | 保存済みチャンクから索引を作り直す |
| 不要データの整理 | 一覧に無いのに残っているチャンク・文書を削除する（通常は同期時に自動実行） |
| 全キャッシュ削除 | ブラウザ内のデータをすべて消す。**Drive上のファイルは消えない** |

ファイル単位の削除・再同期はファイル管理タブの各行にある。

### 共用PCで使う場合

抽出テキストはブラウザ内（IndexedDB）に**平文で**残る。
共用PCでは、作業のあとに必ず次のどちらかを行うこと。

1. ストレージタブの「全キャッシュ削除」を押す
2. ブラウザの「閲覧履歴データの削除」で「Cookieと他のサイトデータ」を削除する

アクセストークンはメモリ上にしか無いため、タブを閉じれば消える。
ログアウトを押すと、Google側の付与も取り消される。

### 既知の制約

- 抽出テキストはIndexedDBに平文で残る。共用PCでは上記の運用を入れる。
- IDトークンの署名検証はしていない（サーバーが無いため）。
  画面のアカウント表示は**表示専用**で、アクセス制御には使えない。
- CSPは `<meta>` 指定のため `frame-ancestors` が効かない。
  フレーム埋め込みを禁止する必要があれば配信側のヘッダーで設定する。
