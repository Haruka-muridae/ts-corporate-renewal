## A. Supabase 側の設定

### A-1. プロジェクト作成

- [ ] https://supabase.com/dashboard で新規プロジェクトを作成した
- [ ] リージョンは Northeast Asia (Tokyo) など利用者に近い場所を選んだ
- [ ] DBパスワードをパスワード管理ツールへ保存した（**リポジトリへ書かない**）

### A-2. 公開サインアップを無効化

**先にやること。** 有効なまま公開URLへ出すと、誰でもアカウントを作れる。

- [ ] Authentication → Sign In / Providers → Email → **Enable email signups** を **OFF**
- [ ] 他のプロバイダ（Google / GitHub 等）がすべて無効
- [ ] Anonymous sign-ins が **OFF**

失敗時: 項目名はUI改訂で変わる。「サインアップを許可するか」を意味する項目を探す。

### A-3. メールとパスワードの条件

- [ ] Enable Email provider = **ON**
- [ ] Confirm email = **ON**
- [ ] Secure email change = **ON**
- [ ] **Secure password change = ON**（重要。第A-3補足）
- [ ] Minimum password length = **8**

> **A-3補足: Secure password change**
> OFF だと、有効なセッションさえあれば現在のパスワードを知らずに変更できる。
> 「ログインしたままの端末を借りた人」がアカウントを乗っ取れる。
> 画面側では防げない。**必ず ON。**

### A-4. 二段階認証

- [ ] Authentication → Multi-Factor Authentication → TOTP を **Enabled**

### A-5. URL の登録

- [ ] Site URL = 本番のトップURL（例 `https://tsam-ai.com`）
- [ ] Redirect URLs に本番のコールバックを追加
      `https://tsam-ai.com/apps/auth-callback/**`
- [ ] ローカル確認用も追加
      `http://localhost:8000/apps/auth-callback/**`
- [ ] プロジェクトPages でも確認するなら追加
      `https://<user>.github.io/<repo>/apps/auth-callback/**`

失敗時: 登録漏れがあると、メール内リンクが Site URL へ飛ばされる。
`**` を忘れると `?flow=recovery` が付いたURLが一致しない。

### A-6. メール送信（本番運用前に必須）

- [ ] Project Settings → Authentication → SMTP Settings に自前SMTPを設定した
      （SES / SendGrid / Resend など）
- [ ] Email Templates を日本語化した（`{{ .ConfirmationURL }}` は残す）

失敗時: 既定の送信元は1時間あたり数通の制限。試験中に届かなくなったらこれ。

## B. 値の設定

### B-1. 取得

- [ ] Project Settings → API → **Project URL** を控えた
- [ ] Project Settings → API → **anon / public** キーを控えた

> **`service_role` を控えないこと。**
> 全データへの管理者権限を持つ。ブラウザへ渡すと全ユーザーのデータが読み書きされる。
> 見た目が anon と似ているので、表示ラベルを必ず確認する。

### B-2. 設定

- [ ] `apps/shared/supabase-config.js` の `url` に Project URL を貼った
- [ ] 同ファイルの `anonKey` に anon キーを貼った
- [ ] 前後の空白・引用符が入っていない（入っていても実行時に除去されるが、見た目で確認）

### B-3. 切り替わりの確認

- [ ] `python -m http.server 8000` を起動
- [ ] `http://localhost:8000/apps/login/` を開く
- [ ] **「動作確認用」の注意書きが消えている**
- [ ] 「パスワードを忘れた方」が**リンクになっている**

| 症状 | 原因 |
|---|---|
| 注意書きが消えない | 値が未設定。括弧内に理由が出る |
| 「service_role キーが設定されています」 | anon と取り違えた。**Supabase側でrotateすること** |
| 何も表示されない | コンソールを確認（構文エラー等） |

## C. 利用者の作成

### C-1. 招待

- [ ] Authentication → Users → **Invite user** で自分のアドレスを招待
- [ ] 招待メールが届いた
- [ ] リンクを開くと `apps/auth-callback/` を経由して画面が進む
- [ ] パスワードを設定できた

失敗時:
- リンクが Site URL へ飛ぶ → A-5 の登録漏れ
- 「期限切れ」→ メールのプレビュー機能が先に開いた可能性。再送する
- 別ブラウザで開いた → PKCE のため失敗する。同じブラウザで開き直す

## D. ログインの試験

### D-1. 正常系

- [ ] `apps/login/` でメールとパスワードを入力 → `apps/home/` へ遷移した
- [ ] 表示名が出ている
- [ ] 「ログインの有効期限」が表示されている

### D-2. 誤ったパスワード

- [ ] 「メールアドレスまたはパスワードが正しくありません。」と出る
- [ ] **登録済みかどうかが分からない文言**である（存在するアドレスと未登録アドレスで同じ）
- [ ] パスワード欄がクリアされている
- [ ] URL にパスワードが載っていない

### D-3. 未確認メール

- [ ] （Confirm email = ON の状態で）確認前のアカウントでログインを試す
- [ ] 「メールアドレスの確認が済んでいません」と出てログインできない

失敗時: ログインできてしまう場合は A-3 の Confirm email が OFF。

### D-4. セッション復元

- [ ] `apps/home/` でページを再読み込み → ログイン状態が保たれる
- [ ] ブラウザを閉じて開き直す → ログイン状態が保たれる
- [ ] 開発者ツール → Application → Local Storage を確認
  - [ ] `tsam-ai-session` に **パスワードが入っていない**
  - [ ] `tsam-ai-supabase-auth` にトークンが入っている（これは想定どおり）

### D-5. ログアウト

- [ ] `apps/home/` の「ログアウト」→ `apps/login/` へ戻る
- [ ] `tsam-ai-session` が消えている
- [ ] `tsam-ai-supabase-auth` も消えている
- [ ] **ブラウザの「戻る」を押しても home の中身が表示されない**

失敗時: 戻るで中身が見える場合は bfcache の再検証が効いていない。
`apps/shared/auth.js` の `watchAuthState` を確認。

## E. 二段階認証の試験

### E-1. 登録

- [ ] `apps/account/` →「二段階認証を設定する」
- [ ] QRコードが表示される
- [ ] 認証アプリで読み取れる
- [ ] 6桁を入力 → 「設定済み」になる

失敗時:
- QRが出ない → コンソールを確認。Supabase側でTOTPが無効の可能性（A-4）
- 「コードが正しくありません」→ 端末の時刻がずれていないか確認

### E-2. 二段階認証つきログイン

- [ ] ログアウトして、もう一度ログイン
- [ ] パスワードのあとに**二段階認証の画面が出る**
- [ ] この時点で `apps/home/` を直接開いても**入れない**
- [ ] 正しいコードを入れると home へ進む
- [ ] home に「二段階認証で確認済み」と出る

### E-3. 不正なコード

- [ ] 誤った6桁 → 「コードが正しくありません」
- [ ] 入力欄がクリアされる
- [ ] 何度誤ってもログインできない
- [ ] 5桁・7桁・英字は送信前に弾かれる

### E-4. 中断からの復帰

- [ ] コード入力画面で**ページを再読み込み**する
- [ ] **コード入力画面から再開される**（パスワードからやり直しにならない）

失敗時: パスワード画面に戻る場合は `resumePendingMfa` が働いていない。

### E-5. 解除

- [ ] コードを入力したセッションで `apps/account/` を開く
- [ ] 「二段階認証を解除する」が**押せる**
- [ ] 確認ダイアログのあと解除される
- [ ] 解除後は「未設定」になる

### E-6. AAL1 では解除できないこと（重要）

- [ ] 二段階認証を再登録する
- [ ] ログアウトする
- [ ] ログインし、**コードを入力する前に**（＝入力画面のまま）
      別タブで `apps/account/` を開く
- [ ] **home にも account にも入れない**ことを確認

失敗時: 入れてしまう場合は AAL 判定が効いていない。**先へ進まないこと。**

## K. 判定

すべて `[x]` になったら Phase 4 の条件を満たす。

`[!]` が残っている場合、**Phase 4（`/apps` への認証ガード適用）へ進まない。**
ガードは「認証が確実に動く」ことが前提の機能であり、
動作が不確かなまま適用すると、正規の利用者が締め出される。
