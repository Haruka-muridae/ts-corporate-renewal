# 人手確認リスト（ブラウザ録音アプリ）

自動テスト（[recorder.spec.mjs](./recorder.spec.mjs)）で確認できない項目をここに残す。
自動化できたものは書かない。**「まだ書いていない」ではなく「自動化できない」ものだけ**を載せる。

実行: `npm run test:e2e`（12件） / `npm run test:e2e:soak`（30分・別実行）

---

## 1. 実際のマイクで録れているか

**なぜ自動化できないか**: E2E は Chromium の偽デバイス（正弦波）を使う。
これは「音声の経路が繋がっている」ことは示すが、**実マイクのゲイン・ノイズ・
サンプルレートの組み合わせ**までは再現しない。

**確認すること**: 実マイクで1分録音し、プレビューで自分の声が聞き取れること。

---

## 2. タブを裏へ回したときに録音が続くか

**なぜ自動化できないか**: Playwright からはタブの表示・非表示を実際に切り替えられない。
自動テスト（手順7）は `document.hidden` を差し替えて `visibilitychange` を投げており、
**ハンドラが警告を出すこと**しか確認していない。「本当に録音が継続するか」は
ブラウザとOSの省電力挙動に依存するため、実機で見るしかない。

**確認すること**: 録音中に別タブへ移動して5分放置 → 戻って経過時間が進み続けていること。
停止後のプレビューに、裏にいた間の音声が入っていること。

---

## 3. サンプルレートが規格外の環境

**なぜ自動化できないか**: 偽デバイスは 48,000Hz 固定で、Chromium 起動フラグでも
32,000Hz などにはできない。`isSupportedSampleRate` の false 経路（§FR-04）を
実機で通せない。

**確認すること**: Windows のサウンド設定でマイクを 32,000Hz などにして録音開始 →
「OSのサウンド設定で44.1kHzまたは48kHzに変更してお試しください」が出ること。

---

## 4. 空き容量の下限（開始前250MB・録音中100MB）

**なぜ自動化できないか**: `navigator.storage.estimate()` の quota はブラウザが決める値で、
テストから小さく見せる手段がない（テスト機では 3GB 前後を返す）。

**確認すること**: ディスクをほぼ埋めた状態で録音開始 → 開始が止まり、
「不要なファイルを削除してから」の案内が出ること。

---

## 5. 90分の実録音 → **自動化した**（`npm run test:e2e:soak90`）

[soak-90min.spec.mjs](./soak-90min.spec.mjs) が、注入なしの本物の90分で
自動停止・残り5分の予告・約86MB・プレビューの長さ・8MBチャンクでの分割送信までを見る。

**人手に残るのは、本物の Drive への90分保存だけ**（下の §7 と同じ理由）。
自動テストは Drive を差し替えているため、「86MB がチャンクに分かれて送られること」までしか示せない。

---

## 6. 見た目

自動化した分（[a11y.spec.mjs](./a11y.spec.mjs)）:

- 320 / 375 / 768 / 1024 / 1440px で横スクロールが出ないこと
- キーボードでの到達と Enter 操作
- ラベルと `aria-describedby` の結び付き
- `role="status"` / `role="alert"` / `role="progressbar"`
- `prefers-reduced-motion: reduce` で点滅が止まること（止めない設定では点滅すること）

**人手に残るもの**:

- **配色のコントラスト比**。機械で測れる形にはしていない（色の妥当性は目で見る）。
- **フォーカスリングが実際に見えるか**。フォーカスが当たることは確認しているが、
  「見えるか」は見た目の問題。
- 上記5幅での**レイアウトの妥当性**。横スクロールが出ないことと、
  読みやすい配置であることは別物。

---

## 7. Google Drive への実保存

**なぜ自動化できないか**: 実 OAuth の同意画面は自動化できないし、自動化すべきでもない。
テストで本物の Drive へ書き込むのも避ける。

自動テスト（[drive.spec.mjs](./drive.spec.mjs)）は GIS と Drive API を差し替えており、
**アプリ側の分岐（フォルダ解決・連番・分割送信・後片付け・エラー分類）は本物が動く。**
差し替えているのは「トークンの出どころ」と「Drive の中身」だけ。
したがって実機で見るべきは、**本物の Google が想定どおり応答するか**に絞られる。

**確認すること**（`python -m http.server 8000` で開くこと。承認済みオリジンが 8000 番のため）:

1. 「連携する」→ 同意画面が出て、許可するとメールアドレスが表示される
2. 保存 → マイドライブに「TSAM AI ＞ Voice Recorder」が作られ、MP3 が入る
3. Drive 上で再生できる。共有設定が付いていない（「リンクを知っている全員」になっていない）
4. 同じ名前でもう一度保存 → `_2` が付く
5. **`Location` ヘッダーが読めること**（読めないと「保存に失敗しました」になる）。
   自動テストではこのヘッダーを実物と同じ形で返しているが、本物での確認は実機のみ。
6. 8MB を超える録音（約9分以上）で、進捗が複数回更新されること（分割送信の確認）

> **60分を超える録音では、停止後に必ず「連携しなおす」が要る。**
> Google のアクセストークンは約1時間で切れ、録音の上限（90分）より短い。
> 先に連携して90分録音すると、停止した時点で「認証の期限切れ」になっている。
> 録音は残っているので、連携しなおせばそのまま保存できる（録り直しは不要）。
> これは不具合ではなく §FR-02 の想定どおりの動きだが、**知らないと戸惑う**ので
> 実機で確認するときは覚えておくこと。
