# 名刺スキャナ

名刺を撮影して文字を読み取り、Google スプレッドシートへ1行ずつ蓄積するアプリ。
1件につき表面（必須）と裏面（任意）の2枚を登録できる。

生成AIは使用していない。文字認識は Google ドライブが画像を Google ドキュメントへ
変換するときの OCR を利用する。したがって API キーも Cloud の課金も不要で、
必要な権限は voice-recorder と同じ `drive.file` スコープだけである。

## 処理の流れ

```
表面を撮影（必須）
裏面を撮影（任意）
  → 面ごとに 縮小(canvas) → Drive へ Google ドキュメントとして変換アップロード(OCR)
     → テキストをエクスポート → 一時ドキュメントを削除
  → 面ごとに正規表現で項目に振り分け → mergeParsed() で1件へ統合
  → 画面で確認・修正 → Sheets へ1行追記
```

OCR は表面 → 裏面の順に実行する。裏面の OCR が失敗しても表面の結果だけで先へ進む
（裏面は補助であり、失敗を全体の失敗にしない）。ただし 401 だけは例外で、
上位の再認可へ通してから両面をやり直す。

一時ドキュメントは中間生成物なので必ず削除する。エクスポートが失敗した場合でも
削除は実行する（`drive-ocr.js` の `try / finally`）。削除に失敗しても全体は
失敗にせず、ログに残して続行する。

## 保存先

```
マイドライブ/
└─ TSAM AI/
   └─ 名刺スキャナ/
      ├─ 名刺台帳（表裏対応 v3）
      ├─ 名刺画像/
      │  ├─ 表面画像/
      │  └─ 裏面画像/
      └─ 添付ファイル/          ← 初回の添付保存時に作る（今は作られない）
```

初回利用時に、足りないフォルダだけを作る。既にあるものは再利用する。

`添付ファイル` は `ensureFolderTree()` では作らない。現時点で使う機能が無く、
空のフォルダを先回りで置いても「何のためにあるのか分からないフォルダ」が
残るだけだからである。実際に添付を保存するときに `ensureAttachmentFolder()` で
作る（添付機能そのものは未実装なので、現在この関数を呼ぶ箇所は無い）。

### localStorage はキャッシュであって正本ではない

正本は Drive 上の実体で、`localStorage` は「前回そこにあった」という手がかりに
過ぎない。したがって空でも、消えても、別端末・別ブラウザ・シークレットモード・
サイトデータ削除後でも動作する。

キーはすべて v3。**v2 以前のキーは読み書きも削除もしない。**

```
tsam-card-scanner-root-folder-id-v3
tsam-card-scanner-app-folder-id-v3
tsam-card-scanner-image-folder-id-v3
tsam-card-scanner-front-image-folder-id-v3
tsam-card-scanner-back-image-folder-id-v3
tsam-card-scanner-attachment-folder-id-v3
tsam-card-scanner-spreadsheet-id-v3
```

入れてよいのはフォルダID・ファイルIDだけ。IDは秘密情報ではない。
**アクセストークンは絶対に入れない**（認可は `../drive-auth.js` がメモリで持つ）。

### 解決の3段階

フォルダも台帳も、必ずこの順で解決する（`drive-folders.js`）。

**段階1 … キャッシュを `files.get` で検証する**

IDだけでなく、名前・親・種別・未削除まで確かめる。IDが生きていても別の場所へ
移動されていたら使わない（気付かないまま別の場所へ保存するのを防ぐ）。

| 結果 | 扱い |
| --- | --- |
| 期待どおり | そのまま使う |
| 404（削除済み）/ 403（権限なし） | キャッシュを**削除**して段階2へ |
| `trashed=true` / 名前・親・mimeType の不一致 | キャッシュを**削除**して段階2へ |
| 401 | キャッシュは**残す**。再認可してやり直す |
| ネットワークエラー / 5xx | キャッシュは**残す**。一時障害で消すと復旧が壊れる |

**段階2 … Drive を検索する**

名前・親フォルダID・mimeType・`trashed=false` を**必ず全部**条件に含める。
親を外すと、別の場所にある同名フォルダを掴んでしまう。
見つかればIDをキャッシュへ書き戻す。**`localStorage` が消えただけなら、
ここで必ず自動復旧する**（別端末・別ブラウザでも同様）。

**`TSAM AI` が複数見つかった場合だけは自動で選ばない。** 更新日時が新しいものが
正しいとは限らず（古い方に実データが入っていることもある）、黙って選ぶと利用者が
気付かないまま別のフォルダへ保存し続けることになる。段階3の選択画面へ進む。

配下のフォルダは親が特定済みなので、複数あれば新しい方を採用する。

**段階3 … 見つからなければ作る**

段階2でも見つからなければ、その名前でフォルダを作る。
**`localStorage` が空というだけでは作らない。** 段階2の検索を必ず通し、
本当に存在しないと分かってから作る。

例外は `TSAM AI` が複数見つかった場合だけで、このときは候補一覧を出して
利用者に選んでもらう（Drive で中身を確認できるリンクを添える）。
候補から選ばれたフォルダは、採用前に次をすべて確認する
（`adoptCandidateRootFolder()`）。ひとつでも欠ければ採用しない。

1. `files.get` で実際に読めること
2. mimeType が Drive のフォルダであること、ゴミ箱に入っていないこと
3. 名前が `TSAM AI` であること
4. マイドライブ直下にあること（親がちょうど1つ）

### Google Picker は使わない

このアプリ群は、すべて自分で作る `TSAM AI` 配下だけを使う前提である。
したがって Drive 全体から任意のフォルダを選ばせる仕組み（Google Picker）は持たない。

`drive.file` スコープで見えるのは「このクライアントIDが作成したファイル」だけで、
別のOAuthクライアントIDのアプリが作った `TSAM AI` や、利用者が Drive の画面で
手作りした `TSAM AI` は検索に出てこない。その場合は同じ名前で新しく作る。

Picker を入れれば取り込めるが、そのために Google Picker API の有効化・
APIキーの発行と管理・CSP の追加・保守対象の増加が必要になる。
現状それに見合う利点が無いため入れない。本当に必要になった時点で追加する。

### 台帳の版について

14列（片面）→ 24列（表裏）→ 36列（拡張）と列が変わっている。
版ごとに台帳名と `localStorage` のキーを完全に分けてある。

| 版 | 台帳名 | キー |
| --- | --- | --- |
| 14列 | `名刺台帳` | `tsam-card-scanner-spreadsheet-id` |
| 24列 | `名刺台帳（表裏対応）` | `tsam-card-scanner-spreadsheet-id-v2` |
| 36列 | `名刺台帳（表裏対応 v3）` | `tsam-card-scanner-spreadsheet-id-v3` |

**旧台帳・旧キーは参照も削除もしない。** 列を移行する処理も、見出しの不一致を
検出して分岐する処理も持たない（持つと、ズレたまま追記する事故が起きうる）。
旧データが必要な場合は、利用者が Drive 上で旧台帳を直接開く。

### 列（全36列 / 範囲 `A:AJ`）

列順は `fields.js` の `COLUMN_DEFS` が唯一の定義で、`SHEET_HEADERS` と
`SHEET_RANGE` はそこから生成される。**列順を別の場所で組み立て直さないこと。**

```
 1 カードID        2 登録日時        3 更新日時       4 OCR実行日時   5 会社ID
 6 会社名          7 部署名          8 役職           9 氏名         10 氏名かな
11 メインメールアドレス  12 メールアドレス2  13 メールアドレス3  14 その他メールアドレス
15 電話番号        16 携帯電話       17 FAX          18 郵便番号     19 住所
20 Webサイト       21 SNS・その他URL  22 タグ         23 担当者       24 備考
25 表面画像URL     26 裏面画像URL
27 表面OCR         28 裏面OCR        29 統合OCR
30 OCRエンジン     31 OCR信頼度
32 表面画像ハッシュ 33 裏面画像ハッシュ
34 名刺の向き      35 言語           36 重複判定キー
```

空の項目でも列は必ず出力し、36 列を固定する。

列の種類は `kind` で分ける。`field` は入力欄を作る項目、`emails` は4列へ展開される
特別扱い、`auto` はアプリが決める項目（入力欄を作らない）。

### カードID

`CARD-YYYYMMDD-XXXXXX`（例 `CARD-20260727-000001`）。保存時に採番する。
将来の更新・削除・CRM連携で主キーとして使える設計にしてある。

同一日の連番で、既存台帳のカードID列を読んで最大値 + 1 を求める。
**「読む → 候補を作る → もう一度読んでまだ空いているか確かめる」**という手順を踏み、
間に他の端末が保存していたら採番し直す（`allocateCardId()`、最大5回）。
それでも確定しなければ `CARD_ID_CONFLICT` として利用者に知らせる。

カードIDは画像のファイル名にも入れるので、台帳の行から画像を辿れる。

#### 採番は原子的ではない（既知の限界）

**この方式は重複を減らすだけで、原子的な排他制御ではない。**
Sheets API には条件付き書き込みもトランザクションも無く、ブラウザだけで
「読んで書く」を不可分に行う手段が存在しない。したがって次の競合が理論上残る。

```
端末A: 読む(最大=5) → 候補 000006 → 再読み込みで確認(空き) → 追記
端末B: 読む(最大=5) → 候補 000006 → 再読み込みで確認(空き) → 追記
          ↑ AとBがこの窓の中で交差すると、両方が 000006 を書く
```

窓は「確認してから追記するまで」の数百ミリ秒で、実運用（1人が1件ずつ手で撮る）
ではまず起きない。**MVPとしてこれを許容する。**

そのうえで、起きたことは必ず検出する。追記後に `verifyCardIdUnique()` が
カードID列を読み直し、同じIDが複数行あれば重大警告を表示する。

- 何行目にあるかを画面に出し、台帳を開いて確認するよう促す
- **既存行の自動削除も上書きもしない。** どちらを残すかは中身を見ないと決められず、
  機械的に消すと取り返しがつかない
- 検査そのものが失敗しても保存は成功しているので、全体は失敗にしない

厳密な一意性が必要になった段階で、採番を担うサーバー（Apps Script の
`LockService` など）を挟む形へ置き換える。その場合も差し替えるのは
`allocateCardId()` の中身だけで済むようにしてある。

### 更新日時 / OCR実行日時

- **更新日時** … 新規保存では登録日時と同じ値。`buildRow()` は `createdAt` と
  `updatedAt` を別引数で受けるので、将来の編集保存では登録日時を保ったまま
  ここだけ更新できる（編集保存機能そのものは未実装）
- **OCR実行日時** … OCR が通った時刻。再OCRしたときはここだけ更新する構造。
  OCR していなければ空

### OCRエンジン

`metadata.js` の `OCR_ENGINE` に定数として1か所だけ定義してある（現在は
`Google Drive OCR` 固定）。各処理へ文字列を直書きしないこと。

### OCR信頼度（アプリ独自の指標）

**これは Google が返す公式の信頼度ではない。** Drive の OCR は数値を返さないため、
「どの項目を、どれだけ確かな手がかりで取れたか」をアプリ側で点数化したものである。
画面にもその旨を明記している。

主要6項目 — 会社名 / 氏名 / メインメールアドレス / 電話番号 / 携帯電話 / 住所 —
の平均を四捨五入し、0〜100の整数で保存する。

| 1項目あたり | 点数 |
| --- | --- |
| 利用者が手で直した | 100（人が確認した値なので最も確か） |
| 値が空 | 0 |
| 自動入力の根拠が無い（`matched=false`） | 0 |
| 根拠あり・`confidence: high` | 100 |
| 根拠あり・`confidence: medium` | 70 |
| 根拠あり・`confidence: low` | 40 |

**空欄も母数に含める（6項目固定の母数）。** 含めない方式だと「1項目しか取れなかったが
それがメールだったので100点」となり、読み取り不良の名刺が満点になってしまう。
固定母数なら「6項目のうちどれだけ拾えたか」がそのまま数値へ表れる。

氏名は根拠となるパターンが存在せず常に `matched=false` なので、既定では0点になる。
利用者が確認して直せば100点になり、確認済みであることが数値に反映される。

### 画像ハッシュ

表面・裏面それぞれの SHA-256 を16進小文字64文字で保存する。裏面が無ければ空。

対象は**実際に保存する縮小後のJPEG**（`shrinkToJpeg()` の結果の Blob）。
元ファイルではなく保存対象を取るので、同じ名刺を同じ設定で撮り直せば
同じハッシュになる。

`crypto.subtle.digest('SHA-256', ...)` を使うが、`crypto.subtle` は
**セキュアコンテキストでしか存在しない**。`http://localhost` は該当するが
`http://192.168.x.x` は該当しない。実機をLAN経由で開いた場合に備えて、
`metadata.js` に純JavaScript版のフォールバックを持たせてある（結果は同一）。

### 名刺の向き

表面画像の縮小後の幅と高さから決める。

| 条件 | 値 |
| --- | --- |
| 幅 / 高さ ≧ 1.1 | `横` |
| 高さ / 幅 ≧ 1.1 | `縦` |
| それ以外 | `正方形` |

表面は必須なので、表面が無いまま保存されることはない。

### 言語

OCRテキストからの簡易判定（`detectLanguage()`、純粋関数）。
保存値は `日本語` / `英語` / `中国語` / `韓国語` / `混在` / `不明`。

- メール・URL・電話番号・郵便番号・記号は**判定の母数から除く**（どの言語でも
  同じ形をしており、手がかりにならない）
- **ひらがな・カタカナが1文字でもあれば日本語を優先する。** 漢字だけで判定すると
  日本語の名刺が中国語になってしまう
- ハングルがあれば韓国語、かな無しの漢字のみなら中国語、ラテン文字だけなら英語
- 2種類以上がそれぞれ2割以上を占めるなら混在
- 比率を出すとき、CJK側には重みを掛ける。文字数をそのまま比べると必ずラテン文字に
  偏るため（「株式会社テスト」7文字 対 "TEST Corporation" 16文字）
- 判定に使える文字が無ければ不明

精密な言語判定ライブラリは追加しない。名刺に必要な粒度はこれで足りる。

### タグ / 担当者

どちらも確認画面の自由入力で、初期値は空。自動抽出はしない。

タグはカンマ（半角・全角）でも改行でも区切れる。保存時に前後の空白を除き、
重複を落とし、`タグ1, タグ2` の形（カンマ + 半角スペース）へ揃える。

### 会社ID

`COMPANY-<正規化した会社名のSHA-256の先頭12文字>`（例 `COMPANY-a1b2c3d4e5f6`）。
フォームには出さない自動項目。

正規化は「全角英数記号を半角へ」「空白をすべて除去」「英字を小文字へ」。
したがって `株式会社 テスト` と `株式会社テスト` は同じIDになる。
法人格（株式会社 / Inc. など）は**あえて落とさない**。落とすと
`テスト株式会社` と `テスト合同会社` が同じIDになってしまう。

会社名が空なら会社IDも空。同じ会社名なら端末やブラウザが違っても同じIDになる。
将来これを会社マスタの参照へ置き換えるときは、`buildCompanyId()` だけを差し替える。

### メールアドレス（複数件）

内部では `values.emails`（配列）と `values.primaryEmail`（**実値**）で持つ。
インデックスで持つと、途中の1件を削除したときにメインの指す先がずれるため。

- 列へは `emailsToColumns()` で展開する。メインが先頭、4件目以降は
  「その他メールアドレス」へ改行区切りでまとめる
- 列から戻すのは `columnsToEmails()`。重複判定でのみ使う
- 確認画面では追加・削除・修正ができ、ラジオでメインを選ぶ。
  1件しか無いときはラジオを固定し、メインを消した場合は残りの先頭が自動でメインになる

### 画像リンク

`表面画像URL` `裏面画像URL` は `=HYPERLINK()` としてクリック可能にする。
表示文言は `表面画像を見る` / `裏面画像を見る`。裏面が無ければ空欄。

数式として入れたいので、**この2列だけは `escapeCellText()` を通さない。**

### 数式化の防止と文字数制限

行全体を `valueInputOption=USER_ENTERED` で送っているため、`=` `+` `-` `@` で
始まるセルは数式として解釈される。OCR 本文がこれに当たると `#NAME?` になるので、
`escapeCellText()` が先頭にアポストロフィを付ける。

対象は次の列。表面OCR / 裏面OCR / 統合OCR / 重複判定キー / 表面画像ハッシュ /
裏面画像ハッシュ / カードID / 会社ID / タグ / 担当者、および他のすべての入力項目。

切り詰めの上限は列の性質で分ける。

| 対象 | 上限 | 定数 |
| --- | --- | --- |
| OCR本文3列 | 50,000文字（Sheets のセル上限） | `CELL_MAX_LENGTH` |
| それ以外の文字列 | 1,000文字 | `SHORT_CELL_MAX_LENGTH` |

短い列まで50,000文字を許すと、異常に長い値が入っても気付けない。

### 重複判定

`重複判定キー` は次の優先順位で1本だけ作る（`buildDuplicateKey()`）。

1. `email:<メインメール>`
2. `mobile:<携帯電話の数字だけ>`
3. `company+name:<会社名>|<氏名>`

既存行との突き合わせは、次のいずれかに当たれば重複とみなす。
表示は優先度の高い順に並べる。

| 優先 | 判定 | 深刻度 |
| --- | --- | --- |
| 1 | カードID一致 | **重大**。通常は起きない。採番の異常を疑う |
| 2 | 表面画像ハッシュ一致 / 裏面画像ハッシュ一致 | 警告 |
| 3 | メール一致（4列すべてとの交差判定） | 警告 |
| 4 | 携帯電話一致（重複判定キー経由） | 警告 |
| 5 | 会社名 + 氏名一致（重複判定キー経由） | 警告 |

メールは**交差判定**する。候補の全メールと既存行の全メールに1件でも共通があれば
一致とみなす。「メインは違うが2件目が同じ」をキー一致だけでは拾えないため。

画像ハッシュは表裏を入れ替えた場合も拾う（候補の表面が既存の裏面と一致、など）。
どの面が一致したかは `reason` に入れて画面へ出す。

重複が見つかっても**保存は止めない**。同じ相手から名刺を再度もらうこと自体は
正常な出来事なので、警告を出して判断は利用者に委ねる。
カードID一致のときだけ、警告の見た目を変えて強く出す。

### 表面と裏面の統合

`mergeParsed(front, back)` が1件へまとめる（純粋関数）。

- 表面を優先し、表面が空の項目だけ裏面で補完する。
  補完した項目は根拠があっても `matched` を false にし、「要確認」を出す
  （どちらの面から来た値かは画面から見えないため）
- 両面に値があって内容が違う場合は**自動で上書きしない**。表面の値を採ったうえで
  `conflicts` に記録し、画面が両方を並べて「裏面の値を使う」ボタンを出す
- メールは単一値ではないので競合させず、和集合にする。
  裏面にしか無いアドレスがあった場合は、追加した旨の案内だけ出す

## この方式の限界（確認画面が必須である理由）

OCR が返すのは**構造のない一続きのテキスト**であり、レイアウト情報は失われる。

| 取れるもの | 理由 |
| --- | --- |
| メール、URL、郵便番号、電話/FAX | 書式が決まっており、正規表現で安定して取れる |
| 法人格を含む会社名 | 「株式会社」などの手がかりがある |

| 安定しないもの | 理由 |
| --- | --- |
| **氏名・氏名かな・部署・役職** | 名刺のレイアウトは会社ごとに違い、テキストの並び順だけでは「営業本部」「部長」「山田太郎」を確実に判別できない |

したがって「自動入力してそのまま保存」は成立しない。
**確認・修正画面は省略可能な飾りではなく、この方式の必須要素**である。

画面はこの限界を隠さない。

- `matched` が `false` で値が入っている項目には「要確認」を表示し、
  `aria-describedby` で理由を結びつける
- 氏名・氏名かな・部署名・役職については、値の有無にかかわらずフォーム上部に
  「氏名・氏名かな・部署名・役職は読み取り精度が低いため、必ずご確認ください。」と一度だけ案内する
- 氏名・氏名かなは positive なパターンではなく除外条件で選ぶため、値が入っても
  `matched` を `false` のままにする（根拠が弱いことを画面に出すため）
- 裏面から補完した項目も `matched` を `false` にする
  （どちらの面から来た値かは画面から見えないため）

推測が当たったように見せる UI にはしない。

## `card-parser.js` の抽出ルール

読み取り漏れが出たときは、この表の該当箇所を直す。
正規表現はすべて `card-parser.js` の冒頭に名前付き定数としてまとめてある。

高確度のものから順に取り、**一度使った部分は後続の判定から除外**する
（電話番号として消費した文字列を住所側で拾わない）。消費済みの管理は
行インデックスと文字範囲の集合で行い、破壊的な文字列置換はしない。

### 正規化（この順）

1. 改行を `\n` に統一し、各行を trim、空行を除去
2. 全角英数記号（U+FF01–FF5E）を半角へ。全角スペースは半角スペースへ
3. 各種ハイフン（U+2010–2015 / U+2212 / U+30FC）を `-` へ統一。
   ただし**数字に挟まれた位置だけ**に限定する（`サービス` を `サ-ビス` にしないため）
4. `TEL.` `TEL:` `Tel／` のような表記ゆれを空白へ揃える

### 項目ごとのルール

| 項目 | 定数 | ルール |
| --- | --- | --- |
| メール | `EMAIL_RE` | **見つかった全件**を小文字化し、出現順で `emails` へ。1件目を初期のメインにする |
| Webサイト | `URL_RE` / `KNOWN_TLDS` | メールとして採用済みの範囲は除外。末尾のラベルが既知のTLDのものだけ採用（`Co.Ltd` をURLと誤認しないため）。`http` `www` `co.jp` `com` を含むものを優先。SNS 系ホストは除外する |
| SNS・その他URL | `SOCIAL_HOST_RE` | x / facebook / instagram / linkedin / note / YouTube など既知のホストのURL。複数あれば改行区切りで全件残す。会社サイトの欄がSNSで埋まるのを防ぐための分離 |
| 郵便番号 | `POSTAL_WITH_MARK_RE` / `POSTAL_BARE_RE` | 〒付きを優先。〒が無い場合は前後が数字・ハイフンでないことを条件にする（`03-1234-5678` の一部を拾わないため） |
| 電話 / 携帯 / FAX | `PHONE_RE` / `PHONE_LABELS` | 行単位ではなく**ラベルと番号のペア**で走査。直前に複数ラベルがある場合は番号に最も近いものを採用。`FAX` → fax、`携帯`/`Mobile`/`M.`/`Cell` または `070/080/090` 始まり → mobile、それ以外とラベル無し → tel。同種の2件目以降は備考へ |
| 会社名 | `COMPANY_RE` | 法人格を含む行から、消費済みの部分を除いた残り |
| 住所 | `PREFECTURE_RE` / `STREET_RE` / `BUILDING_RE` | ①郵便番号と同じ行の後ろ ②郵便番号の次の行 ③都道府県または番地を含む行。直後の行が `ビル/階/棟/号室/F` を含む短い行なら連結する |
| 役職 | `TITLE_RE` | キーワードを含む行 |
| 部署 | `DEPARTMENT_RE` | キーワードを含み、会社名・役職として採用していない行。役職と同じ行（`営業部 部長`）は分割する |
| 氏名 / 氏名かな | `NAME_CHARS_RE` / `KANA_ONLY_RE` | 他項目に採用されておらず、数字・`@`・`/` を含まず、漢字/ひらがな/カタカナのみで2〜10文字（`姓 名` のように空白1つは可）、会社名・部署・役職のキーワードを含まない行を**候補として全部集めてから**、漢字を含むものを氏名、かなだけのものを氏名かなに振り分ける。上から1件目を氏名にすると、氏名の上に載ったふりがなを氏名として採ってしまうため。漢字の候補が無ければ、かなの先頭を氏名にする。候補が0件なら**空文字**（適当な行を入れない） |
| 備考 | — | どの項目にも振り分けられなかった行と、2件目以降の電話番号 |

### 動作確認の方法

`card-parser.js` は純粋関数だけで構成してあるため、ブラウザのコンソールから
単体で試せる。この性質を壊さないこと（DOM や fetch を持ち込まない）。

```js
const { parseCardText, mergeParsed } = await import('/apps/card-scanner/card-parser.js');

const front = parseCardText('株式会社サンプル商事\nTEL 03-1234-5678 FAX 03-1234-5679');
const back = parseCardText('info@sample.co.jp\nTEL 03-9999-0000');

console.log(front.values);
/* 統合結果と、表裏で食い違った項目 */
console.log(mergeParsed(front, back));
```

## 精度を上げる撮影のコツ

- **影を作らない。** 手やスマートフォン自体の影が名刺に落ちると読み取れなくなる
- **名刺を画面いっぱいに写す。** 撮影枠は名刺と同じ 91:55 の比率にしてある
- **斜めにしない。** 正面から、名刺の辺が枠の辺と平行になるように
- 明るい場所で撮る。暗い場所ではピントが合わず細かい文字が落ちる
- 光沢のある名刺は、照明の映り込みを避ける角度にする

長辺は 1600px へ縮小している（`capture.js` の `DEFAULT_MAX_EDGE`）。
OCR の精度は解像度に効くため、**この値を下げないこと。**
小さくすると部署名やメールアドレスのような細かい文字が落ちる。

## 動作しないときの対処

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 「このアプリは現在準備中です」 | クライアントIDが未設定 | `apps/auth-config.js` を確認する |
| 「認証画面を開けませんでした」 | ポップアップブロック | ブラウザの設定で許可する |
| 「認証画面が閉じられたため…」 | 利用者が閉じた | もう一度押す。画像と入力内容は保持されている |
| 「Google Drive APIが有効になっていません」 | Drive API が未有効 | Google Cloud Console で有効化する |
| 「スプレッドシートへの保存機能が有効になっていません」 | **Sheets API が未有効** | Google Cloud Console で Sheets API を有効化する |
| 「文字を読み取れませんでした」 | OCR の結果が空 | 明るい場所で、名刺を枠いっぱいに、斜めにせず撮り直す |
| 「読み取り結果を取得できませんでした」 | export が 404 | もう一度読み取る |
| 「Googleドライブの保存容量が不足しています」 | Drive の空き容量 | 空き容量を確保する |
| 「裏面の読み取りに失敗しました」 | 裏面のOCRだけ失敗 | 表面の結果は残っている。裏面の内容を手で足すか、裏面を撮り直してもう一度読み取る |
| 「表面の画像を選んでください」 | 裏面だけ選んでいる | 表面は必須。表面を撮影する |
| 氏名が空のまま | 候補が見つからなかった | 手で入力する。適当な行を入れない設計になっている |
| 氏名かなの欄に氏名が入る | かな表記だけの名刺 | 漢字の候補が無い場合、かなを氏名として扱う。手で直す |
| 部署名と役職が入れ替わる | レイアウト依存で判別できない | 手で直す。この方式の限界（上記参照） |
| OCR列が `#NAME?` になる | 数式として解釈された | `escapeCellText()` の対象漏れ。`sheets-client.js` を確認する |
| 「保存先の確認」が出る | `TSAM AI` がキャッシュにも検索にも無い | 既存があれば選択、無ければ新規作成。**別端末でもキャッシュが無いだけなら検索で自動復旧するため、通常この画面は出ない** |
| 「TSAM AI が複数見つかりました」 | 同名フォルダが2つ以上ある | Driveで中身を確認し、使う方を選ぶ。不要な方は Drive 上で整理する |
| 選択したフォルダが採用されない | 名前・場所・種別が条件外 | マイドライブ直下の `TSAM AI` という名前のフォルダを選ぶ |
| 「カードIDの採番が確定しませんでした」 | 他端末と同時に保存した | 少し待ってもう一度保存する |
| OCR信頼度が低い | 氏名は根拠が無く既定で0点 | 内容を確認して直せば100点として再計算される |
| 台帳が2つできた | 別アカウントで使った、または台帳を削除した | 不要な方を削除し、`localStorage` の `tsam-card-scanner-spreadsheet-id-v3` を消す |

デバッグログは URL に `?debug=1` を付けると `console.debug` へ出る。

**出さないもの**: アクセストークン / メールアドレス /
画像の内容 / OCR の本文 / フォルダID・ファイルID。

**出すもの**: 件数・真偽値・エラーコードなどの要約。
画面に出さない自動項目（カードID・会社ID・重複判定キー・画像ハッシュ・
OCR信頼度）は、保存時に `save:derived` としてログにだけ出る。
